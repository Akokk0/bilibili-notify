# 界面验证

目标：改动在真实内置浏览器里看得见、点得通，本轮操作没有新增 console error。验证失败就修复并从头重跑本轮验证，验完再报完成。

## 合格线

- 打开每个受影响页面，执行改动对应的操作：点击、填写、切换 tab 或打开弹窗，覆盖本次要修的状态。
- 每处改动保留前后截图，使用相同视口。能在改代码前截图就先截；改完才验时，前图取操作或注入之前的状态，并说明两图含义。
- 页面加载后记录 console 基线或起始时刻，检查本轮新增记录：error 为零；新增 warning 要解释或修复。日志跨整页刷新累积时，区分旧记录与本轮记录。
- 自己启动的后端日志没有因本轮操作新增 `level >= 50` 的记录。已有告警与持久问题按改动前的基线判断。
- devtools 注入全部收摊，`GET /api/dev/active` 返回 `{"active":[]}`；自己的服务和页面已收尾，工作区没有遗留验收改动。

## 起服务

共享辅助脚本是仓库根下的 `.claude/skills/verify-ui/scripts/dev.sh`。它提供 `status`、`wait [web|desktop]` 和 `stop`；先用 `status` 核对占用端口的进程及探针。

1. 本仓已有服务可复用时，记录其归属并直接复用，收尾保留它。端口由其他程序占用时先说明冲突。
2. 服务命令见 `.claude/launch.json`：`dev-apps` 启动后端和面板；拓展由BN挂载源码并监听；`web` 仅启动面板；`desktop-launcher` 启动桌面前端。命令中的包管理操作均经 `vp`。
3. Claude Code 提供 `preview_start` 等工具时，按当前工具说明使用已有配置。Codex 等没有这些工具的宿主，用终端执行工具后台运行对应命令，保留 session/PID 和日志，再运行 `dev.sh wait`。
4. 读取等待结果中的 session 状态。需要鉴权且没有可复用会话时告知主人；凭据不从 `apps/server/bn.config.yaml` 或环境变量中提取。
5. `dev:apps` 服务端通过开发 tsconfig 读取工作区源码，面板直接读取 internal、contract 和 UI 源码；开发拓展由BN直接加载src/index.ts，无需打包监听。需要运行依赖 `lib/` 的测试或生产入口时，先构建相关包。

后端探针使用 `http://127.0.0.1:8787/api/health`；面板与桌面前端使用 `localhost:5173`、`localhost:1421`，兼容 Vite 只监听 IPv6 本机地址的情况。

## 内置浏览器

先阅读当前会话浏览器工具的说明，再按其支持的入口初始化和操作。Codex 使用内置浏览器；Claude Code 使用其实际提供的预览工具。视口、导航、控制台和截图均使用当前工具声明的能力。

打开改动对应页面，完成合格线中的交互。按任务要求设定桌面或窄屏视口，前后截图保持同尺寸；确认目标内容和动画稳定后截图。工具无法提供某项观察时，回报实际证据与未验部分。

## 造状态

等不到的状态用开发者工具注入，说明见 `docs/agents/devtools.md` 的注入高度和已验范围。

- devtools 默认可能真实发送消息。造开播、作品或私聊指令事件前，先启用截流；测试推送、下载及其他外部副作用按本次任务已授权范围操作。
- 验完执行“全部收摊”，核对 `/api/dev/active`。前端已生成的更新通知可能仍留在页面上，需要关闭或刷新后再取收尾截图。

## 桌面端

- 浏览器中的 `desktop-launcher` 没有 Tauri，只能验证布局与降级态；依赖 `invoke` 的 starting/ready/failed 由既有桌面测试覆盖，回报中注明是否验证了真实桌面壳。
- 真壳 `vp run dev:desktop` 需要先构建更新载荷和 Rust。桌面壳内的面板仍按 Web 页面验证。

## 收尾与回报

撤销本轮注入和临时视口，关闭自己开的页面。自己启动的服务优先按保存的 session/PID 优雅停止；`dev.sh stop` 会停止本仓范围内的开发进程，仅在确认这些进程均可由本轮收尾时使用。复用主人的服务时保留进程。

`dev:apps` runner 收到 SIGINT 会关停子进程组；直接硬杀 runner 可能留下占端口的子进程。停止后用 `dev.sh status` 复核自己的端口已释放。

回报每个页面的操作、前后图含义、console 基线与新增记录、注入和服务清理结果。未验到的项目写清范围和原因。
