# 机器人框架桥接

把 **koishi / AstrBot 里已经配好的 bot 借给 bilibili-notify 用**。

BN 自己只认识 QQ 官方机器人、OneBot 和几种群机器人 webhook。Telegram、Discord、KOOK 这些平台，koishi 和 AstrBot 早就有人写好适配器了 —— 这个拓展不再各写一份，而是**把那些 bot 借过来当推送目标**。

借来的 bot 走的是和直连完全同一条路：推送照发，私聊指令、群里贴链接自动出卡也都照常。

## 怎么用

1. **在这一页把开关拨开**（拓展装完默认是关着的）。
2. **建一条「接入」** —— 填个名字、挑 koishi 还是 AstrBot，拿到一段 **BN 地址**和一条 **token**。
3. **去那台 koishi / AstrBot 装插件**，把地址和 token 填进去。koishi 那侧的插件已发 npm：

   ```
   koishi-plugin-bilibili-notify-bridge
   ```

   装好之后桥会**自己连过来**，这张卡就亮了。
4. **回「推送目标」页建连接** —— 平台挑「机器人框架桥接」，再从连着的 bot 里挑一个。**挑中的那个 bot 就是这条连接**，要用几个 bot 就建几条。

## 两个最容易踩的坑

**BN 地址是按你浏览器地址栏算的。** 在 BN 那台机器上用 `localhost` 打开面板，复制出来就是 `ws://localhost:8787/ext/bridge` —— 填进另一台机器、另一个容器里的 koishi，必然连不上。要填**那台 koishi 访问得到**的地址。

**接入不等于推送目标。** 卡片亮了只说明桥连上了，消息还发不出去 —— 还要回推送目标页，为每个要用的 bot 建一条连接。这一步最常被漏掉。

## 关于方向

**桥主动连 BN，BN 从不反过来连它。** 所以 BN 跑在 NAS、软路由、家宽后面都不用开端口、不用打洞 —— 要出得去的是那台 koishi。

token 只在新建那一刻给全文，之后只显示头尾；忘了就重新生成，旧的立刻作废。

## 能力

每个 bot 能干什么，是**桥握手时自己报的**，因为同一个平台经不同的框架连进来，拿得到的能力可能不一样。面板上用三种形状画：支持 / 不支持 / **它没报**。「没报」不是「不支持」—— 那是「值得一试」。

对面读不了 markdown 时，版式会自动剥成干净纯文本，而不是甩一屏字面星号过去。

## 写自己的桥

线上协议写在 [`PROTOCOL.md`](./PROTOCOL.md)：帧、握手、close code、能力表，以及一份最小实现清单。BN 只认识「桥」这一档，桥后面挂着什么，是握手时你告诉它的。
