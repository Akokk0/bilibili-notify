## [0.0.1] — 2026-09-11

第一版。协议 1.4;接入与 token 住拓展自己的设置里,能力按 bot 逐个报,对面读不了 markdown 就自动剥成纯文本。

### Added

- 形态:**桥主动连 BN,BN 从不反过来连它** —— koishi / AstrBot 跑在内网、NAS、家宽后面都不用开端口。一条接入(一个框架实例 + 一条 token)驮着 N 个 bot,**挑中的每个 bot 就是 BN 那边的一条推送连接**,所以 Telegram、Discord、KOOK 这些 BN 自己没有的平台也能推 —— 那些平台的适配是框架早就写好的
- 桥协议 1.4:握手、bot 名单、发消息与回执、入站消息、心跳;`ping` 带 `id` 时 `pong` 原样回,面板「测试」量得出真实往返;群入站消息里分享卡的链接单独两格(`cardLinks` / `miniAppCardLinks`),B 站小程序卡进来不会被回一张重复的卡
- 面板:接入(token)住拓展自己的设置里,每条接入可改名、可停用、可重新生成 token(重新生成与删除都先问一次,并说清会断掉什么);token 只在新建那一刻给全文、和 BN 地址成对摆着各带一颗复制钮,之后只显示头尾。每条接入一张卡 —— 真 logo、亮着还是掉线、**连上多久了、来自哪台机器**(两条都叫「家里那台」时靠这行分),底下是它借出来的 bot 表。**token 填进了另一种框架的插件**时卡上直接点出来,并给一颗只改种类、token 原样带过去的一键修复 —— 这种情况其实收发一切正常,不点破就会有人去拆一套本来没毛病的配置。一条接入都没建时空页把三步写出来;拓展被关掉时卡片压成一行标「已随拓展断开」,不和「启动失败」共用同一句话。连接编辑器从连着的桥上挑 bot
- 能力按 bot 报:小程序卡三态、markdown 支持;每项画成三种形状(支持 / 不支持 / 它没报)并配图例 ——「没报」是「值得一试」,和「不支持」不是一回事。**对面读不了 markdown 时自动把版式剥成干净纯文本**,而不是甩一屏字面星号过去
- 入站:借来的 bot 走的是和直连完全同一条链路 —— 私聊指令、群里贴链接自动出卡都照常,链接解析的按群例外里也列得出桥后面的群
- 一次性取图口:图片走 blob URL,桥自己来拿,用过即失效,不塞进 socket
- 插件那一侧:koishi 的已发 npm(`koishi-plugin-bilibili-notify-bridge`);**AstrBot 这一档面板上选得到,但插件还没写**
