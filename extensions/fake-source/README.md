# 假源(开发用)

一个**开发用**的订阅源拓展,背后不连任何平台。真平台(抖音)接进来之前,拿它在真机上把「订阅源」那条路走一遍:平台选择里多出一档「假源」、输入框的提示、解析门交回的候选、各种失败怎么显示,以及拓展页上的视图(ADR-0019 决策 34)。

它走的是正式的注册口(`ctx.registerSource`:`start` / `stop` / `searchCreators` / `fetchProfile` / `fetchLiveStatus` / `health`),并通过 `ctx.registerPlatformAdapter` 登记假平台,与以后真的订阅源拓展是同一条路:解析门,加上拓展页上十二颗造上报 / 入站的按钮(见下面「上报按钮」和「假平台（推送口）」)。

## 在开发版里试用

1. 在已完成[开发准备](../../README.md#开发)的主仓根目录运行 `vp run dev:apps`，启动 BN 服务端和面板。
2. 在拓展页点「挂载开发拓展」→「浏览目录」，选择 BN 所在机器上的 `extensions/fake-source` 源码目录。保留「源码变化时自动重载」的勾选，点「挂载」。
3. 在「假源(开发用)」卡片上拨开启用开关。BN 直接运行 `src/index.ts`，保存源码后会自动重载这个拓展。
4. 打开订阅页，点「添加订阅」，平台选「假源」，输入任意名字即可看到候选。

联调结束后在假源卡片上点「解除挂载」。BN 会停止运行和监听，保留源码目录。

## 输入什么会怎样

| 输入 | 解析门做什么 | 面板上看到的 |
| --- | --- | --- |
| 随便什么字 | 按这句字现编三个候选:有头像有粉丝、有头像不报粉丝、没头像只报粉丝(头像先存进图库、交引用)。同一句字永远是同一组 | 三个候选,选一个进配置弹层 |
| `空` | 回空表 | 没找到 |
| `慢` | 一直不回,直到宿主不等了(15 秒) | 504:解析门超时 |
| `坏` | 回失败的结果形状:「cookie 已过期,平台要求重新登录」 | 502:拓展查询出错,带着这句原话 |
| `乱` | 交回宿主必须拒的候选(一个头像不是图库引用的形状、一个负的粉丝数) | 502:候选不合规矩,点名哪两处 |

## 资料与状态

宿主拉资料时调 `fetchProfile`:本次运行里用「报资料」报过的人交最后报的那一版,连头像引用也一样;没报过的人交名字带「拉取版」的一份(粉丝数 0,头像取报资料那组的第一张)。外部 id 恰好是 `fake-0000000000000000-z` 时回「假平台上没有这个人」(`not_found`),宿主把这条订阅的问题记成 `creator_not_found`。这个 id 合清单的 `externalIdRegex`,可以经新建订阅直接填;解析门不会自己现编出它。

`health()` 给 `status` 指令一行「在跑 · 管着 N 个人」,N 是开着订阅里去重后的外部 id 数;来源停下后是 0。

清单订阅段还声明了这些现状:`postNoun` 是「假帖」,宿主拿它称呼作品;`creatorNoun` 是「假主播」,宿主拿它称呼创作者;`externalIdNoun` 是「假号」,身份标签拿它称呼外部 id;`externalIdRegex` 是 `fake-[0-9a-f]{16}-[a-z]`,新建订阅与特别关注名单的 id 按整串格式核;`icon` 是平台选项要用的内联 SVG 图片 data URL,不是可翻译文字。

## 上报按钮

拓展页 →「假源(开发用)」的头卡上有十二颗按钮:六颗造上报(报一条作品、报一条五种片段的作品、开播、下播、报资料、报直播状态)、两颗问题按钮(报问题、清问题)、两颗报坏的(报一条带坏图的作品、报一条多一格的作品)、两颗入站(发一条入站私聊 /status、发一条冒名连接的入站私聊)。视图里的按钮带不了「点的是哪一行」(ADR-0019 决策 42),所以每一颗按人上报的按钮都**一次作用于名下所有开着的订阅**:按外部 id 报,同一个人建了两条订阅也只报一次(BN 自己扇出),停用的不报。按完头卡底下多一行结果;一条开着的都没有时按人上报的按钮什么都不报,那一行说「还没有开着的订阅」,两颗问题按钮仍会报 / 清拓展与来源。

造出来的数据是**确定的**:序号一下一个(只在真报出去时才往前走),不掷骰子;链接都落在 `*.fake-source.invalid` 上,点了也不会跑到别人家。图是 64×64 的纯色 png,先 `ctx.storeImage` 存进图库、上报里只交引用;上报在 `start` 拿到的来源上下文上交(`reportPost` / `reportLive` / `reportProfile`),没有返回值,被拒了假源不知道,只能去「上报出入」看。来源停了(`stop` 之后),按人的按钮与两颗问题按钮回「来源没在跑」;两颗入站按钮只看假平台适配器,规则见下一节。

| 按钮 | 报什么 | 去哪儿看 |
| --- | --- | --- |
| 报一条作品 | 第 N 条作品:单数是图文(三段正文轮着用,都带序号、第二行与 `#假话题`,三张图,报话题「假话题」;话题上色靠上报的 `richText` 片段),双数是视频(封面、标题「城市散步 vlog · 第 N 期」、时长、简介、播放数,正文末尾 `#城市散步`,报话题「城市散步」;契约里一条作品只有一个话题,原来的第二话题 `vlog` 没有位置了);都带赞 / 评论 / 转发。正文写成像真作品的话 —— 开着 AI 点评时,女仆点评的就是这段字 | 动态路由到的目标收到卡 + 文案 + 链接(照版式);推送历史多一行拓展行 |
| 报一条五种片段的作品 | 第 N 条作品:文字、@人、话题、带图库图标的链接、带图库图的表情各有一段,片段内的字拼起来正好等于作品正文;@人 id、链接和两张图都是确定的,图先存进图库 | 目标收到五种片段都在的卡;`richText` 拼不回正文时宿主会丢掉富文本 |
| 开播 | 第 N 场:链接、开播时刻、标题、封面(存进图库)、分区(聊天 / 游戏 / 唱见轮着)、此刻在线 100、本场累计观看 1000、点赞、简介 | 开播路由到的目标收到开播卡;首页「正在直播」多出这几条订阅,人数那一列是累计观看(1,000) |
| 下播 | 同一场的链接,补上开播时刻 | 下播路由到的目标收到下播卡(点赞 + 累计观看;断流接续开着时等满那个窗口才来);首页那几条没了 |
| 报资料 | 名字「假名字 · 第 N 版」、粉丝数、头像(报资料专用的四张轮着换,与建订阅时的候选头像不重样) | 订阅页那几条的名字 / 粉丝 / 头像当场换 |
| 报直播状态 | 「在播」,每按一次此刻在线涨 100、累计观看涨 1000;没开播就按,从这一刻算一场新的(演 BN 重启过、开播没见着) | 首页「正在直播」有它、累计观看跟着涨(此刻在线首页不画);周期「正在直播」卡问假源的 `fetchLiveStatus`,它按记着的「谁在播、几时开播、标题封面」回在播 / 没播(开播与报直播状态记上、下播清掉);BN 重启后第一次报在播会补推一张(重启补推开着时) |
| 报问题 | 同一按下报四层:拓展自己私聊提醒并带恢复句、来源级、每条归假平台的连接、每个开着的人;四个 code 依次是 `fake_extension_problem`、`fake_source_problem`、`fake_connection_problem`、`fake_creator_problem`;没有开着的订阅时,拓展、来源与连接三层照报 | 拓展、连接与订阅各自的问题状态;拓展级的通知带恢复句 |
| 清问题 | 同一按下用四个 code 清掉上面那四层;拓展级仍通知恢复,来源、连接与每个人不私聊;没有问题或没有开着的人时,照清当前能清的层 | 那几层问题状态消失,拓展级收到恢复通知 |
| 报一条带坏图的作品 | 一条三张图的作品,第 2 张交一个不合形状的引用(`not-a-ref`) | 拓展详情页的「上报出入」:一条「丢了」,点名 `images[1]`;作品照样收下、照样推出去,卡上少那一张 |
| 报一条多一格的作品 | 一条作品的 `post` 里多带一格 BN 不认识的 `danmaku`(弹幕数,契约明说不收) | 「上报出入」:一条「拒了」,点名 `danmaku`。上报没有返回值,按钮不报错;BN 要是收下了,「上报出入」里就没有这一条 |

## 假平台（推送口）

清单的 `contributes.push` 给宿主多一档「假平台」(短名「假」、紫色、图标与图片 data URL),并把连接设置 `atAll` 与 `inboundFrom` 各声明成一格;代码经 `ctx.registerPlatformAdapter` 把适配器登记进推送系统。`start` 只读一次归自己的连接名单、订一次 `onConnectionsChanged`,用来更新页上的连接数;它不建连接、不出网、不起定时器。

新建连接时能挑两个确定的候选:

- 「假聊天」`fake-chat` 是会话型,目标范围有 `group` / `private` / `channel`;会话去向的地址为空时,适配器答不可用。
- 「假钩子」`fake-hook` 是端点型,只声明 `channel` 范围;端点去向恒可用。

两格连接设置都由适配器自己的 schema 解好再交给它。`atAll` 打开后,这条连接对外说支持单发 @全体,关着就说支持不了;`inboundFrom` 填了地址后,这条连接对外说收得到入站,并让入站按钮从这个地址发私聊,留空就说收不到。能力接口按这两格答 `atAll` / `inbound`;原生分享先答「还不知道」,宿主在手动测试时调 `probeCapabilities`,才答「不支持」并给出「假平台发不了原生分享」。

`send` 只用宿主递进来的连接与去向,不查自己的连接表;每次发送只写内存,账本留最近 50 条(文字截到 80 字),不落盘也不出网。拓展页上能看到「假平台管着 N 条连接」、「假平台收到的发送」(最新的在上,表格只列最近 10 条)与「最近一条文字」。

两颗入站按钮各有用途:一颗对每条开着且填了 `inboundFrom` 的连接,以那个地址发一条私聊 `/status`;另一颗拿不存在的连接 id 与发送者 `forged-sender` 发同一条私聊,宿主应丢掉并记一行,不会有任何回复。

适配器里故意塞了 `adapterKey`、`listAddressCandidates`、`connectionAuth`,订阅侧故意塞了 `auth`、`liveInteractions`,它们是给契约守卫证明宿主会覆盖或摘掉的:宿主把 `adapterKey` 改成拓展 id,并摘掉适配器的两个与订阅侧的两个不开成员。开发者别把这些故意塞进去的格子当成假源已经开放的能力。

## 真机怎么看

1. 照上面装好、拨开开关;订阅页 →「添加 UP 主」→ 平台选「假源」→ 输入「阿梓」→ 三个候选各建一条(想看「停用的不报」,就把其中一条停用)。
2. 首页开着一个标签页,拓展页 → 假源开着另一个。
3. 推送目标页新建连接时选「假平台」→「假聊天」或「假钩子」,再填 `atAll` 与 `inboundFrom` 两格;给一条订阅配好这个目标后,发过来的内容会出现在拓展页的「假平台收到的发送」表里。
4. 按「开播」→ 首页「正在直播」出现开着的那几条(标题「假直播 · 第 1 场」、分区、累计观看 1,000);连按两下「报直播状态」→ 2,000、3,000;按「下播」→ 没了。首页那一列只画累计观看(与 B 站那几行同一个口径);两个数差一个数量级,看见的要是 100 / 200 就是把在线当成累计画了。
5. 按「报资料」→ 订阅页那几条的名字变成「假名字 · 第 1 版(…)」、头像换色、粉丝数变;再按一下又换一版。
6. 先给这几条订阅配好动态的推送目标,按「报一条作品」→ 目标收到图文卡:三张纯色小图的九宫格、正文上方一行带图标的话题标签「假话题」、正文第二行换了行、正文里的 `#假话题` 与 B 站动态正文里的话题同一个颜色;再按一下是视频卡(封面、时长、标题「城市散步 vlog · 第 2 期」、播放数,没有弹幕图标;话题标签是「城市散步」,正文末尾的 `#城市散步` 上色)。开着 AI 点评时,文案换成女仆对这段正文的点评。
7. 按「报一条带坏图的作品」「报一条多一格的作品」→ 拓展详情页出现「上报出入」框:每个开着的人各一条「丢了」(点名 `images[1]`)、各一条「拒了」(点名 `danmaku`)。
8. 把订阅全停用再按任一颗按人上报的按钮 → 头卡底下那行说「还没有开着的订阅」,首页 / 订阅页 / 上报出入都不动。

十二颗按钮的接线、问题分层与入站由 `extensions/fake-source/src/__tests__/buttons.test.ts` 和 `adapter.test.ts` 钉着;作品、开播 / 下播 / 资料与两颗报坏按钮在真 BN 上的路径由 `apps/server/src/__tests__/fake-source-buttons-e2e.test.ts` 装真的假源核过,作品与开播 / 下播推到目标、落历史的那一段另有 `extension-post-e2e.test.ts` 与 `extension-live-push-e2e.test.ts`。

契约守卫 `apps/server/src/__tests__/extension-contract-parity-e2e.test.ts` 也装这个包逐成员走契约。`src/adapter.ts` 里 `adapter-reconcile`、`adapter-send`、`adapter-start` 三段用 `#region sample:` 包着,会被 `docs/1.0/extension-contract.md` 原样引用,`scripts/__tests__/contract-samples.test.mjs` 钉着;改了这几段就要同步文档。
