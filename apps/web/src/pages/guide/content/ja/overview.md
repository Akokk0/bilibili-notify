bilibili-notify（BN）へようこそ。このガイドでは、初期設定から最初の通知を受け取るまでを説明します。配信元へのログイン、接続、送信先、テスト送信、購読の順に設定します。ログインできる配信元がなければ、接続から始めてください。左端の「ガイド」は完了状況を確認して自動で進み、すべて緑になれば完了です。

1. **配信元のアカウントにログイン** — 「システム → アカウント」で、ログインに対応する配信元ごとにログインします。購読するコンテンツの取得に使います。
2. **通知用の接続を設定** — QQボット、Feishu、DingTalk、WeComなどにBNを接続し、「テスト」で接続を確認します。
3. **送信先を追加** — 通知を届けるグループや相手を指定します。
4. **テスト通知を送信** — 送信先の「テスト」を押し、メッセージが届くことを確認します。
5. **最初の購読を追加** — 「購読」で配信元を選び、クリエイターを検索して購読します。

購読を最後にするのは、購読フォームで送信先を選ぶためです。先に通知経路を用意すると、一度で設定できます。

## QQ接続方式の選び方

BNには、機能と準備の異なる2つのQQ接続方式があります。

| 判断基準 | qq-official（公式ボット） | onebot（NapCatなどのプロトコルクライアント） |
| --- | --- | --- |
| **グループへの通知** | ボットの区分によります。QRコードで作る軽量ボットは、作成者との個人チャットと作成者が所有するグループに対応します。審査済みボットや企業アカウントの利用範囲は公式ポリシーに従います。 | グループ・個人チャットに対応し、グループへの参加も柔軟です。 |
| **追加のデプロイ** | 不要。BNがTencentの公式APIに直接接続します。 | NapCatやLagrangeなど、別のクライアントコンテナーが必要です。 |
| **アカウント制限・停止** | 公式APIを使い、個人のQQアカウントにはログインしません。 | QQアカウントでログインするため、利用制限や停止の可能性があります。サブアカウントを推奨します。 |
| **メッセージ形式** | テキスト・画像・カード画像に対応します。Markdown形式はこの方式のみですが、ボットの区分で制限されます。軽量・パブリックドメインのボットにプライベートドメイン向けの権限はありません。転送メッセージのまとめ表示と全員メンションは非対応です。 | テキストと画像に対応し、複数画像はまとめて転送します。全員メンションに対応しますが、Markdown形式は使えません。 |

個人で手軽に使う場合は、qq-officialのQR接続・作成を試してください。グループ通知が多い場合や、まとめ転送・全員メンションが必要な場合は、onebotとNapCatを使います。両方の手順は[通知経路](/about/guide/push)にあります。

QQ以外では、Feishu・DingTalk・WeComのグループボットを接続できます。独自サービスには、BN標準のエンベロープを受け取る**種類未指定のHTTPエンドポイント**を使えます。通知経路の章を参照してください。

Telegram・Discord・KOOKには、「拡張機能」から**ボットフレームワークブリッジ**を導入し、KoishiやAstrBotで設定済みのボットを利用します。
