歡迎使用 bilibili-notify（BN）。這份指引會帶你從初次設定走到收到第一則推送。先登入各來源帳號，再設定推送連線、目標、測試與訂閱；沒有提供登入的來源時，直接從連線開始。左側「指引」會檢查完成狀態並自動前進，全部變綠即完成。

1. **登入來源帳號** —— 在「系統 → 帳號」逐一登入支援登入的來源，供 BN 讀取訂閱內容。
2. **設定推送連線** —— 將 BN 接上 QQ 機器人、飛書、釘釘、企業微信等服務，按「測試」確認連線。
3. **新增推送目標** —— 指定訊息要送往哪個群組或哪位使用者。
4. **傳送測試推送** —— 在目標上按「測試」，收到訊息即表示通道已接通。
5. **新增第一個訂閱** —— 在「訂閱」選擇來源，搜尋並訂閱想追蹤的創作者。

為什麼最後才新增訂閱？訂閱表單需要選擇推送目標，先接通通道就能一次完成設定。

## QQ 連線方式：如何選擇

BN 提供兩種 QQ 連線方式，功能與部署需求各不相同：

| 判斷條件 | qq-official（官方機器人） | onebot（NapCat 等協定端） |
| --- | --- | --- |
| **群組推送** | 依機器人等級區分。掃碼建立的輕量機器人可傳給建立者私聊與建立者擔任群主的群組；通過審核的機器人與企業帳號會依官方政策開放更多範圍。 | 支援群組與私聊，加入群組較自由。 |
| **額外部署** | 不需要，BN 直接連線至騰訊官方 API。 | 需要額外執行 NapCat、Lagrange 等協定端容器。 |
| **帳號限制或停權風險** | 使用官方 API，不登入個人的 QQ 帳號。 | 協定端需要登入 QQ 帳號，可能遇到限制或停權，建議使用分身帳號。 |
| **訊息格式** | 支援文字、圖片與卡片圖片；只有這條路線支援 Markdown 排版，但受機器人類型限制。輕量與公域機器人沒有私域權限；不支援合併轉傳與 @全體。 | 支援圖文，多張圖片以合併轉傳呈現，也支援 @全體成員；不支援 Markdown 排版。 |

個人輕量使用可先試 qq-official 的掃碼連線／建立；大量群組推送，或需要合併轉傳、@全體時，使用 onebot 搭配 NapCat。兩條路線的完整步驟都在[推送通道](/about/guide/push)。

不使用 QQ？飛書、釘釘與企業微信各有群組機器人的連線類型；自己的服務可使用接收 BN 原生封裝的**未指定的 HTTP 端點**，詳見推送通道章節。

若要推送至 Telegram、Discord 或 KOOK，可到「擴充功能」安裝**機器人框架橋接**，使用 Koishi 或 AstrBot 已設定好的機器人。
