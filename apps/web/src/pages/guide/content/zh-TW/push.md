本章涵蓋連線、目標與測試三個步驟。還沒選好路線時，請先看[總覽的比較表](/about/guide)。

## 路線 A：QQ 官方機器人（qq-official）

BN 直接使用騰訊官方 Bot API，不登入個人的 QQ 帳號，也不需要額外部署協定端。功能依機器人等級區分：掃碼建立的輕量機器人目前可推播給建立者私聊與建立者擔任群主的群組；通過審核的機器人與企業帳號會逐步開放更多範圍，以官方最新政策為準。

### A1 · 快速設定：掃碼連線／建立

1. 開啟[推播目標](/targets)，新增連線並選擇「QQ 官方機器人」。
2. 按表單中的**掃碼連線／建立**（實驗性功能），用手機 QQ 掃碼，在騰訊頁面建立機器人。以前用此通道建立過的機器人，也可重新選擇、連線並帶入憑證。頁面出現 OpenClaw／小龍蝦字樣屬正常，這是騰訊提供給輕量機器人的通道。
3. `appId` 與 `appSecret` 會自動填入，**仍需按「儲存」才會生效**。
4. 在儲存後的連線按「測試」，成功即完成連線步驟。

> 輕量機器人目前不需審核，可推播給建立者私聊與建立者擔任群主的群組，範圍以官方政策為準。每個 QQ 帳號最多建立 5 個。遺失憑證時可重新掃碼，選擇已建立的機器人並重新取得密鑰。需要更廣的功能時，請用 A2 或路線 B。

使用 A1 時可跳過 A2，直接進入 A3。

### A2 · 正式設定：開放平台註冊

1. 在 `q.qq.com` 註冊開放平台帳號並建立機器人，名稱、簡介與頭像需要審核。
2. 在「開發 → 開發設定」取得 `AppID` 與 `AppSecret`，填入 BN 的連線表單。
3. 在同頁設定 **IP 允許清單**，填入伺服器對外連線使用的公開 IP；可在伺服器執行 `curl ifconfig.me` 查詢。
4. 測試時先在平台設定**沙盒**，指定 20 人以下的群組或私聊作為測試環境，BN 表單的 sandbox 也需對應開啟；正式使用後記得關閉。

> 公開 IP 變動可能造成權限錯誤。建議使用固定公開 IP 的伺服器，或每次 IP 變更後更新平台允許清單。

### A3 · 加入群組與設定權限

不論 A1 或 A2，要推播到群組都需要先加入並開啟權限：

1. 在手機 QQ 的「聯絡人 → 機器人」開啟機器人資料頁，選擇加入群組。輕量機器人只能加入建立者擔任群主的群組，其他等級依官方政策；私聊可直接從資料頁開啟對話。
2. 在群組的機器人管理中，允許機器人**取得群內所有訊息**，並開啟**主動在群內發言**。

> BN 的推播屬於主動訊息，未開啟主動發言時，群組可能收不到推播；訊息接收範圍若不完整，也可能收不到用於探索對話的 @提及。

### A4 · 新增目標與官方路線注意事項

1. 連線測試成功後，新增推播目標：群組使用 `groupOpenid`，私聊使用 `userOpenid`。
2. 這些值**不是群組號碼或 QQ 號碼**。請先在群組 @機器人，或私聊傳送訊息；BN 收到事件後，目標表單才會列出可選的對話。
3. 在目標上按「測試」，確認 QQ 收到訊息。

閘道約每 30 分鐘會主動要求重新連線，日誌中的 RECONNECT 是正常協定行為。圖片訊息需要可從網際網路存取的圖片 URL，BN 會處理渲染圖片的中繼；Markdown 排版仍受公域／私域權限限制，輕量機器人沒有私域特權。

## 路線 B：OneBot 協定端（NapCat）

協定端使用實際的 QQ 帳號收發訊息，支援群組、私聊與圖片。代價是需要額外執行容器，而且帳號可能受到限制或停權。

> 建議使用分身帳號。協定端會模擬用戶端登入，存在停權風險，請勿使用主要帳號冒險。

### B1 · 使用 Docker 部署 NapCat

在 BN 所在的伺服器，以 Docker Compose 啟動 NapCat：

```yaml
services:
  napcat:
    image: mlikiowa/napcat-docker:latest
    container_name: napcat
    restart: unless-stopped
    environment:
      - NAPCAT_UID=1000
      - NAPCAT_GID=1000
    ports:
      - "6099:6099"   # WebUI
    volumes:
      - ./napcat/config:/app/napcat/config
      - ./napcat/qq:/app/.config/QQ
```

1. 開啟 `http://SERVER_IP:6099/webui`，初次登入的 token 可用 `docker logs napcat` 查看容器日誌。
2. 在 WebUI 用分身帳號掃碼登入 QQ。
3. 映像檔與參數以 [NapCat 官方文件](https://github.com/NapNeko/NapCatQQ)為準。協定端更新較快，以上是撰寫時的設定範例。

> NapCat 持有 QQ 登入狀態，請勿將 WebUI 或 WebSocket 連接埠直接公開到網際網路。限內部或 Docker 網路互通，並視需要設定 `accessToken`。

### B2 · 連接 BN（建議反向 WebSocket）

OneBot 有三種連線方式，**建議使用反向 WebSocket**：由 BN 監聽、NapCat 主動連入，NapCat 重新啟動後會自動重連。

1. 在 BN 新增 OneBot 連線，選擇「反向 WS」，設定監聽連接埠（例如 `6199`）並儲存。
2. 在 NapCat WebUI 的網路設定新增 WebSocket 用戶端，URL 填 `ws://BN_HOST:6199/`，訊息格式選 **Array** 並啟用。
3. 若兩個容器在同一台主機，將它們接上同一個 Docker 網路，使用 `ws://CONTAINER_NAME:PORT/` 直接連線即可。
4. 回 BN 在連線上按「測試」確認。

正向 WS 由 BN 連到 NapCat 開啟的 WebSocket 服務，例如 `ws://napcat:3001`；HTTP 則由 BN 向 NapCat 的 HTTP 服務傳送 POST，NapCat 需同時開啟 HTTP 伺服器與事件回報。若有設定存取權杖，兩端必須一致。

### B3 · 新增目標與協定端注意事項

1. 新增推播目標，群組填群組號碼（`groupId`），私聊填 QQ 號碼（`userId`）；此路線可直接輸入號碼。
2. 在目標上按「測試」，確認 QQ 收到訊息。

圖片訊息需要先上傳到 QQ，常會超過 15 秒，BN 已針對圖片延長逾時時間，不需另外修改設定。若測試顯示 NapCat 可能未連線，請到 WebUI 檢查登入狀態與網路設定。

## 路線 C：群組機器人／HTTP 端點（不使用 QQ）

選擇**飛書機器人**、**釘釘機器人**或**企業微信機器人**連線，填入目標 URL。自己的服務使用接收 BN 原生封裝的**未指定的 HTTP 端點**。需要簽章的平台請填密鑰；端點位於反向代理或 Cloudflare Access 後方時，將憑證填入「自訂標頭」。同樣以「測試」確認連線。

## 通道驗收

回到[推播目標](/targets)，在目標上按「測試」。QQ 或其他目的端收到測試訊息即表示通道接通。最後[新增訂閱](/about/guide/subs)，選擇剛建立的推播目標，即完成初始設定。
