## [0.4.0] — 2026-07-22

新增「数据统计」Tab —— 记录并展示每位 UP 的涨粉、投稿、动态与直播活动,还能让智能女仆据此写一份周报或单人锐评、直接推成卡片图发到群里。另修复四个正确性问题,其中「配置里关掉的开关关不掉」与「直播间卡在正在直播」影响面较广。

### Added

- **「数据统计」Tab**:记录每位订阅 UP 的涨粉曲线、投稿 / 动态数与直播场次时长,提供对比表、KPI、活动热力图、雷达图与单 UP 钻取,时间窗可选 1–90 天。数据全部来自**已有的**事件流,不额外请求 B 站。

  两件事值得先知道:一是**统计从升级这一刻才开始记**,升级之前的活动没有留档,所以头几天的图表会比较空;二是**「没有记录」与「确实是 0」严格区分** —— 服务器当时没在跑、或功能还没上线的日子一律显示成空格而不是 0,曲线在缺数据处断开,不会画一条看着像「那天没动静」的实线 (7890649, 79beb6e, 6c356dd, 17d9e15, 0447fe7, 464ea77, 9bc2935, fef42aa)

- **AI 周报 / 单人锐评可直接推成卡片图**:统计页的「可推送周报」此前只能看不能推,只好手工复制;现在可以选一个推送目标直接发出去,榜单卡(鸽王 / 勤奋 UP / 逐位锐评 / 评分条)与单人锐评卡各一张。

  没装 Chromium 或关掉了图片渲染也发得出去 —— 会依次降级成纯文字,而不是整条失败。推送的是**你在页面上看过的那一份**,不会在服务端重新生成一份没人审过的文本 (ecadf03, 05a62a4, 0390fec, e127fa0, 8ff7ab0, d218329)

### Changed

- 界面与卡片里的 **emoji 全部换成 SVG 图标**。emoji 的长相由观看者的系统字体决定,同一个警告图标在 macOS 是黄色三角、在 Windows 是另一副样子、字体缺失时干脆是豆腐块;卡片图更明显,渲染机器的字体不同,推出去的图就不同 (673dc75, e962b49)
- 每位 UP 的**代表色从 8 种扩到 24 种**。原先 8 种里有两种肉眼几乎分不出,实际可用只有 7 种,订阅到第 4 位就有约六成概率撞色、10 位以上几乎必然撞 (88decb1, 0bfdca2)
- 顶栏那枚绿色徽章由「推送服务运行中」改名为「**服务器运行中**」。它只表示后端能不能连上,不少人把它当成推送的总开关去找 —— 推送开没开是每位 UP 各自的设置 (727ab9b)

### Fixed

- **配置里关掉的开关关不掉、清空的字段清不掉**:典型表现是「打开直播卡的单独样式、保存,再关掉就关不掉了」—— 请求成功、页面也没报错,刷新回来开关又是开着的。同类问题还有:清空 AI 的 API Key(换服务商时要做的第一件事)旧密钥仍留在服务器上;模块日志级别在有两个以上覆盖时改不回「跟随全局」;按 UP 的单项卡片样式在开了两种、只关一种时关不掉。所有保存路径已统一走同一套差异计算,不再各写各的 (e8b93ba, 4bd3776, 440f934)
- **账号登录失效后,动态检测会再报一遍错**:主人先收到「账号登录已失效,请到控制台重新扫码登录」,过一会儿又收到一条「[bilibili-notify-dynamic] 账号未登录」,读起来像是又坏了一处。现在动态检测跟直播监听一样在登录失效时立刻停下,不再多打一次注定失败的请求;日志措辞也说明了原因和恢复条件 (e991a0a, 834fd68)
- **直播间可能卡在「正在直播」下不来**:有四条路径会在等待网络期间翻转直播状态,其中两条没有防护 —— 下播事件恰好落在这个窗口里就会被丢弃,而 B 站不会再补发一次,该直播间从此永远显示直播中。附带的三个后果:重连放弃时会留下一个每小时私信一次、永不停止的提醒;开播中断时上一场的弹幕会漏进下一场的词云 (4859656)
- **冷启动时 cookie 已过期的话,重新扫码登录后不会自动恢复**:动态检测、直播监听重建、关注同步全都停在原地,必须重启服务才恢复。这个场景下的登录失效走的是另一条状态迁移,恢复事件被漏发了 (5efddc9)

## [0.3.0] — 2026-07-17

渲染浏览器支持远程连接与不重启热切换,配套推出免装 Chromium 的 slim 镜像并收紧容器常驻内存;直播开播卡片封面可换成自选图;修复图集合并转发重复推送与图廊悬空引用两个正确性问题。

### Added

- **渲染浏览器可远程连接、支持不重启热切换**:系统页新增面板,可把卡片渲染指向远程浏览器端点(不再要求本机装 Chromium),切换来源无需重启服务;配套推出免装 Chromium 的 **-slim** Docker 镜像(需搭配远程浏览器容器使用),本地 Chromium 空闲一段时间后自动关闭以降低容器常驻内存,两种镜像都收紧了 Node 堆上限 (96ca28a, 0ab2798, 66e10f4, 15f8978, ddaf57d, b1374f7)
- **直播开播卡片封面可换成自选图**:卡片编辑器新增「直播封面」区块,全局与按 UP 单独设置皆可,可选多张轮换;不选则保留 B 站原始封面 (0bbef92, 3996a1f, be74c8d, f64e5dc, 39a0580)

### Fixed

- 动态图集(合并转发,多图)推送**超时后被误判为失败并重试,导致同一条动态在群里重复出现多份** —— 超时不代表消息没发出去,现在只对确定没发出去的失败重试;合并转发的超时阈值也放宽到 60 秒以适配多图下载耗时 (32c2d0e)
- 卡片图廊里引用了一张已删除的图片时,该图会**悄悄占住轮换位却在界面上不可见、也无法取消选中**。现在失效引用会显示成可删除的「已失效」占位块,删除一张图片时会一并清理页面上所有未保存草稿里对它的引用,渲染与推送侧也会直接跳过失效图片 (3bfe551)

## [0.2.1] — 2026-07-15

AI 页新增「试一句」实时测试面板;订阅时自动关注 UP、并补关注历史上从未关注的订阅;外加一批推送正确性与界面修复。

### Added

- AI 页新增 **「试一句」面板**:用当前(哪怕还没保存的)人格草稿,当场发一句话给智能女仆,她的回复会同时显示在页面上、并真实推送到你指定的推送目标 —— 调人格时不必再跑去聊天软件里翻效果 (5841068, b9becc4, aa160b1)
- 订阅卡片上显示 **「未关注」标记**,一眼看出哪些订阅还没关注(未关注的 UP 拉不到动态) (618317e)

### Fixed

- **订阅一个 UP 时自动关注他**,并在启动时**补关注那些历史上从未关注的订阅** —— 动态是从关注流拉的,不关注就收不到该 UP 的动态。此前独立端从不自动关注,存量订阅可能一直静默收不到动态 (d1a00d0, 0191fbf, 9a7a50e)
- **「特别关注用户进房」提醒终于生效** —— 这个功能此前依赖一份不存在的解码表,每次都静默失败,从第一天起就没工作过。现在改用直播消息组件自带的进房事件 (ba9914b)
- 给某个 UP **单独改一项卡片样式**(例如只改渐变起始色),会把该 UP 的字体、背景图轮换、粉丝区显示等**其它全局设置一并冲回默认** —— 最严重的是全局关掉的图片渲染会被悄悄重新打开。现在单项覆盖只改那一项 (9c1c476)
- 图文动态(多图帖)的**附图发送失败时,主卡片连同 @全体会在之后每一轮检查里重复推送**,直到那条动态滚出列表。现在附图发不出就跳过,不连累主卡重发 (808b480)
- AI 页**只改了 apiKey 一栏、保存之后仍卡在「未保存」状态**,再也点不动保存 (1145c09)
- 配置热重载会**跨功能域误触发**:改个动态轮询设置会顺带重置 User-Agent、重排登录健康检查计时;更糟的是**图组转发开关改了之后不重启根本不生效**。现在按字段精确判定,各设置改动只唤醒真正相关的部分 (aeb64eb)
- 停止监听某个直播间时若撞上开播推送正在进行,会残留一个永不停止的「正在直播」复推定时器,对着已取消的订阅一直推。现在拆除时一并清掉 (aa387a0)
- 账号被风控、退避等待期间增删 / 开关订阅会提前重启动态检测、抢在退避结束前又去戳风控接口。现在退避期间不再被订阅变更打断 (55af1ec)
- 请求出错时错误日志会带上完整请求 URL,其中可能含账号 CSRF 令牌等凭据,报 bug 贴日志即泄漏。现在日志只保留路径 (742af30)
- 修复六个失效的界面颜色 token(部分控件颜色渲染不出来) (5f19ab3)

### Changed

- **默认**动态轮询时间从每 2 分钟的整分(:00)错开到第 30 秒(:30),避开整分请求高峰、降低风控概率。你若自己设过 cron 表达式则不受影响 (d2321ef)

## [0.2.0] — 2026-07-11

新增一键备份与恢复(完整备份 / 脱敏导出两档,恢复不需重启),订阅卡片支持右键 / 长按快捷菜单。修复一类「可选项改回默认值就存不下去」的保存故障,以及脱敏备份在配置有 QQ 官方机器人时**根本恢复不了**的问题。

### Added

- **备份与恢复**(系统页新增一节)。两档:**完整备份**把 B 站登录与 AI API Key 等机密用 6 位 PIN 加密后一并带走,换机 / 重装能原样恢复,连登录都不用重扫码;**脱敏导出**把所有机密位置留空,可以放心分享给别人。导出时按「全局设置 / 订阅 / 推送目标 / 适配器」分节勾选。导入分覆盖与合并两种模式,**覆盖前会先算出计划、把「将删除 N 项」摆到你面前确认**(删除不可撤销)。恢复后配置热重载,不需要重启 (72e1a9b, 0ae2ed8, b7c0fe6, 7653b12, c41d0be, 63313ca, c7dbaea)
- 订阅 UP 卡片支持右键(桌面)/ 长按(触屏)呼出快捷菜单:编辑详情、启用停用、复制 UID、加入分组、删除 (195d147)

### Fixed

- 「玻璃片透明度」这类可选项**改回默认值后存不下去** —— 改动会显示成「→ undefined」,保存点了没反应。现在清空一个可选字段会正确地作为「清除」提交。同类问题在卡片全局样式、per-UP 覆盖、日志级别覆盖上一并修掉 (974ed46)
- **脱敏备份恢复不回来**:配置里若有 QQ 官方机器人适配器,导入直接报 `config validation failed`。脱敏会把 appSecret 抹成空,而它此前不接受空值 —— 也就是说这个功能对用 QQ 官方机器人的人从第一天起就是坏的。现在空密钥表示「尚未填写」,可以正常存下;恢复后该适配器不会拿着空密钥去撞 QQ 网关,导入回执还会提醒你回去补填凭据 (7b6bd91)
- 批量启用 / 停用订阅之后,选中状态没有清空 (7acbdd1)
- 在卡片渲染页拖动透明度滑块时,日志会一条接一条刷出 INFO「配置已更新」,看着像是已经保存了 —— 那其实只是预览在重渲染,已降为 debug (89ca0ca)
- 日志把「清空的可选样式字段」打印成 `undefined`,现在显示为 `(默认)` (5c8714f)

## [0.1.0] — 2026-07-09

首个正式版,从 alpha 系列毕业。Docker 镜像大幅瘦身(自包含 bundle + chromium 基础层冻结,升级只需拉取几十 MB);修复 per-UP 高级规则「动态过滤」与「直播阈值」开关互相连带点亮的问题。

### Changed

- Docker 镜像瘦身:服务端改为自包含单文件 bundle,镜像不再携带完整 node_modules,应用层体积从数百 MB 降到约 15MB,升级时只需重新拉取这一小层 (c291631, 3359e7f, 0f766a7, d6e5aa3)
- Chromium 运行时层(约 300MB)冻结进独立基础镜像,不再随每次发版重建;今后升级只需拉取应用层,chromium 层只在显式重建基础镜像时才变化 (6d5c97d)

### Fixed

- per-UP 高级规则「动态过滤」与「直播阈值」两个开关此前共享同一份底层字段,只开其中一个另一个也会连带点亮(侧栏小点同样误标),关闭后保存草稿灵动岛还会残留;已按字段分域拆开判定,两个开关互不干扰 (e4d11ce, 8e62307)
- 服务端入口通过符号链接路径启动时(如全局链接的可执行文件、部分容器挂载路径)会静默不做任何事直接退出,不报错也不留日志;已在入口比对前对路径同样做 realpath 解析 (8e4dc6f)

## [0.1.0-alpha.17] — 2026-07-04

底层网络传输从 axios 全面切换到基于 fetch 的实现(自带轻量 cookie jar、每实例一致的浏览器指纹),并配套一批降低 B 站风控概率的优化(粉丝轮询解耦降频、风控熔断、请求去重复用);另修复概览页「本周推送趋势」柱状图左侧空柱与「今日推送」计数在高推送量下偏低的问题。

### Added

- 粉丝数轮询独立周期 `fansCron`(默认每 10 分钟):从动态轮询周期(`dynamicCron`)解耦、可单独调节。订阅数量多的用户不再每 2 分钟对每位 UP 各发一次请求,请求频率大幅下降,降低风控概率 (21b0280)

### Changed

- 网络传输层从 axios 切换到基于 fetch 的实现:自带一个轻量 cookie jar(持久化格式与旧版兼容,升级不掉登录),逐跳捕获 Set-Cookie;并为每个实例生成前后一致的浏览器指纹(User-Agent 与 sec-ch-ua 版本互相咬合),减少指纹错配招致的风控 (f6c3d2a, 0762c2f, ff12670, db1c068)
- 一批降低 B 站风控概率的优化:粉丝数改用更轻量的关系接口拉取、命中风控时自动暂停本轮轮询而非继续请求剩余 UP、直播间号解析结果与登录账号信息缓存复用不再重复请求、WBI 签名请求持续被风控时不再快速重试放大 (8917753, 21b0280, 92188da)

### Fixed

- 概览页「本周推送趋势」柱状图左侧总有空柱:数据源此前只取最近 100 条推送,推送量大时覆盖不满 7 天、越早的日子分到的记录越少直至为零;现改为服务端按日全量统计,并按本地时区(而非 UTC)划分日界。「今日推送 / 今日失败」计数同源修复(单日推送超 100 条时不再偏低)(4f7ebd6)

## [0.1.0-alpha.16] — 2026-07-03

消息版式自定义(一次推送可拆分 / 重排为多条消息)+ 充电专属动态占位渲染;修复全局默认背景图廊不轮换、镜像更新后面板仍是旧版的浏览器缓存问题。

### Added

- 消息版式自定义:动态与直播(开播 / 直播中 / 下播)推送的消息结构可视化编辑 —— 卡片图 / 文本 / 链接三个部件可排序、显隐,插入分条符把一次推送拆成多条消息,同条内相邻文本部件的连接符可自定义;全局与 per-UP 均可配置。编辑器带实时预览,并在卡片图不在消息首位时提示 QQ 会把图文拆成两条 (e669a9d)
- 充电专属动态:未充电时 B 站接口不返回动态内容,此前会渲染出正文空白的卡片;现渲染「充电专属」占位提示 (54fb032)

### Fixed

- 背景图轮换对全局默认图廊不生效:此前仅当订阅或卡片类型单独配置了多张背景时才轮换,只在全局默认样式配图廊的用户每次推送都是同一张;现全局默认图廊同样参与轮换 (ce97b1f)
- 镜像更新后面板仍是旧版:Dashboard 静态资源此前不带缓存头,浏览器会按启发式缓存旧页面,表现为「核心版本更新了但面板没更新」,需强刷或删镜像重拉才恢复;现带正确缓存策略(哈希资源永久缓存、入口文件每次回源确认)。升级到本版后首次访问仍需强刷一次,此后镜像更新面板自动跟随 (6ce4f99)

## [0.1.0-alpha.15] — 2026-07-02

一批稳定性与体验修复:卡片版式全局热更新补漏、独立端对畸形 cron 表达式的崩溃防护、推送路由在退避重试期间的陈旧目标复检、QQ 官方机器人连通性测试改为真实探测并新增重连日志开关。

### Added

- QQ 官方机器人适配器新增「记录重连日志」开关(默认关闭):网关 RECONNECT/RESUMED 事件约每 30 分钟一次、属正常协议行为,此前无差别刷屏,现默认静默,排障时可开启 (2141cf6)
