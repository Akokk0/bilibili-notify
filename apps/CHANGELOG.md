## [0.10.0] — 2026-09-05

推送历史改成「一次推送一行」:一次推送的多条消息收在同一行、可以展开逐条看,没有可用目标的推送也会留一张卡;链接解析新增 QQ 小程序卡。

⚠️ **弹幕词云与 AI 总结改成了「下播」的附加项,不再各自独立开关。** 升级时按老配置自动合并:三者任一开着,「下播」就是开的;下播的推送目标取三者并集;两个附加项保持原来的开关状态。**此前只开了词云 / 总结、没开下播的主人,升上来会开始收到下播卡片本身** —— 不想要就把「下播」整项关掉(附加项跟着停),详见 Changed。正式版,Docker 的 `:latest` 从 0.9.1 挪到这里。

### Added

- **没有推送目标的推送也会在面板上留一条**:此前订阅开着、但这类推送没配目标(或配的目标全停用)时,推送静悄悄地什么都不做,面板上一点痕迹都没有。现在照样在「推送历史」里记一行、右下角弹一张警示色小卡标「无目标」,卡上的「去配置」直接跳到那位 UP 的抽屉并停在推送目标那一节。这一行不进「今日推送」与「今日失败」——它确实没推到任何地方 (af6d032c, ca8ac15e, 0f5c7b35)
- **链接解析可以回 QQ 小程序卡**:「系统」页链接解析一节的每一行多了「形式」—— 图片卡(默认)或小程序卡。小程序卡就是 B 站 App「分享到 QQ」那种,点开直接进小程序播放。它要机器人所在的 OneBot 实现提供 `get_mini_app_ark` 接口(目前已知只有 NapCat 有),独立端自己探测:同一节里新增「适配器支持情况」面板,逐个 OneBot 适配器显示支持 / 不支持 / 未探测。签不出卡或发送失败时自动回落图片卡,群里不会空着;QQ 官方机器人做不到,一律图片卡 (6dcf4bd4, 5b6727fc, 53129268, 869a4964)
- **「有新版」的通知卡说清是哪一版、带来什么**:卡上写版本号、那一版 CHANGELOG 的概述,以及当前状态。下载改成后台跑 —— 点了之后卡片立刻变「下载中」,面板照常用,下载完同一张卡换成「已就绪,可以重启应用」或「下载失败」。GitHub Release 的正文也会带上该版本的 CHANGELOG 整段 (c62ff533, 27d9db85, da3b558e, 11cb2bbd, debe08ed, 959617a1, e588a066)

### Changed

- **⚠️ 弹幕词云与 AI 总结改成「下播」的附加项**:此前它们是两个独立特性,各有开关与推送目标;现在挂在「下播」下面当两个附加项,共用下播的开关与目标(升级迁移见上方 ⚠️ 段)。一次下播从此是**同一次推送**:下播卡先发,词云与 AI 总结算好之后追加到同一行 —— 右下角那张小卡会从「1 条」长到「3 条」,历史里也是一行 (999906c2, aa16cfc4)
- **推送历史一行 = 一次推送 × 一个目标**:一次推送里的多条消息(卡片本体、@全体、图集、词云、AI 总结)收在同一行,列表上显示首条文案加一颗「N 条」胶囊,点开逐条看文案、图和送达结果。状态从「成功 / 失败」两态改成四态:已送达、部分失败(本体到了、附加项没到)、失败(本体没到)、无目标。老的历史记录照常显示,不用迁移 (af6d032c, bb17ae09, ed7c5c34, 1a4ae98d, 1e9ad594)
- **链接解析的「生效范围」换成一张表**:0.9.1 的「所有群 / 仅以下群 + 勾选白名单」改成「默认行 + 按群例外」,两列分别是解析与形式,每格三态(跟默认 / 显式开 / 显式关),像每位 UP 的覆盖那样。「所有群」不再是一种模式,它就是默认行;想只在某几群解析 = 默认行关掉 + 那几群显式开。老配置读时自动迁移,不用动手;按群例外默认收起,群多时不会把卡撑爆。**有一处行为变化**:默认行开着时,停用的目标群也不解析了(0.9.1 的「所有群」不看停用) (ac708b74, 149e3f2a, 53668899)
- **停用的推送目标不再当推送候选**:此前推给一个停用的目标(目标本身停用,或它挂的适配器停用)会一路退避重试约三分钟才记成失败;现在直接不当候选,该类推送的目标全停用时视同「无目标」 (af6d032c)
- **「今日推送」数的是推到了多少个地方**:一次动态推给三个群算 3 次,而不是 1 次;「今日失败」数的是失败与部分失败的行数,趋势图同口径 (bb17ae09, 1e9ad594)
- **周期「正在直播」在历史里单列一类**:此前它和开播都记成「开播」,分不出哪条是复推;开关与推送目标仍与开播共用 (1a4ae98d)
- **图集发送失败不再静默**:一条图文动态的图集单独发失败时,那一行记「部分失败」、在历史里看得到;仍然不重发(重发会把主卡也带出来) (2423cd66)

### Fixed

- **QQ 官方机器人的推送目标会白发一条 @全体、并把整次推送标成失败**:官方机器人根本发不了 @全体,而只要订阅的 @全体 开关开着,推送时仍会先给它发一条独立的 @全体 消息 —— 那条必然失败。UP 抽屉里那个开关对官机目标本来就显示为关,发送时的行为却对不上。现在不支持 @全体 的平台一律跳过那条消息 (3ddf55bc)
- **周报「发送到」里,适配器被停用的目标显示为启用**:0.9.1 起选择器会给停用的目标标「已停用」,但它只看目标自己的开关 —— 目标开着、它挂的适配器被停用时不标,而发送时本来就会跳过它。现在面板上的判定与发送时的判定是同一条 (788cec1c)

## [0.9.1] — 2026-09-04

链接解析学会了认群:可以只在你点名的群里出卡,其余群贴链接不理;周报的推送目标与它用同一套「停用」规矩。**有一条要动手的**:自定义文案里还留着 `{url}` / `{link}` / `-link` 的,这一版起会原样打出来,请到「高级规则」页把它删掉(详见 Changed)。正式版,Docker 的 `:latest` 从 0.9.0 挪到这里;留在正式渠道的实例在「系统」页检查更新即可收到。

### Added

- **链接解析生效范围**:「系统」页「链接解析」一节新增「生效范围」—— 「所有群」照旧,「仅以下群」则从推送目标里勾选(只列群类目标,OneBot 与 QQ 官方机器人两种都行),没勾的群贴链接不理,勾选立刻生效、不用重启。被停用的目标(目标本身停用,或它挂的那个适配器停用 / 已删)即使勾着也不解析,芯片上标「已停用」提醒你;推送目标里一个群都没有时给出空态并指向推送目标页。升级上来的老配置按「所有群」走,行为不变 (4b1d36b1, 9b0eaa7c, 70141f77, 2344e8e8, 90346132)

### Changed

- **⚠️ 文案模板不再替你抹掉 `{url}` / `{link}` / `-link`**。自 0.5 起链接就是消息版式里独立的「链接」块,文案模板没有链接变量;此前为了兼容更早的自定义文案,渲染时会悄悄把这三个老占位符删掉,这一版起不删了 —— 模板里还留着它们的,推送出来会原样显示 `{url}`。请到「高级规则」页的「动态文案 / 视频文案 / 开播 / 直播中 / 下播」模板(以及每位 UP 的覆盖)里把它删掉;模板还是 0.5 之前那份默认文案的,点「默认文案有更新」一键换新即可。想显示链接,在版式编辑器里开「链接」块 (7a62f023, b6dfbb38)
- **周报「发送到」对停用目标的处理**:选择器改成与链接解析同款的芯片,停用的目标照列、标「已停用」、勾选状态保留;发送时跳过它们并在结果里写「跳过 N 个已停用」,不再算作发送失败;勾的目标全都停用时视同没配目标,不生成周报,通知主人「目标都已停用」 (1631811e, ee3251ee, 5ee85f3e, 49d1b9ea)
- **桌面安装包与 Docker 镜像、应用内更新装的是同一份东西**:安装包里不再带整棵 node_modules,只有打包好的服务端、界面和一个 Node,体积随之缩小;行为不变 (b16033ba)
- 配置文件里若残留 Koishi / AstrBot 端专属平台(`koishi-bot` / `astrbot`)的适配器或推送目标,启动时静默丢弃 —— 独立端从没提供过这两种,只有从那两端搬过数据来的人会遇到 (2261cd59, 7bd2305f)
- 从源码跑的开发版(版本号 `0.0.0-dev`)不再检查更新:此前它比任何发布过的版本都「旧」,每次开面板都提示有新版;现在「系统」页写「开发版,不检查更新」。Docker 与桌面版用户不受影响 (4148d420)

### Fixed

- **应用内更新按了「立即重启并应用」后没有任何反应**:更新其实成功了,只是界面上什么都不显示 —— 没有重启中状态、不刷新、也不告诉你换到了哪一版。现在会等新进程真正起来后整页刷新,并弹「已更新到 X」/「已退回 X」;90 秒没等到会提示多半是容器没配重启策略,可以再等;新进程报的版本对不上(新版没起来、启动器退回了)也会明说。服务卡住时按钮不再无限转圈 (1aee5390, 366e41e8, 16b34654)

## [0.9.0-alpha.2] — 2026-09-03

链接解析上线:群里有人贴 B 站视频链接,机器人自动回一张视频卡片。这也是**第一个能在应用内装上的版本** —— 已经跑着 0.9.0-alpha.1 的,把「系统」页的更新渠道切到「预发布」、检查更新即可;更早的版本仍得拉镜像 / 装安装包。

### Added

- **链接解析**:群里有人贴 `bilibili.com/video/BV…` / `av…` 链接或 `b23.tv` 短链,机器人自动回一张视频卡片 —— 用的就是推送动态卡那一套,你在版式编辑器里排的块顺序、装的皮肤都跟着走。**默认关**,「系统」页新增「链接解析」一节:总开关,加一个冷却时间(同一个群同一个视频多久内只出一次,默认 60 秒,0 = 不节流)。开着就意味着机器人在的**所有群、谁贴都算**,所以这个开关得是你自己按的;私聊里贴不理。失败一律沉默:视频不存在、没配 Chrome、发送失败,都只记日志、不在群里回话。另有两条不可调的底线防换着视频刷 —— 每个群每分钟最多 6 张、全局同时最多处理 3 张(超了直接放弃,不排队,免得把真正的开播 / 动态卡挤到后面)。OneBot 直接可用;QQ 官方机器人要群主在群设置里把机器人的消息范围放到「获取群内全部消息」,留在「仅 @ 机器人」那档的话得 @ 它再贴链接 (1c207f55, 054de844, e4258dd6, 8515a5ab, 0b704c65, fbbdecd6, 21a5d998, 26cb201a, 1e4e3807, 15933417, bf16508b)

### Fixed

- 推送目标页的 QQ 会话发现列表:一条没带名字的后续事件(比如机器人被拉进群)不再把先前记住的那个名字抹掉 —— 群事件本来就不带群名,那个名字是列表里唯一能认的东西 (83827240)

## [0.9.0-alpha.1] — 2026-09-02

应用内更新上线:Docker 与桌面版从此可以在「系统」页里直接换版本,不必再重拉镜像、重下安装包。**从 0.8.0 升到这一版仍得照老办法拉镜像 / 装安装包** —— 机制是这一版才带上的,它是第一个能被后续版本在应用内更新到的版本。这是 alpha:想在应用内收到后续 alpha,把「更新渠道」切到「预发布」;在下一个正式版发出之前正式渠道还没有清单,留在「正式版」渠道检查会报「连不上更新服务器」,那不是你的网络问题。

### Added

- **应用内更新**:「系统」页新增「应用内更新」一节 —— 检查更新、下载、「立即重启并应用」三步,新版本装进数据目录的 `versions/<版本>/` 下,镜像 / 安装包自带的那份永远不动。默认只自动下载(可关),**什么时候重启换版本永远由你按**;应用那一刻服务会重启几秒,推送断一下、直播监听重连。**容器部署请确认 `restart` 策略开着**(compose 模板的 `unless-stopped` 就够),否则进程退出后没人把它拉起来;桌面版由外壳自动拉起,界面跟着刷新。更新渠道分正式版 / 预发布,预发布默认关。同一份包这个进程装过了就不再下;盘上只留当前 + 新装的那一版,更老的自动清掉 —— 只碰长得像版本号的目录,你放进 `/data` 的自己的东西不动。清单和更新包都带签名:验不过的一律不装、盘上什么都不留;比之前见过的旧的清单也不收,代理站缓存或回放旧文件推不回去。新版本要求更高的运行环境(Node)时会明说「请重拉镜像」,不会装上起不来。自己构建的版本没有内置公钥,这一节会说明「本构建未启用」而不是报错 (b6e0e3ff, f3819654, 0ef41f12, cd6e07a5, 3dc9e2d4, fcbcae2f, a8456c94, 006ff174, aed3d192, af24d0c1, 56ff665e, d360a9f3, b3fd8ce0, e08c8f15, 231f4c77, f82f9fbf, a43493dc, 07389758, c5d5a728, 5b13e822, 495a9dc7, 0c0d3b93, 45f44246, 2dea2e64, 92dc633f, 85943621, b7e7feaa, 7ef62ce3, c73e7643, 611819fc, 1d95927c)
- **回退与自愈**:装了新版之后可以一键「退回上一版」(只退一步,不给版本列表)。退回后那一版会被钉住 —— 打开面板不再自动查更新,免得一开面板就把你按的回退撤销了;手动按「检查更新」才是明确要往前走,装上新版会拔掉钉子。新版本要是起不来,启动器连试几次后自动判死、退回上一个能起的版本,不用进面板。我们撤回一个坏版本时:没升的人不会装它,已经下好等重启的那份会被删掉,正在跑着它的人会被带到清单指定的那一版(哪怕版本号更小),重启后不再选它 (73dbbc2f, e75a5eeb, 82eac3af, d6aaaa4f, c6d5b5ef, 084fca87, 436fb88a, f23f4527)
- **有新版时的提示**:打开面板查一次(不定时、不轮询),查到新版右下角出一张带「去更新」按钮的通知卡、不自动消失;概览「系统状态」卡的版本号旁边也标一句,点过去直接滚到系统页那一节。没新版就什么都不说 (6db3d61d, bfd04382, a4e1b38a, 2ba17ead, 0550f67f)
- **下载加速站**:连不上 GitHub 时可以在更新那一节选一个代理站 —— 内置六个候选加一行自定义,「测一遍」由服务端逐个测延迟、并列出每站拿到的清单版本,签名验不过 / 缓存了旧清单 / 连不上分别标出来。默认直连、只能选一个,直连永远垫底兜着;更新包有签名,代理站改不了内容,最多让这次下载失败 (39518ddf, 5440396f)
- 更新那一节会显示新版本的发布说明,并附发布页链接 (78bdd94b)

### Changed

- **Docker 镜像不再注入 `BN_WEB_DIST`;首次启动种进 `bn.config.yaml` 的 `webDistDir: /app/web-dist` 那行会在下次启动时自动删掉**。那行从来不是你填的(界面上根本没有这个字段),留着它就把界面钉死在镜像自带的那份上 —— 应用内更新换了后端、界面却不跟着走。只删值恰好是 `/app/web-dist` 的那行,你自己的注释和排版不动;自己改成别的路径的会保留,但那样应用内更新就换不了界面。配置目录只读时只记一条日志、照常启动 (693da0cb, be4ab102)
- 镜像与桌面版都改经启动器 `boot.mjs` 起服务:它先在镜像 / 安装包自带那份与数据目录里更新过的版本之间选一个,再加载;版本号与界面资源都跟着实际加载的那份走。镜像默认 CMD 已随之改变,自己覆盖过 CMD 的请对一下 (3891c97f, cb0db077, 2d94dc3f)

## [0.8.0] — 2026-08-31

## [0.5.3] — 2026-08-08

定时 AI 锐评落地:到点自动把榜单周报或某位 UP 的个人锐评发进群,发之前还能先私聊给主人过目、等一句「y」再放行。另外镜像的 Node 堆上限抬到了 512MB,并新增一条内存自检日志 —— 有人撞到了旧的 384MB 天花板,而光凭崩溃日志分不清是本来就该吃这么多、还是在漏。

### Added

- **定时 AI 锐评**:「全部 UP 的榜单周报」和「单个 UP 的个人锐评」各有一条独立的定时线,各自设 cron、各自选发送目标,到点自动生成并推送。统计范围 7 / 30 / 90 天,与数据统计页上面那排口径一致。榜单那条在数据统计页顶部设置,某位 UP 的那条在切到该 UP 之后设置 (f811172, 19d0e47, 5245f74, 357fc54, 5e0cb69, 6ee2ce2, f81f1a0)
- **发送前先给主人过目**:打开审批后,锐评生成完先私聊发给主人 —— **主人看到的就是群里将要收到的那一份**(卡片图开着就连图一起发,不是另写一段摘要),回「y 编号」放行、「n 编号」丢弃,48 小时没回自动作废 (4fa6c36, f1b3c68, 8d94b32)
- **主人可以直接在 QQ 里回 y / n**:OneBot 与 QQ 官方两条通道都能收主人的私聊回复了。webhook 只有出站没有回程,在它上面开审批会被直接拒绝并说明原因 —— 否则那条锐评会一直等一个永远收不到的回复 (c21d1a3, 5a133a1, ca3510a)
- **「试一次」按钮**:不用等到点,立刻按**已保存**的配置跑一轮,走的就是 cron 到点走的同一条路(所以顺带也验了「回 y」这条路通不通)。⚠️ 审批关着的时候它是**真发进群**的,不是演习 —— 按下去之前会先问一遍,并写明会发给几个目标 (8e91e60, 1288255)
- **内存自检日志**:默认每 10 分钟一条 `[mem]`,报堆用了多少 / 离上限多远 / 常驻内存 / 堆外内存,以及弹幕收集器占着的规模。堆用量超过上限 85% 时升为警告并附处理办法。嫌吵可以设 `BN_MEMORY_PROBE_SECONDS=0` 关掉,不必去动日志级别 (195ca5e)
- **动态检测出故障时会直接私聊主人**:账号被风控、或拉取动态报错时,除了原有的告警面板,现在还会私聊说一声;**恢复正常之后也会私聊报个平安**(这条只私聊,不会去点亮告警面板) (a4927ba)
- 动态里带的关联视频,现在会渲染成视频卡片,而不只是一行链接 (9c31d0f)

## [0.5.2] — 2026-08-02

这版几乎全在收拾上一版留下的尾巴,大多是内存与错误处理这类看不见的地方:上传的字体不再在内存里存两遍、也不再赖着不放,超大文件在读进内存之前就被挡在门外,卡片预览排队发出、一张卡卡住不会再把其余几张拖死,出错时也不再把前端自己的毛病说成「网络断了」。另外 OneBot 多了两栏超时设置,带图和合并转发的超时终于能自己调。

### Added

- **群聊女仆会声称帮你改好了订阅,其实什么也没发生**。订阅的增删改早就只能在面板或指令里做,提示词却还在指挥她去调用并不存在的工具 (4c9e747)

### Changed

- 字体上传被拒时的提示,从一行小红字改成和「字体偏大」同样醒目的提示块 (12ab29a)
- 部署文档补上两条建议:出图那一下是整个服务的内存峰值,**宿主可用内存建议 1GB 以上**(只有 512MB 的请改用 `:slim` + 远程浏览器);经反向代理访问时**读超时请调到 120 秒以上**,否则渲染成功了请求却被代理掐断,两边对不上很难查。另外附了两条 `docker` 命令,用来分辨面板断线到底是被 OOM 杀过、还是代理掐的 (5a6b449)
