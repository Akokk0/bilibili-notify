# 架构决策记录(ADR)

**一次拷问出来的定案,落一份 ADR。** 这里放的是「**为什么当初这么定**」——决定本身、被否掉的选项、认下的代价。

三类内容各有各的去处,别混:

| 内容 | 去处 |
|---|---|
| **为什么这么定**(决定 / 被否的选项 / 代价) | 这里 |
| **怎么用**(接口、约定、操作步骤) | `docs/agents/*.md`、各包的 `README.md`、拓展的 `extensions/<id>/PROTOCOL.md` |
| **做到哪了**(进度、断点、待办) | 工作稿与 issue,**不入这里** |

标着**「追认」**的是事后据定案记录与实现整理的,不是当时拷问的原文:「决定了什么」与「为什么」可信,「当时的现场」不可考。

## 编号怎么给

**按决策发生的时间排,不是按写下来的顺序。** 补历史决定时如果它排在中间,**整体重排** —— 文件名、标题、索引、交叉引用一起改。2026-09-09 补前两批 ADR 时就是这么做的:那一批里有两份(备份 PIN 2026-07-11、皮肤包 08-14)早于当时的 0001,不重排就没有号给它们。

🔴 **什么时候就不能再重排了:编号被 `docs/adr/` 之外的东西引用之后** —— 别的文档、issue、commit message、对外的说明。到那时重排会把那些引用悄悄指向另一个决定,而改的成本从「跑一遍脚本」变成「找遍所有引用」。

**所以重排之前先 grep 一遍全仓**,确认零外部引用;有了就别动,新决定接在末尾、靠索引表的时间列排。

```
## 明确不做    拷问中被否决的 —— 这一节最值钱,它拦住下一次重开同一个话题
## 后果        包括认下来的代价
## 仍未决      **决策层面**还悬着的(进度 / 欠账 / 没验的不算 —— 见开头那张表)
```

**「明确不做」那一节别省。** ADR 的价值一半在这儿:半年后有人(包括我们自己)提出同一个方案时,能一句话答完「试过,理由在 ADR-000N」。

## 一份 ADR 该多大

**默认一个决策一份,一页写完。** 决策变了**不改旧的** —— 开一份新的,把旧的标上「由 ADR-000N 取代」,旧的留着当历史。这样单份永远不膨胀,涨的是份数;一个项目有几十份短 ADR 是正常的。

**主题 ADR 是例外**,只在「这摊决策互相咬合、拆开就读不懂」时才开(ADR-0012 拓展化、ADR-0014 卡片皮肤)。它买到的是「一个地方读完整摊」,代价是**它会一直长胖**。所以配两条硬的:

- **这个主题做完之后的新决策另开号**,引用它,别再往里追加。
- **主题还在施工时,改了其中某一条**:原文一字不动,在那一条下面追加一行 `🔗 **日期 改成什么**:……(去哪看)`,施工细节改进 docs 里的施工参考;只有整块设计被推翻才另开号(2026-09-27 定,ADR-0021 改期那条是第一例)。
- **销账即删**:**待办**做完了就别留在文件里 —— 它的价值在 git 历史里,留在正文里只是噪音。⚠️ 别误伤**决策被取代**那种划线(「~~旧决策~~ —— 某日推翻,现在的规矩是……」):那是 ADR 最该留的东西,它拦住下一次重开同一个话题。⚠️ 也别整条删 —— 销账的壳里常裹着当时顺手定下的决策、或一条还活着的尾巴,先把它们挑出来归位(2026-09-16 瘦 0014 与 0012 时两次都差点删掉)。

**一条事实只写一处。** 参数为什么是这个数、坑是在哪儿踩的 —— 写在**代码注释**里,那儿离出事地点最近;ADR 只写「定了什么 / 为什么 / 否了什么」。两处各写一份的下场是改一处忘一处。

## ADR 里不写什么

- **对外口径** —— 发版公告怎么说、对用户怎么解释,那是公告与 CHANGELOG 的活。
- **对其他框架的意见。**
- **本机路径。**
