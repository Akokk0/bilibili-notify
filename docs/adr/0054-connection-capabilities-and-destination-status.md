# ADR-0054：机器人能力与群内状态分层展示

状态：已接受（2026-11-17，主人确认）。

## 决策

1. 推送目标页的连接卡展示机器人经 BN 可使用的能力；具体群目标展示群内身份与使用记录。能力支持、群内权限和剩余额度分别表达，不能相互推断。
2. 复用 `ConnectionCapabilities` 三态。保留已有 `atAll`、`nativeShare`、`inbound`，增加可选的 `image`、`imageGroup`、`forward`、`audio`、`markdown`。缺项为未知；未接入 BN 发送链路的语音显示不支持，不能把平台可能支持当成本程序已支持。支持态也可通过 `reason` 说明范围，如 QQ 私域机器人仅图集使用原生 Markdown。新字段只供展示，不改现有发送路由。
3. 新增目标状态只读接口，宿主按目标和连接寻址后委托适配器。第一批实现为 QQ 官方与 OneBot；暂不开放给拓展，桥未报告的群内身份保持未知。查询不发送群消息，停用、无权限、失联和坏响应均不能显示为已确认的成员身份。
4. QQ 官方角色来自 `bot_state`；OneBot 来自登录身份与群成员资料。查询有短缓存、并发合并、手动刷新与限流；连接设置、机器人身份或群地址变化使旧状态失效。发送前的 QQ 管理员检查仍取新结果，不以页面缓存代替。
5. QQ 官方没有今日剩余额度查询。按 BN 发送记录显示“今日未记录使用／已使用／平台提示用尽／发送结果待确认”，注明来源为 BN；未记录不能显示“剩余 1 次”。记录按机器人应用身份、沙箱、群和北京时间日期区分，经集成状态存储保存并在重启后恢复。成功才登记已使用；明确额度错误登记用尽；发送结果不确定不能声称仍有额度。不依据本地记录拦截发送，最终由 QQ 判定。
6. UI 使用已有玻璃卡、圆角矩形、三态图形和字号；四语文案齐备。刷新期间保留布局，失败有原因和重试入口。

## 验证

主人已确认能力接口、推送目标页面、新增群内状态接口与适配器公开入口，以及本机 QQ HTTP 夹具中的用量记录、跨群／跨日、重启恢复测试；不向真实 QQ 发送测试消息。
