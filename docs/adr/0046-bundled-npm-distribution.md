# ADR-0046：npm作为自带宿主的正式发行渠道

- **状态**：2026-11-11主人定案；实际发布另行确认。
- **影响面**：`@bilibili-notify/bn`、宿主装配、主程序发版流水线。
- **修订**：[ADR-0045](0045-bn-runtime-cli.md)决策4的下载获取方式；其他开发、数据和隔离边界继续成立。

## 背景

首次运行再从GitHub下载宿主，会让无法访问GitHub或访问缓慢的用户无法正常使用npm入口。用户要求npm与Docker、桌面端一样成为正式使用方式，安装包自带载荷，并随主程序每次发版。

## 决策

1. npm包包含正式、开发两种已构建宿主及面板，版本、用途、大小和摘要随包固定。安装后的`bn web`、`bn dev`只读取包内载荷，解包校验后运行，无需GitHub、源码检出或本机编译。Node和公开npm依赖由安装环境提供。
2. npm版本跟随主程序`v<VERSION>`，预发布使用`alpha`，正式版使用`latest`。源文件仍保持`0.0.0-dev`，流水线构建前临时同步。SDK和拓展创建器保持独立版本。
3. 同一主程序tag分别触发npm、Docker、桌面端、应用内更新载荷；各渠道独立构建和发布，共用门禁、版本守卫与正式宿主装配。npm另包含明确构建用途的开发宿主。
4. 发行命令先核对完整包及版本；dry-run不写registry。已发布版本不可覆盖，重跑核对现有内容，旧版本不可把渠道指针倒退。正式流水线通过npm可信发布身份授权；账号配置及首次实际发布由主人确认。
5. 持久数据继续放在npm缓存之外。`web`沿既有应用内更新机制，`dev`保持开发用途隔离。此决定解决npm安装、重装和升级的宿主获取，不重做应用内更新服务。

## 明确不做

- 不在首次启动时下载GitHub载荷，也不要求用户提供载荷路径或离线参数。
- 不把业务核心workspace包逐个公开发布，不把开发能力编入正式宿主。
- 不由本次施工登录npm、上传包、推送tag或改变组织权限。

## 后果

npm包体积包含两份宿主，构建及发布需要验证两种用途。用户可以仅通过npm完成安装与升级，不再依赖GitHub提供首次运行所需文件。
