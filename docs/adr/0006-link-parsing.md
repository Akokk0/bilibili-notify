# ADR-0006:群里贴链接自动出卡 —— 范围、形态与不回卡

- **状态**:**已实现并发版**(2026-09-02 四项拍板 → 09-04 群白名单 13 问 → 09-05 小程序卡 → 09-07 「收到小程序卡不回卡」;分别随 v0.9.0-alpha.2 / v0.9.1 / v0.10.0 / v0.10.1 发出)
- **记录方式**:⚠️ **事后追认** —— 据三轮定案记录与已落地的实现整理,非当时原文。
- **影响面**:`apps/server/src/runtime/link-parser.ts`、`link-scope.ts`、`packages/internal/src/schema/link-parsing.ts`、`apps/server/src/platforms/*-inbound.ts`、系统页的链接解析卡

## 背景

这个功能的起因很实际:主人 2026-09-02 说「写个新功能试试更新功能的效果」——它是用来验证[应用内自主升级](0005-in-app-self-update.md)那条链路的第一个真功能。

选它是因为**约束来自地形**:OneBot 的群帧本来就进到服务端、只是在 `extractPrivateMessage` 那里被丢掉了;官机也收得到(群主可在群设置里给机器人设三档消息范围)。所以「收群消息」这一半是白拿的。

## 决策

### 第一轮:形态(2026-09-02,四项拍板)

1. **触发范围 = 机器人在的所有群**,不是「推送目标群 + 主人私聊」。**私聊不做。**
2. **链接形态 = 完整 URL + b23.tv 短链**,裸 BV 号不认。审查后**分享卡也认** —— B 站 App「分享到 QQ」发的是 json/xml 卡、正文为空,链接藏在 `meta.detail_1.qqdocurl` / `meta.news.jumpUrl`。
3. 🔴 **卡片复用现有的视频动态卡,不新做一种。** 把 `getVideoInfo` 拼成 `DYNAMIC_TYPE_AV` 动态喂给渲染器。⚠️ **版式要显式传** —— 不传就退回出厂版式,跟推送卡长得不一样(审查抓到的)。
4. **它不是指令**:与指令分发器**并列**挂在入站上;指令那条「群消息一律不认」的测试原样保留。

### 第二轮:群白名单(2026-09-04,13 问拍板)

5. `linkParsing.scope: "all" | "selected"`(默认 `all`,升级与新装都是 `all`)+ `targets: {targetId}[]`。**条目是对象不是裸 string** —— 给将来「按群差异化」留壳,但今天只有 `targetId`。
6. **引用推送目标的 uuid**(先例是周报的 `targets`),运行时解析成三元组去比入站帧。**悬空 id 运行时忽略、面板只画现存的,不做删目标时的跨块联动**(那是配置 PATCH 删除语义那颗雷)。
7. **只列群类目标**;`selected` 且空列表 = **哪个群都不解析**(严格),面板提示。
8. 🔴 **「停用」在两处是同一个意思**(主人两次强调「链接解析和周报行为要一致」):目标或其连接 `enabled=false` = 暂停 —— 白名单里停用的群**不解析**;周报发送时**跳过**停用目标、结果多一列 `skipped`。**这一条是主人改的,不是我的推荐**(我原推荐链接解析不看 `enabled`)。
9. **真相住 `linkParsing`,不往 `targets.ts` 的 union 上长功能位** —— 那是未来薄插件的接入点。
10. **不加指令入口**,面板是唯一入口。

### 第三轮:小程序卡与「不回卡」(2026-09-05 / 09-07)

11. 模型改成**「默认行 + 逐群例外」两列**(解析 / 形式),取代「范围 + 白名单」。形式二选一:图片卡 **或** 小程序卡,**没有两个都发**。
12. **能力靠空参探 `get_mini_app_ark`(1404/1400)判定,不认实现名** —— 不去猜对面是 NapCat 还是别的。
13. 🔴 **2026-09-07 主人推翻第一轮的「分享卡不特殊处理」**:**进来的本身是 B 站小程序卡的,一律不回卡**。理由是群里已经有一张能点开播放的卡了,再回一张(图片卡也算)都是重复。实现上 `miniAppCardLinks` 单放一格、link-parser **刻意不读它**,而且**不留痕**(不记冷却)—— 随后有人把同一条链接以文字贴出来照常出卡。

### 闸门

14. **闸门按代价排**:先正则挑链接(没链接连配置都不读 —— 读一次是整份 `structuredClone`,而官机「全部消息」档下群里每句话都进这儿)、再配置、再渲染器;网络与冷却留到每个链接那一轮。
15. **自带闸门**:默认关、每群每视频冷却(默认 60s,**从开始处理起算**)、一条消息最多 3 个链接、自己发的不解析、**失败一律沉默**、b23.tv 只跟一跳且只认落到 bilibili.com。
16. **硬上限不进面板**(`LINK_LIMITS`:每群每分钟 6 张、全局同时处理 3 张、两张表各 2000 条 LRU)。**三道闸先看不动手,都过了才一起记账** —— 在冷却里的链接不该吃群额度,因忙而放弃的也不该被记成「处理过」。

## 明确不做(拷问中被否决的)

- **私聊里也解析**:见决策 1。
- **裸 BV 号**:见决策 2。
- **新做一种视频卡**:见决策 3。
- **加一个指令入口**:见决策 10。
- **删推送目标时联动清理白名单**:见决策 6 —— 那是配置 PATCH 删除语义的雷区。
- **审查里的「小写 bv 污染冷却键」是误报,别再提**:冷却键区分大小写,而小写 body 本来就解析不出来,谁都救不了。

## 后果

- **失败一律沉默**是产品决定:群里没人要求解析,失败了还回一句只是噪音,而且等于把「机器人在这个群里」广播出去。
- 链接卡的呈现与**推送的全局动态卡同源**(同一把尺、同一个图廊轮换游标 `global:dynamic`)—— 主人定的「跟着全局走,不另起名字」。
- **入站归一化对称**:OneBot 帧在 adapter 里解析,两端交出**同一个形状**;分享卡链接单放 `cardLinks`,正文只是正文。这条后来成了桥接入站接线的地基。
- **渲染让路靠低优先级车道**,不靠这里数自己发了几张 —— 谁都能触发的卡不能排在开播 / 动态卡前面。
- **System 页的保存范围改成 diff 推导**,不再有手抄清单。

## 仍未决 / 未验

- **链接解析本身(群里贴链接出卡)一直没听主人说真机验过。**
- 未验:真群里 NapCat 收帧 → 出图整条链(含分享卡)、官机群、封面预取白名单、`x/web-interface/view` 不带 wbi 会不会被风控。
- 选择器只对**目标自身**停用标「已停用」,连接停用的目标运行时也算暂停但选择器不标。
