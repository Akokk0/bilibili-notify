# ADR-0012:拓展化 —— 订阅源与推送源开成可下载的拓展

- **状态**:**地基与搬家都已落地**(2026-09-09 两轮 `/grill-me` 共 26 条拍板;桥已是第一个拓展,拓展页与拨开关即热装卸都在;09-10 又去掉了源码根、加了 devtools 装 / 卸 / 重载,把**装 / 卸做成热的**,并给拓展页开了**上传装包**那条路 —— 见决策 34/35/39/40/41)
- **影响面**:`apps/server/src/extensions/`、`apps/server/src/bridge/`(整块搬走)、`packages/internal/src/schema/targets.ts`、`packages/internal/src/schema/globals.ts`、`apps/web` 的拓展页与推送目标页、新增 `extensions/<id>/` 顶层目录
- **依赖**:ADR-0011(`kind` 轴 / 分发键 / adapter 矩阵是拓展契约的地基)、ADR-0005(装载复用它的信任链与机件)
- **取代**:ADR-0009 里「桥接是内置模块」这个身份 —— 桥接将成为**第一个拓展**

## 背景

BN 的功能面在变宽:接一个新聊天平台要改核心词表、发一次版;想接抖音之类的**非 B 站订阅源**更是要动整个订阅系统。而这两件事的共同点是 —— **它们增强的只有两块:订阅 UP 主、推送目标**,其余部分(卡片渲染、路由、免扰、历史、dashboard)完全复用。

于是方向从「把功能塞进核心」转成「**核心提供订阅系统 + 推送系统 + dashboard,具体接哪个平台由拓展写**」——有点机器人框架的味道。

**这不是又一个新方案**:ADR-0011 的 49 个提交全是它的地基,ADR-0009 的桥接八片是**搬家不是推倒**。它换掉的只是分期③ 的收尾方式。

## 决策

### 谁写、做什么、什么时候

1. 🔴 **拓展只有我们写、我们签**,走 ADR-0005 那条签名流水线(同样两把公钥)。**不建第三方生态。** 这一条是后面所有决定的前提:BN 手里握着主人的 B 站登录态(`<dataDir>/secrets/`),而 Node 没有进程内沙箱 —— 同进程加载的第三方代码伸手就能拿走它。代码是我们自己的,这颗雷才不存在。
2. **先开推送源那口**;但装载 / 清单 / 启用停用 / 版本协商这套**地基一次设计到位**。理由不是推送更重要,而是**这条缝已经被验证过一次了**(ADR-0009 走通了协议、端点、adapter、入站、取图口);订阅侧连「源」这根轴都还没有,现在开口等于同时赌「拓展机制」和「一个还没设计过的归一化模型」两件事 —— 两个都错的时候分不清是谁的错。
3. **桥接整块搬出核心,当第一个拓展。** 它是最重的用例(要挂 WS 端点 + HTTP 路由 + adapter + 入站 sink),拿它撑契约风险高但撑得彻底;而「发布前都有调整空间」这条前提让不可逆风险不成立。
4. 拓展住**本仓** `extensions/<id>/`,workspace 引类型,发版用 **tag 前缀**分开(`extension-bridge-v1.0.0` vs `v0.11.0`)。决定性的理由是**守卫**:契约改一格,本仓里所有拓展**当场编译不过**,`vp run typecheck` 一跑清单就出来了;单独仓要等到运行时才炸,而且是在用户机器上炸。

### 叫什么

5. 🔴 **不叫 plugin。** 两条理由:① **会撞车** —— 桥接的用户故事里已经有一个「插件」(装在机器人框架那一侧的那个),BN 自己的东西再叫插件,一句话里就会出现两个不同的「插件」;② **过度承诺** —— 「插件系统」在所有人的预期里是「插进通用插槽、什么都能干」,而我们**刻意**只开两个口。
6. 面板与配置层叫**「拓展」**(extension),分发物叫**「拓展包」**(extension bundle)。「载荷 / payload」已经被 ADR-0005 占了,不能复用,否则日志里会出现「载荷里的载荷」。
7. **契约层不统一命名。** 两边本来就不是一回事(订阅源产事件、推送源收消息,一个入口一个出口),抽共同基类只会得到一个空壳。推送侧**不造新词** —— `PushExtensionDef` 装着三样已有名字的东西:`PlatformAdapter`(行为)+ `PlatformDescriptor`(元信息)+ config 字段表;订阅侧造词 `SubscriptionSourceDef`(那边今天连轴都没有)。

### 拓展包长什么样

8. 拓展包 = **`extension.json` 清单 + `index.mjs` 代码**,清单进签名摘要。清单必须存在的三条理由:① dashboard 要在「装了但没启用」时列出它,而没启用就不该 import;② **兼容性检查必须发生在执行之前** —— 为旧宿主写的拓展该「不加载 + 说清楚为什么」,而不是「加载了、注册到一半炸掉」;③ 失败记账要拿得到身份,而恰恰是 import 那一步炸了的话,代码里的导出取不到。
9. **拓展 id 是 URL 的一段**(见决策 11),所以必须 URL 安全且唯一,清单校验要拦。

### 怎么活

10. **生命周期分层:启用 / 停用热,升级重启。**(2026-09-10 补:**装 / 卸也热** —— 见决策 40。)「启用 / 停用不重启」做得到 —— 第一次 `import()` 一个文件不涉及缓存。**「换掉已加载的代码」做不到**:ESM 模块卸载不掉,同一路径 import 第二次不会重新求值,而 BN 是 **ESM + bundle**,没有 CJS 那种删模块缓存的路子。要热做只剩「按版本号换路径」,代价是旧模块永久留在内存里 —— 升级是低频动作,不值得为它付这笔。
11. 🔴 **两条硬约束**:
    - **一切副作用必须经由注入的 ctx 注册**,裸 `setInterval` / 裸挂端点禁止,而且要有守卫拦。这是「能卸载干净」的**唯一**承重条件 —— 只要留一条旁路,卸载就不干净,而**不干净的卸载比要求重启更难 debug**。
    - **路由走动态挂载点 `/ext/:id/*`**:开机注册一条总入口,它去查一张**活的拓展路由表**;卸载一个拓展 = 从表里删一行。⚠️ **不去覆写 Hono 的注册方法**来换一个「可卸载的路由」—— 那是拿框架内部结构换便利,框架一升级就炸,而这条路用公开 API 就走得完。
12. **拓展不该知道自己挂在哪,宿主告诉它。** 挂载前缀由宿主分配并经 ctx 交给拓展 —— 这样改前缀不用动任何拓展。桥接的 `BRIDGE_BLOB_PATH` 常量因此消失,地址变成 `ws://<BN>/ext/bridge`。

### ctx

13. **第一版窄面,就桥接需要的那几格**:logger / 可回收定时器 / 向宿主申请挂载点 / 注册 adapter / 喂入站 sink / 读到属于自己的连接 + 变更通知 / 宿主版本号 / **一格自己的持久状态**。多一格都不给 —— **契约的宽度是不可逆的**,窄面加宽容易,反过来不行;而且我们只有一个真实用例,凭空设计「宿主应该提供什么」就是在猜。
    🔗 **第二轮补了两格、缓了一格**:补 `onUpgrade`(决策 26)与 `publishStatus`(决策 36);**「自己的持久状态」缓到订阅源那一步**(桥用不上它,按同一条纪律等真实用例)。
14. 那格**持久状态**是拿订阅源验地基时补上的(推送侧永远不会发现它):订阅源要回答「哪些是新的」,那个游标必须跨重启活着。宿主负责落盘(复用 `durable-json`)——让每个拓展自己写文件,只会得到几份各自有 bug 的原子写;而且**落盘位置由拓展自己挑的话,卸载时宿主不知道该清什么**。附带好处:备份天然带上它。
15. ⛔ **`bus` 绝不开给拓展** —— `MessageBus` 是全仓唯一事件通道,CLAUDE.md 那条硬约束写着「绝不写 bus 与任何别的事件通道之间的转发器,会自喂死循环爆栈」。

### 装载与校验

16. **两条路都认**:面板安装(复用 ADR-0005 的镜像链 + 验签 + zip 原子落盘 + 越界检查)+ **手放目录**(开机扫 `<dataDir>/extensions/`)。后者几乎是白送的,而它对我们自己开发拓展是刚需。
17. **验签只在安装那一刻,开机不验。** 这不是偷懒 —— `boot.mjs` 加载已装载荷时也不重新验签。`<dataDir>` 里已经装着 cookie 和主密钥,**能往那儿写文件的人早就赢了**,再验一道只是让每次开机多花几百毫秒。手放拓展的用户自己承担责任,与手放 skin / maid-skill 同一个立场。
18. 装在 `<dataDir>/extensions/<id>/`,**不能放进 `<dataDir>/versions/`** —— `pruneOldVersions` 只留当前 + 上一版,会主动删掉不在名单里的目录。
19. **config 两份声明 + 加载时对表**:拓展交一个 zod schema(校验)和一份字段表(表单),宿主在加载时逐格对一遍,对不上**拒绝加载**。它们本来就不是一回事 —— 字段表给人填(label / 控件 / 分组),schema 给机器校验(类型 / 必填 / refine);合成一份要么把字段表逼成一门 DSL,要么让校验退化成只剩类型检查,而真实 config 里有「加速前缀必须 https」「`connector` 必须和 `config.transport` 一致」这种跨字段规则。**两份会漂那笔账由加载期守卫兜住**(同进程,宿主拿得到拓展的 zod)。
20. **图标跟着拓展走**:清单里带一段 SVG,加载时白名单过滤,失败退回灰方章。让图标进 `packages/ui` 的闭表看似省事,但那会**把拓展的独立发版废掉** —— 新拓展要等主程序发一版才有脸。至于「往页面塞外来 SVG 有 XSS 面」:拓展已经在同进程跑我们签过的任意代码了,再担心它的图标有点滑稽。

### 两条前提(不是选项)

21. 🔴 **`isRetiredConnection()` 必须先改** —— 它跑在 parse 之前、拿原始 JSON、用闭集判定,**认不出就开机静默丢弃并在下次写入时落实到盘**。拓展用户配好的连接会凭空消失,一声不吭。判据换成「parse 得过」,推送目标那侧有现成模板(ADR-0011)。
22. **`ConnectionSchema` 开成按 `kind` 判别**,config 由拓展的 schema 校验。继续按 `platform` 判别的话,**第一次 parse 就会抛 `Invalid discriminated union option`** —— 门禁全绿,炸在开机读配置那一刻。
    ⚠️ **这条写的时候以为顶层还按 `platform` 判别,其实分期① 已经改成按 `kind` 了**,所以这一半是既成事实。而「拓展那一支的 `platform` 是开放字符串」那半句**已被决策 27 取代**:那一支根本没有 `platform`。

### 顺带:命名走查

23. 全仓走查过一遍「一词两义 / 一义两词」,**改到中档**:三条会伤人的(~~`"connection not found"` 被当接口做字符串相等比较~~ —— **已修**(`3c21d18b`):一个导出的常量 + `isConnectionNotFound()` 判据,两边共用同一处、「模块」一词三集且跨端无门禁(**09-10 复查:面向用户的只剩「日志模块」一义**,「拓展模块」那一集随拓展化清掉了、其余都是代码注释里的 ESM 模块;剩下的真缝是**日志模块那三档 `core`/`dynamic`/`live` 两端各写一份字面量、没有共享词表** —— 服务端加一个子系统面板上不会出现,单独一片再收)、~~已飘掉的 `data-tour="adapter-add"`~~ —— **重命名那一轮已改成 `connection-add`**;2026-09-10 补了守卫:每个声明过的挂点必须在某个页面 / 组件里真出现一次(此前这条缝跨两端、一道门禁都没有))+ 跟着这次重构一起动的那批(`platform` 当分发键时的形参名、`InboundSinks`、「拓展模块」)。
24. **~468 处 `adapter` 不统一动** —— 大半本来就该叫 adapter(`PlatformAdapter` 指实现、协议文档里指桥那一侧的适配器),改了反而制造新的错;而用户可见面早就清干净了。
25. **`packages/push` / `BilibiliPush` 名不副实但不改** —— 它确实按 B 站 `uid` + `FeatureKey` 路由,**B 站味在参数里不在实现里,是个可辩护的疤**。

## 第二轮拷问(2026-09-09,搬家开工前)

地基(决策 8–20)落地之后、桥接搬家动工之前的一轮,十三格。前一轮定的是「拓展这套东西长什么样」,这一轮定的是「桥怎么住进去」。

### 拓展与外界

26. 🔴 **WS 那格开在低层:`ctx.onUpgrade(handler)`,拓展自带 `ws`。** 宿主只负责「这条 upgrade 是不是 `/ext/<id>` 的」,其余(握手、401/503、`maxPayload`、心跳)全归拓展。高层方案(宿主开 socket、拓展给 `authorize` + `onOpen`)要**现在就凭空发明一整套 socket 词表** —— close code 怎么传、二进制还是文本、背压怎么办 —— 而我们只有一个用例,发明出来的每一格都是猜的。更要紧的是 **401 与 503 的区分是桥协议的语义**(token 不对别重连 / 眼下不收请退避),翻译成宿主的枚举之后,桥协议每加一档都要动核心发一版 —— 而拓展化整件事就是为了不这样。`ws` 能内联进拓展包(server 自己的 bundle 就是这么打的)。
    **认下的代价**:裸 socket 是一个不经 ctx 管的资源,卸载时靠拓展自己的 `onDispose` 关连接;一个进程里两份 `ws`;拓展包变大。
27. **拓展连接那一支:`{ id, name, enabled, testStatus?, kind: "extension", extensionId, config }`。** 取代决策 22 的后半句。
    - **没有 `platform`** —— 桥没有单一平台(后面挂着哪个平台是握手时报的)。必填只能填假值,可选会让全仓读点静默变 `undefined`(ADR-0009 当初拿掉这一格的理由)。真有单一平台的拓展在自己的 `PlatformDescriptor` 里说;**推送目标那一侧照常带 `platform`**,那边本来就是开放词表 —— 平台信息一格没少,只是不住在连接上。
    - **没有 `connector`** —— 全仓 20 处读它,**无一例外**都在问 `=== "webhook"`。给拓展支塞一格,唯一作用是让那 20 处编译得过,那是让契约去迁就调用点。改成谓词 `isWebhookConnection()`。
    - **判别子仍是 `kind`**(`"direct" | "extension"`),不拿拓展 id 当 `kind` —— 判别键不可枚举,第一次 parse 就抛。
    - 换形状**不写迁移**:`kind:"bridge"` 一次都没发出去过。
28. **一个拓展 = 一个推送源;分发键 = `extensionId`,而且由宿主填,拓展不自报。** 自报的话,一个拓展可以声明 `"onebot"` 把内置连接抢过去,或者声明别人的 id 截走别人的连接 —— **归属是宿主的判断,不是拓展的声明**(同决策 12 的挂载前缀)。
    要「一个包两个源」的那天再加一格 `sourceId`:**分发键是算出来的、从不落盘**,加宽时盘上一条记录都不用动。

### 拓展与核心

29. **adapter 矩阵改成活的注册表**,`register()` 回 `Disposable`,消费方在分发那一刻问 `list()`。两段式装配(先加载拓展再拼静态数组)会把决策 10 那句「启用/停用热」作废;而「传同一个可变数组」有一颗**只在开发版炸**的雷 —— dev 下 `adapters` 取的是 devtools `map` 出来的另一份,往原数组 push 的话开发版里根本看不见,两边都不报错。
    **注册口一次交一整包**(决策 7 的 `PushExtensionDef`),不拆三个:拆了就能只注册一半,而「有行为没有面板元信息」是个没人想处理的中间态。
30. **读连接:现读快照 + 变更通知。** `ctx.connections()` / `ctx.onConnectionsChanged()`。三条细则:**给全部而不是只给启用的**(桥必须认得出一条已停用接入的 token 才能回 503 而不是 401,否则主人停用一下,插件那头看到的是「token 不对」);**config 是已经过拓展自己那份 zod 的**,形状不对的那条根本不出现在快照里并记一行;**不给写口** —— 配置的写路径在这仓里只有一条。
    推送式(宿主推快照、拓展自己缓存)被否:缓存与真相会漂,症状是「面板上停用了它还连着」,且没人报错。
31. **入站:拓展交归一化后的内部形状**(`InboundPrivateMessage` / `InboundGroupMessage` + `InboundMeta`),frame → 内部形状那段搬进拓展。宿主另发明一个更窄的中间形状被否:要宿主替它猜不到的字段发明默认值,还多一层翻译;而**内部形状加一格必填的,本仓所有拓展当场编译不过**,那正是决策 4 的守卫。
    🔴 **`connectionId` 拓展给,宿主校验归属** —— 不属于就丢并记一行。放过去的话甲拓展能冒充乙拓展的连接投消息,而主人身份比对走的正是 `platform + address + botId` 三坐标。`platform` 由拓展填(桥后面挂哪个平台只有它知道)。
32. **出口能力加 `markdown`,消费者 = 模板文案按能力降级。** 能力项的存在理由是「BN 要据此分叉」——桥自己怎么渲染 `link` 段本来就归它判,不必报备。真正的分叉在:主人在文案模板里写的 markdown,支持就原样发,**不支持 / `unknown` 就剥成干净纯文本**(宁可少点排版,也别让群里收到一堆星号)。BN 只出 CommonMark 子集,**方言转换归拓展**(转义、模板那套 BN 一个都不该懂)。加一个可选能力键向后兼容,不升协议主版本。
    ⏱ **排在搬家之后单独做**:搬家刻意不改协议语义,混一批就分不清是哪一半干的。

### 分发、开发与验证

33. **表单:可序列化字段表 + zod 两份,`set` 由前端统一生成**(`config[code] = v`)。所以**第一版 config 必须是扁平的一层 key-value**(跨字段联动表达不了,照后果段认下)。JSON Schema 被否 —— 我们已经有 zod,再来一套就是三份声明各说各话。
    **加载期对表要可执行**:字段表每个 `code` 必须是 zod 的一个键,zod 每个必填键必须在字段表里有一栏;对不上当场拒绝加载并说清是哪一格。
    🔴 **`secret: true` 同时当备份脱敏的依据** —— 今天脱敏靠键名黑名单,拓展把密钥叫 `apiKey` 就会**原样进备份文件**,而备份是会被主人发出去求助的东西。密钥要**声明**出来,不能靠猜名字。
34. ⛔ **~~桥随载荷预装~~ —— 2026-09-09 落地当天被推翻。** 现在的规矩是:**本体一个拓展都不带**,拓展只有两条来路 —— **从拓展页传一个包上来**(决策 41;日后从签名镜像下载走的是同一段落地逻辑),或者**主人自己放进 `<dataDir>/extensions/<id>/`**。载荷里没有 `extensions/` 目录,装载器也**没有载荷根**(结构性,不是约定)。
    推翻的理由:「预装」把拓展化这件事做回了内置模块 —— 拓展与本体又一次同一个发布节奏、同一份产物,而整个 ADR 的出发点正是把它们分开。**开发时也不该靠预装**:决策 35 的源码根已经解决了那件事(`tsx watch` 盯得到,实测过),预装反而多一条「我改了怎么没生效」的路。
    **装载器只扫一个根**:`<dataDir>/extensions/`(入口 `index.mjs`)。曾经还有个仓里的源码根,2026-09-10 也去掉了(见决策 35)—— 一个根意味着没有优先级、没有「同一个 id 有两份」,入口也只剩一种。
    **代价照认**:按需下载(走 ADR-0005 的签名镜像链)还没建,所以**在构建产物上跑桥,今天只有「自己 `vp pack` 出包、手放进 `<dataDir>`」这一条路**;真正的分发要等那套流水线。桥仍然一次真机都没跑过。
    与决策 18 不冲突:主人装的不能放 `versions/`(会被 prune 删)。
    **装了 ≠ 默认开着**:`globals.extensions.<id>.enabled` 缺失仍然是关着。
35. ⛔ **~~源码根:开发时多扫仓里 `extensions/`、入口解析成 `src/index.ts`~~ —— 2026-09-10 去掉。** 现在的规矩是:**装载器只有一个根**,开发时由 **devtools 把仓里构建好的 `dist` 链进那个根**(`ext.install` / `ext.uninstall` 两条场景)。
    去掉的理由(主人 09-10 拍板):源码根是**宿主里的一条只在开发版成立的特例** —— 它让开发时跑的东西与主人手放的、日后从市场下载的**形状不同**(两种入口、两个根、还要判优先级与「谁盖住谁」)。改成「装进同一个根」之后,开发时走的就是真实安装路径,宿主那三样特例一起没了。
    参照物是 koishi:它的本地插件也不走特殊路,而是由 yarn workspace 软链成 `node_modules` 里的一个包,与市场装的走同一条 `resolve`。
    ⛔ **清单不加 `entry` 字段** —— 清单进签名摘要,加一格 `entry` 等于让分发出去的拓展指定加载哪个文件;入口固定,**宿主自己判,清单说了不算**。
    **软链而不是拷贝**:`vp pack -w` 一改就重打包,链着的那份当场就是新的。
    **装 / 卸当场生效**(装完自己 `rescan()` 一遍,见决策 40);**已经装着的那些改代码**按一下重载 —— 见决策 39。面板上传装拓展见决策 41。
39. **换代码走显式「重载」,只在开发版**(`LoadedExtensions.reload(id)`,devtools 的 `ext.reload`):收摊 → **换一个 URL** 重新 `import`(`?v=<mtime>`)→ 重新 `activate`。
    ESM 的模块缓存删不掉(决策 10 的「代码不热」正是这么来的),但**URL 不一样就是一份新模块** —— koishi 那 359 行 HMR 靠的是 CJS 的 `require.cache` 可删,我们换个招做同一件事,而且**不需要它那套依赖图**:拓展是自包含单文件,没有图可算。
    代价:**旧模块回收不掉**,每重载一次漏一份。所以只在开发版按,生产那边换代码仍然是重启一次。
    🔴 **刻意不挂在开关上**:拨开关保持生产语义(复用模块缓存),否则开发版比生产宽容 —— 「拓展模块顶层存了状态」这种 bug 只会在真机上露面。
    **重载不进失败记账**:记账防的是开机反复炸,而重载是主人手按的;改一行崩一次、三次就自动停用的话,开发循环当场卡死。
40. **装 / 卸也是热的:显式 `rescan()` 再扫一遍装载目录。**(2026-09-10;主人报「装了拓展要求重启,可 BN 既不自动重启也没有重启按钮」之后定的。)
    决策 10 否掉的只有「**换掉已加载的代码**」—— 而一个**新出现的 id 从来没被 import 过**,装它与「拨开关第一次启用」是同一档事实,没有模块缓存这回事。曾经要重启,纯粹是因为开机扫一次就把名单定死了,不是做不到。
    三条细则:① **已经收进名单的一律不碰**,哪怕目录里的代码换了 —— 那是决策 39 的活,顺手换掉等于让生产多出一条「换代码不重启」的路(每走一次漏一份模块);② 清单坏了 / 版本不合的那些**每次重读** —— 它们一行代码都没跑过,主人把清单修好就该装得上;③ **消失的从三张表里删干净**,留一格在 ready 里的话,下一次 `sync()` 会把一个已经不在盘上的拓展装回来(它的代码还在模块缓存里,真装得起来)。
    ⚠️ **触发它的是显式动作,不是 `sync()`**:扫盘 + 读清单挂在「任何一次全局设置保存」上,是拿高频路径办低频事(同决策 10 那条理由)。今天按它的只有 devtools 的装 / 卸;主人手放的包仍要重启一次 —— 那个入口现在有了(ADR-0005 决策 22)。
41. **面板上传装拓展:`POST /api/ext/install` 收一个 zip。**(2026-09-10;主人拍板「拓展页应该有一个上传,可以把 zip 放进去」。)
    拆包那一层是**一道真闸,不是格式转换** —— 它把「往装载目录里放代码」从**文件系统权限**降到了**一次面板会话**,而放进去的东西是会被 `import` 的:① 白名单收文件(只有清单与入口,夹带的整包拒绝 —— 黑名单永远漏一个);② **落盘的目录名只来自清单里那个 id**(它已过 `ExtensionIdSchema` 的正则),zip 里的路径一个字都不拿来拼;③ 路径里出现 `..` 直接拒;④ 层数、大小、文件数封顶;⑤ 清单当场 parse、`apiVersion` 当场比对 —— 主人还拿着那个包的时候,这句话最有用。
    **先写 staging 再整体换过去**,覆盖时把旧目录整个删掉:半个拓展(清单是新的、代码是旧的)是最难查的一种状态。⛔ **目标是软链就拒绝** —— 那是 devtools 链进来的仓库工作树,往里写等于往 `git status` 里拉屎。
    **新装的是热的**(落盘完 `rescan()` 一遍,当场跑起来);**盖掉一份已经装着的**要如实回 `needsRestart: true` —— 那份代码 import 过,ESM 在这个进程里换不掉(决策 10)。那句提示与**唯一那颗重启按钮**就出现在这一刻(ADR-0005 决策 22)。
    ⚠️ **代价:今天不验签。** 签名分发那条链(ADR-0005 那套)还没建,所以这个口信的是「能登进这个面板的人」—— 与「主人自己把目录拷进 `<dataDir>/extensions/`」同一档信任,只是省了一次 ssh。与决策 1 不冲突(拓展仍然只有我们写、我们签),但它确实把「拿到面板会话」变成了「能在 BN 进程里跑代码」,UI 上那句「只装信得过的包」不是客套。签名链建好之后,验签就加在这道闸里,位置已经留好。
42. **devtools 加一条「假装一条桥连上来」。**(2026-09-10;⚠️ **当天推翻过一次**:先按「假桥住拓展自己家」落了地 —— 理由是核心不该认识桥的协议帧 —— 主人当天把它推回 devtools,理由是**这就是 devtools 该干的事**。拓展里那份已删。)
    没有真插件时,拓展页上那条桥接入永远是灰的:能力矩阵、状态面板、bot 名单、失败提示一格都看不见。这条场景拿**那条接入自己的 token** 连一条**真 socket** 回 BN 身上,于是 upgrade、鉴权、握手、`publishStatus`、推送 adapter、回执全是真的 —— 假的只有「后面没有 bot」这一件。
    它是**假状态**:连着的那条由 devtools 造,所以进「当前生效」条、归一键收摊;而它带来的推送**真的发生过**(历史里那行、失败提示那句)不清 —— 那是真动作。⛔ **不做退避重连**:假桥跑在 BN 自己进程里,BN 没了它也没了,重连没有对象。
    🔴 **代价:协议知识在核心里有第二份**(`devtools/fake-bridge.ts` 的帧是照 `PROTOCOL.md` 手写的,核心 import 不到拓展)。手写的会漂,而漂了的症状是「按下去卡片不变绿」且**没有任何门禁会红**。所以配了两道:单元测试钉帧的形状,`__tests__/devtools-fake-bridge-e2e.test.ts` 把**真桥的构建产物**装进装载根、让两边真说一次话 —— 验过:把桥的协议 major 改掉,单元测试 17 条照绿,这条 3 条全红。
    住核心白捡的一样:私聊那条驮上去时**发信人默认取配置里的主人**,所以指令分发器会当真 —— 桥自己家那版够不着这个配置。
36. **面板要的数据走 `ctx.publishStatus(() => json)`,宿主在 `/api/ext/:id/status` 下发** —— 走 `/api/*` 才吃得到 dashboard 会话鉴权。放进 `/ext/<id>/*` 是个安全洞:那条路**刻意在鉴权外**(对家手里只有 URL、没有会话),会话列表与 bot 名单会跟着公开。
    **形状第一版不约束**(任意 JSON,现取不缓存):面板那一页还没写,而**抽象要两个例子**。
    契约跟着归位:`apps/contract/src/bridge.ts` **整块搬进 `extensions/bridge/`**,核心里一格 bridge 的字都不留 —— 可验证形式是搬完之后 `grep -ri bridge apps/contract packages/` 为空。
37. **验证:本仓写一个 e2e 桥客户端夹具**(纯 Node + `ws`,真 upgrade → `hello` → `welcome` → `bots` → `send` → `result`,外加真 GET 一次取图 URL)。现有测试全在各自搭的零件上跑,**没有任何一条**证明「真客户端带真 token 连上来能收下一条推送并回执」,而搬家动的正是装配的每一根线。夹具同时是**协议文档的可执行版本**。
    真插件那侧另算,**证明不了真框架的怪癖**,写进「仍未决」不假装验过。
38. **URL 面一律 `ext`,代码与配置面一律全称。** 对外 `/ext/<id>/*`(WS 与 HTTP **同一个路径空间**,scheme 不同而已),面板 `/api/ext`、`/api/ext/:id/status`;代码里 `globals.extensions` / `ExtensionDTO` / `loadExtensions` 不动。
    定词形的是**会被人手敲的那一侧** —— `ws://<host>/ext/bridge` 要填进另一个程序的配置框;`/api/ext` 没人手敲,跟着短的走没有代价。两个前缀本身**必须留**:分开它们的不是协议,是**鉴权域**(`app.use("/api/*", dashboardAuth)` 是一条结构性的边,改成逐条判要不要鉴权,漏一条就是把数据公开且不会报错)。

### 施工顺序(第二轮定)

**关键性质:桥的分发键搬家前后都是 `"bridge"`**(今天是 `BRIDGE_DISPATCH_KEY`,搬完是 `extensionId`,同一个字符串),所以每一步都能保持绿。

① 连接换支(决策 27)→ ② 矩阵改活注册表(29)→ ③ ctx 补格(26/30/31/36)→ ④ 表单两份声明(33)→ ⑤ 装载根(34/35)→ ⑥ **搬家(原子,不拆)**→ ⑦ e2e 夹具(37)→ ⑧ 文档与文案。之后单独一片:markdown 能力(32)。

**⑥ 刻意不拆**:桥移出核心与核心里对它的引用消失是同一件事的两面,拆开会出现一个中间态 —— 拓展目录里的代码被核心直接 `import`。那条边谁都不该有(拓展 import 不到核心,核心也不该 import 拓展),留一步就是示范了一次错的接法。它是约一千行**位移**,逻辑一行不改。


## 明确不做(拷问中被否决的)

- **第三方生态**:见决策 1。真要走,答案是**进程隔离**(桥那个形态),不是把 ctx 开宽。
- **拓展带自己的前端组件**:web 是单 bundle、`vite.config.ts` 零个运行时加载外部代码的口子。拓展的 UI **只能是「数据描述 + 主程序渲染」**,这一条是架构定的不是偏好。
- **半热插拔**(停用只是「不再调用」、代码留内存):那是个谎言 —— 定时器还在跑、端点还挂着,开关和实际行为对不上,比要求重启难受得多。
- **拓展跑子进程**:为省一次重启把决策 1 排除掉的进程隔离又请回来。
- **一个统一的拓展基类**:见决策 7。

## 后果

- ⛔ **本体不带拓展的代价**:签名分发流水线建好之前,构建产物上跑桥靠的是「自己 `vp pack` 出包,再从拓展页传上去(或手放进 `<dataDir>`)」——**中间没有验签这一步**(决策 41 的代价段)。这是明知的、认下的 —— 换来的是拓展与本体真正分开发布(见决策 34 的推翻理由)。
- **拓展的 UI 有两笔代价要认**:① 字段表序列化之后**跨字段联动表达不了**(桥接的 config 是 `{token, bridgeKind}`,第一版不疼);② 声明式词表要多丰富才够用,是个会持续加档的事(今天有 text/number/toggle/select/chips/headers)。
- **桥接的地址变成 `ws://<BN>/ext/bridge`**,协议文档 §2 与面板文案要跟着改。因为一行没 push,这次改是免费的。
- `globals.extensions` 的语义从「内置模块开关」变成「装了哪些拓展、开没开」。
- 拓展失败记账按 **id + 版本**,连续失败自动停用;骨架抄 ADR-0005 的「选中就记账、起来了才销账」,把 key 从版本号换成拓展 id。
