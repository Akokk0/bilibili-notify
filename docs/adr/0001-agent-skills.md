# ADR-0001:用户可写的 Agent Skill 取代写死的技能胶囊

- **状态**:**已实现**(2026-08-20 经 `/grill-me` 拷问定案,同日落 dev:`8cff038` → `2d25c81` 七笔;**尚未发版、尚未真机验证**)
- **影响面**:独立端 dashboard 的 AI 聊天(`apps/web/src/components/ai-chat/`、`apps/server/src/routes/ai.ts`、`packages/ai/src/commentary-generator.ts`)
- **不影响**:koishi 的 `bili.chat`、AstrBot —— 见「决策 · 边界」第 2 条

## 背景

> 这一节写的是**决策当时的现场**,其中被诟病的代码已随本 ADR 删干净了。行号是那一刻的快照,别拿去对今天的文件。

今天的「技能」是 `apps/web/src/components/ai-chat/skills.ts` 里一个**纯前端常量数组**(`AI_SKILLS`,:41),五条,形状 `{ cmd, icon, desc, prompt, mode? }`。文件头自述「技能不是后端概念,只是**预置提问**」。它有三处实打实的毛病:

1. **加了参数就整条失配。** `resolveSkill`(:99)要求**整条输入恰好等于 `cmd`**,所以打 `/锐评 只看这三个人` 时技能一个字都不进 —— 发给模型的是字面量 `"/锐评 只看这三个人"` 这句它根本不认识的话。注释把这说成「别把追加要求悄悄吃掉」的保护,实际后果是主人以为在用技能、其实在跟模型说暗号。
2. **`/体检` 是空头支票。** 它问「推送目标有没有异常?检查各群 / 频道的连接状态」,而 `TOOL_DEFINITIONS`(`packages/ai/src/tools.ts:25`)里 7 把工具全是 B站 只读查询,调用点注入的 `extraTools`(`apps/server/src/routes/ai.ts:442`)只有皮肤那套 —— **一把跟推送目标有关的工具都没有**。女仆要么说做不到,要么编一个。
3. **`mode` 传不出胶囊那条路。** 胶囊发的是展开后的 `prompt`,技能身份在这一步丢掉,于是带 `mode` 的技能被整条滤掉(`index.tsx:673`)。这个滤法本身是 `dd4998c` 的有意决定、`3ed0dc0` 又把它写进了注释 —— 但它是在给信道的缺陷打补丁。

更要紧的一层认识:`/锐评`、`/优化`、`/文案` 这三条**本来就是多步编排**(列订阅 → 逐个查数据 → 按规则判定 → 固定排版),被压扁成一句提问才显得「写死」。它们不是「一句话」,是**被截肢的 skill**。

## 决策

### 形态

1. 一条 skill = **一份 `SKILL.md`**:frontmatter(`name` / `description` / `allowed-tools` / `disable-model-invocation`)+ 正文指令。
2. **单文件**。不收 `reference.md` 之类附件,不做渐进披露,**不跑脚本**。
3. 存 `dataDir/maid-skills/<name>/SKILL.md` —— 真文件,可手放、可导出。(原文写的是 `dataDir/skills/`,动工前改掉:盘上已经有一个 `dataDir/skins/`,而那正是主人**手放文件**的目录,两个名字只差一个字母。)
4. 作者体验:**网页里直接编辑**(名字 / description / 正文三个框)。

### 边界

5. **只给独立端 dashboard。** koishi 的 `bili.chat` 没有权限门,而 skill 正文是提示词注入面 —— 群里任何人都能触发主人写的 skill,这条口子不开。AstrBot 同理。
6. `load_skill` 工具走 dashboard 调用点的 `ExtraTool` 注入(与 `create_skin` 同一条路,`routes/ai.ts:442`),**绝不进 `TOOL_DEFINITIONS`** —— 那是三端共享的只读表。

### 触发与展示

7. **两条路都要**:模型读 `description` **自选**,主人也能**打斜杠**。
8. 斜杠收 `/skill` 与 `/skill 补充内容`:正文进上下文,后面那串字当主人这一问。这是背景第 1 条的解药。
9. 不论哪条路,skill 被用上都在消息流里出一枚**调用痕迹胶囊**,复用工具小条那套(`ToolChips` / `describeTool`,转圈 / 勾 / 叉三态)。模型自选时尤其必要 —— 否则女仆莫名换了套说法,主人不知为何。
10. **空态那排胶囊全拆**,只留一句引导语。因此 frontmatter **不收 icon**(现有 `IconName` 是闭集,用户自写的 skill 本来也无从取图标)。

### 能力与成本

11. skill 可声明工具**子集,只减不加**。用户可写的数据永远不能扩大工具面。
12. 收紧时机照 Claude Code:工具循环里**下一轮即刻生效,零额外往返**。理由是工具调用之后**本来就要再发一次请求**把结果喂回去,那一次顺路带上窄化的工具表。<br>写这条时以为「只需把 `toolOptions` 从循环外常量改成可变持有」—— **不对,漏了半条链路**,见「实现记录」第 1 条。
13. **不限 skill 总数**,只限常驻那批:每条可 `disable-model-invocation` 退出模型自选,`description` 加长度上限(≤200 字)。依据是常驻的只有一句 description(15~30 token),20 条也就 400~600 token,不值得设闸。
14. SKILL.md 正文**追加**在女仆人格之后,**人格照旧**。

### 内置

15. 内置 skill **写在代码里**,只读、跟版本走;用户建同名**直接拒**(「已被内置占用」)。
16. **`/皮肤` 与 `/体检` 都删。** `/体检` 无工具可用(背景第 2 条);`/皮肤` 的全部意义是 `mode: "skin"`,而 skill 声明不了模式(第 11 条),工坊入口只剩侧栏那颗「新建皮肤工坊」按钮。

## 明确不做(拷问中被否决的)

| 方案 | 否决理由 |
| --- | --- |
| skill 带可执行脚本(完整 Claude Code 标准) | 这台 server 攥着 B站 cookie、推送目标、AI key,而 skill 正是「从网上抄一份贴进来」的东西 —— 等于给面板开 RCE 口子 |
| skill 带 `reference.md` 等附件 + 渐进披露 | 主人拷问后自己撤回:真会写的头几条都是「多步编排现有工具」,单文件装得下,附件是凭空多一层文件管理 + 一把读文件工具 + 一套路径白名单 |
| 三端共享 skill | `bili.chat` 无权限门(边界第 5 条) |
| skill 可声明**模式**(让 `/皮肤` 变成普通 skill) | 那等于让用户可写数据挖到写工具(`create_skin`),安全边界要重画 |
| 内置 skill 可改 + 「恢复默认值」 | 主人选了「只读跟版本走」:内置由我们维护、升级即生效 |
| 存进配置(跟 `presets[]` 一个路子) | 那就不是 Agent Skill,只是借了它的字段名 —— 主人要的是真标准 |
| 空态保留几枚不带参数的 skill 胶囊 | 全拆,一个入口就够 |

## 后果

以下五条是拍板时的预判,**已全部照办**:

- **无数据迁移。** 现有五条是代码常量,直接删,盘上没有用户数据。
- **要删的东西**:`AI_SKILLS` 常量、`index.tsx:673` 那排胶囊及其 `.filter((s) => !s.mode)`、`3ed0dc0` 写的那两段注释(连同它们钉住的 `chat-mode.test.tsx` 两条测试)。`dd4998c` 的决定随之作废 —— 它是在给一条即将被拆掉的信道打补丁。
- **`resolveSkill` / `resolveOutgoing` / `matchSkills` 全部重写**:从常量数组查改成从服务端拉,并接受 `/name 补充内容`。落地后 `resolveSkill` 整个没了 —— 它的活(把命令换成写死的 prompt)现在归服务端,浏览器这边只拆「点名了哪条」+「他这一问是什么」,技能正文一个字都不经过前端。
- **新增服务端模块**一个(skill 的读写、frontmatter 解析、`load_skill` 工具)→ `apps/server/src/maid-skills/`(`parse` / `store` / `builtin` / `chat-tool` 四份)+ `routes/maid-skills.ts` + 契约 `apps/contract/src/maid-skill.ts`。名字正则与三条长度上限只在契约里写**一份**:服务端拒收与网页端提示若各判各的,迟早出现「网页说没问题、存进去被拒」这种主人无从下手的状态。
- **常驻成本上涨**:每轮请求多带一份可自选 skill 的目录。按第 13 条量级可接受。

## 动工前拍板的(原「未决」1~4)

1. **名字规则** → **强制 kebab-case ASCII**(`^[a-z0-9]+(?:-[a-z0-9]+)*$`,≤32 字符),中文不收。定案理由不止「照 Claude Code 标准」:白名单里没有 `.` `/` `\`,`..` 在构造上就拼不出来 —— 比「收中文再拿正则防穿越」少一整类错法。参照皮肤库的教训:`SkinStore.remove` 曾因少了一道 id 校验,被 `DELETE /%2e%2e%2fconversations` 删掉整个会话目录(2026-08-19 审计实测)。全小写还顺带躲开 macOS 大小写不敏感与 NFD 归一化两个坑。
2. **新目录叫什么** → 主人拍板 **`maid-skills`**(服务端模块与 `dataDir` 子目录同名)。`agent-skills` 是我提的,被否。
3. **内置写哪几条** → 六条,全部只用**真实存在**的工具:`weekly-report`(周报)、`unsub-cleanup`(停更清理)、`live-copy`(开播文案)、`today-digest`(今日速览)、`find-up`(找 UP)、`up-pk`(UP 对比 PK)。后三条是主人追加的;`find-up` 用上了 `search_user` —— 那是工具表里此前**没有任何地方用到**的一把。
4. **编辑器放哪儿** → `/ai` 页开**第四个 tab「女仆技能」**。它刻意**不进页面级保存栏**:技能是逐条独立的文件,跟那一页其余设置不是一批东西,混进同一颗「保存」只会让人不知道按下去动了什么。

## 仍未决

5. **强指令 skill 与女仆人格的观感只能真机验。** 第 14 条选了「追加」,那么像 `grill-me` 那种「毫不留情地追问」的 skill 会跟「温柔女仆」并存,模型夹在中间。这是知情下的取舍,但第一版要盯着看;真打起来,frontmatter 再加一个「顶掉人格」的开关也不迟。
6. **模型到底会不会自选。** 常驻的只有一句 description,女仆是否真能在合适的时候伸手去调 `load_skill`,单元测试证不了 —— 只能真机看。若发现它从不自选,该动的是 description 的写法(或把提示词里点一句),不是加闸。

## 实现记录(动手时才浮出来的)

1. **收窄有半条链路差点没接上。** responses 那一味的工具表 `toResponsesTools(toolOptions.tools)` 是在**取轮循环之外**算的一次性常量 —— 照决策 12 只改 `toolOptions` 的话,收窄在 chat 那一味生效、在 responses 那一味**静默失效**,而两味共用的测试当时只覆盖 chat,会一直绿着。把它挪进 `makeParams` 才算真按第 12 条办。**教训**:两味同源的改动,测试要两味都写。
2. **`load_skill` 把自己写进 `restrictTools` 保活。** 收窄是单调只减的,技能一旦声明了 `allowed-tools`,模型挑错了技能就再也换不回来。让工具在返回时把自身名字带进收窄名单,生成器不必为它开特例,收窄也仍然只减不加。
3. **皮肤工坊里带 `skill` → 400,不静默吞**(`2d25c81`)。第一版写成了静默忽略,而那正是背景第 1 条的翻版:主人看着自己打的 `/weekly-report` 发了出去、女仆当普通话回一句,消息流里连一枚痕迹都没有,他没法看出技能压根没生效。
4. **内置那张表的 `allowed-tools` 必须机械校验。** 收窄是交集,所以名字打错的那把工具只是**静默消失** —— 整条链路全绿,只在真机上表现为「说好要查数据却没查」(就是 `/体检` 那个坑的轻症版)。`builtin.test.ts` 拿真工具表逐条对,连正文里用反引号点名的工具名一并对。
5. **`narrowTools` 放在 `commentary-generator.ts`,不放 `tools.ts`。** 后者被四个 suite 整个 `vi.mock` 掉,往那儿加一个导出会让 67 条测试齐报「No export is defined」。补四份 mock 能修好,但那是给下一个人埋雷。
