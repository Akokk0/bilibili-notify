# ADR-0040：拓展SDK与创建器通过npm分发

- **状态**：2026-11-10主人批准npm分发SDK与创建器；进度见[第6期计划](../1.0/phase-6-plan.md)。
- **影响面**：SDK的仓外使用、拓展创建器与两者的发行。
- **修订**：[ADR-0021](0021-neutral-core.md)中契约包暂不发npm的时间边界；其余业务核心包继续私有。

## 背景

仓内拓展经workspace消费SDK，但第三方拿不到私有internal。现有SDK的JavaScript和声明文件都会转引internal，仅改成公开包不能解决仓外安装和编译。Issue #56的一条命令创建拓展，需要先有可独立安装的契约。

## 决策

1. SDK和拓展创建器作为对外开发工具，通过npm分发；其他业务核心包保持私有。
2. SDK源码继续从internal转出既有契约，公开产物包含所需实现和类型。仓外安装和编译不需要私有包、主仓源码、workspace链接或主仓路径别名。
3. 保留根入口与`/build`的用途边界。分发变化不扩大宿主能力，不顺带开放链接解析、AI工具或指令。
4. SDK包版本与宿主契约的`apiVersion` / `apiRevision`分开管理。实际发行版本、npm权限与发布动作在发行时确认；本次批准分发渠道。

## 明确不做

- 不为安装SDK公开整个internal或其他业务核心包。
- 不手工复制一套契约定义，源码仍以现有定义为准。
- 不将本地打包或安装测试当成真实npm发布成功。

## 后果

需验证真实npm包的仓外安装、运行、类型检查与构建。创建器生成的工程消费公开SDK，不要求克隆主仓；两个开发工具增加独立的版本和发布权限准备。

## 实施与发行待定

6-02至6-05已完成本地交付，包名为`@bilibili-notify/extension`与`create-bn-ext`。SDK和创建器的初始发行版本、账号权限和实际发布仍按决策4确认；本机候选归档不算已经上架。其他契约能力是否加宽仍按真实使用者另定。

2026-11-11主人要求像`npm create vue`/`pnpm create vue`一样使用，提出`bn`和`bn-ext`短名；创建器候选改为`create-bn-ext`，对应`npm create bn-ext`/`pnpm create bn-ext`，公开可执行名与包名匹配。原候选未执行发行；公开版本查询404只说明未查到，名称与权限仍在实际发行时核对。
