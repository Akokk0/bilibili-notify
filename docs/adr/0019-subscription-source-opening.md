# ADR-0019：订阅源的口 —— 拓展只报「发生了什么」，数据与决定都归 BN

- **状态**：2026-09-21 ～ 22 `/grill-me` 拍板（25 题，一次一题）；09-22 照设计稿补定界面细节（决策 24–33）。**施工 ① 已完成**（清单 v2 + apiVersion 区间），② 未动工。
- **影响面**：`packages/extension`（契约：订阅源注册、设置项、积木视图、动作）、`packages/internal` 的清单 schema（v2）与订阅 schema（拓展那一支）、`apps/server/src/extensions/`（装载器核对清单、`lookup` / `actions` 路由、设置写入校验）、订阅的存储（另起一个文件）、`packages/dynamic` 的装配段（抽成共用）、`packages/image`（「给 node 就出卡」的入口）、卡片皮肤的选择链（多一层「平台」）、备份脱敏（密钥从清单读）、`apps/web`（订阅页的平台选择、配置弹层分档、拓展详情页改成照声明画、卡片页的「平台 → 皮肤」）、`extensions/bridge`（迁到清单 v2 与声明式界面）、devtools（假源）
- **依赖**：ADR-0012（拓展的地基与纪律）、ADR-0013（市场与第三方源）、ADR-0014（皮肤字段表是只增不删的公开契约、单 UP 选皮肤）、ADR-0016（@全体是挂在主特性下的附加项）
- **修订**：ADR-0012 的决策 14（持久状态格的时间表）、决策 19 / 33（表单那份声明从代码搬进清单）、决策 46（外观三格搬进清单）、「只比主版本、严格相等」的版本规矩、「明确不做」里「拓展带自己的前端组件」（补上后路与永不走的那条）；并写明决策 1 的前提对第三方源不成立（见后果）。各处已在 ADR-0012 原文下挂 🔗。

## 背景

想接抖音，当第一个**订阅源拓展**：装了它，「订阅 UP 主」时多出平台选择，选了抖音，后面的操作与现在一致。ADR-0012 当初先开推送那口，订阅这口只在「仍未决」里留了四件事（身份键换成 `(source, sourceId)`、资料提供者可插拔、特性词表分档、卡片入口降到 `DynamicNode`）。那是 09-09 写的，之后卡片皮肤、附加项、人工重推都改过链路，所以按现在的代码重新摸了一遍：

- **推送链的后半段已经是中立的**：闸、附加项、发送、投递、历史、重推吃的是 `NotificationPayload` + `FeatureKey` + 订阅键，原样可用。
- **B 站形状集中在两处**：动态引擎把「拉取 → 过滤 → 出图 → 链接 → AI → 模板 → 版式 → 广播」一口气做完；卡片入口吃 B 站原始 JSON，而 `DynamicNode` 的正文 / 图廊 / 附加内容三格是**画好的 Vue VNode**，拓展造不出（它只从 `@bilibili-notify/extension` 进，那个包不依赖 vue；自带一份 vue 的话 `Fragment` / `Text` 是另一组 Symbol）。
- **取图有一道 SSRF 白名单**，只认 B 站的域，外站的图静默换成透明占位。
- **订阅早有中立主键 `id`（uuid）**，`uid` 身兼「B 站地址」与「运行期键」两职（约 80 个非测试文件）；`subscriptions.json` 有一条 parse 不过就是开机致命，而应用内更新会退回旧载荷。
- **契约侧**：清单的 `provides` 早收 `"subscription"`，但运行时没人核对；表单字段表只在注册推送源时交，纯订阅源拓展**声明不了密钥**（抖音的 cookie 会明文进备份）；拓展详情页是只给桥手写的。
- **抖音的事实**（公开资料调研）：身份是字符串 `sec_uid`；内容只有视频 / 图文 / 开播下播，没有转发；置顶作品排在最前；09-14 起作品列表被网关拦，要一份浏览器来的 cookie；CDN 图带签名、几小时过期、要 Referer。

## 决策

### 分工

1. 🔴 **拓展只管「和那个平台打交道」，数据与决定全归 BN。**
   - **BN**：订阅记录的增删改与存储（拓展写不了）；推不推、推给谁（路由 / 开关 / 免扰 / 过滤 / @全体）；卡片、模板、AI、版式；发送、投递、历史、重推；设置的存储（只有面板写）。
   - **拓展**：把主人粘的东西解析成「是哪个人」（只返回候选，建不建由 BN 定）；多久问一次、怎么判新作品 / 开播 / 下播；把图下下来交字节；报资料更新；自己内存里的基线。
   - **拓展看见什么就报什么，推不推由 BN 按开关判** —— 与 B 站今天同一条规矩（引擎照样检测每个 UP，统计口径是「发了多少」，开关只决定推不推）。**轮询间隔归拓展**，它才知道那个平台的风控松紧；要让主人调就放进它的设置项。

2. 🔴 **一条规则管两边：拓展交出 / 拿到的永远是平台中立的纯数据。** BN 的内部形状满足这条，就直接当契约；不满足，就隔一张表。
   - 推送侧满足（`NotificationPayload` / `Inbound*` / `PlatformAdapter` 本就为多平台设计，没有 B 站味、没有 VNode），所以 ADR-0012 决策 31「交内部形状」原样成立，**不另加中间表**。
   - 订阅与出图侧不满足（B 站口味 + VNode），所以隔一张表（决策 4）。表还多挡一样东西：B 站卡片的每次内部调整（比如 09-18 把视频拆成五块）不会传到拓展身上。

3. **BN 内部一处不改名。** 皮肤字段表、特性键、`DynamicNode` 都保持 B 站口味 —— 叫 bilibili-notify，就是以 B 站为主，别的平台去适应它。中途提过的「另定一张新字段表 + 旧名当别名」「字段分通用层 / 平台层」都已撤回（见「明确不做」）。

### 订阅事件（中间那张表）

4. **拓展报的是「订阅事件」（`SubscriptionEvent`）**，种类只有 `post / liveStart / liveEnd`，内容只放通用的东西：作者、时间、正文、图片、视频（封面 / 标题 / 时长 / 简介）、互动数、链接；直播的标题、封面、人数、状态。**BN 负责映射**：`post → dynamic`、`liveStart → live`、`liveEnd → liveEnd`；由 BN 自己造 `DynamicNode`（VNode 在 BN 这边造）与直播卡的输入，跑从动态引擎抽出来的**同一段装配**，再走同一条推送链。
   - 字段清单施工时边做边定，规矩是**只收通用的**；哪个平台缺一样东西，就加进这张表，BN 发一版。**拓展不能自己声明字段**（第一版）。

5. **能力声明**：清单里写这个源会报哪几种事件，配置弹层只列这几种。B 站独有的（上舰 / SC / 特别弹幕 / 特别关注进场，以及词云、直播总结）就是只有 B 站报的能力。**第一版不开源专属特性**（抖音的礼物、粉丝团要接直播间 WebSocket + protobuf，而且又是一次契约加宽）。界面叫法可按平台（`postNoun`，抖音叫「作品」，不给就叫「动态」）。

6. **图交字节。** 拓展发现新作品时自己下图，连同事件交给 BN。Referer、cookie、签名链接、过期这些平台门道全留在拓展里；**SSRF 白名单不动**。拓展本来就在 BN 进程里跑，让它下载不改变信任关系。代价是事件带着字节进内存，九宫格约两三 MB。

7. **按外部 id 报。** 拓展报「`sec_uid` 为 X 的人发了作品」，BN 找出这个拓展名下所有指向 X 的订阅逐条分发；资料更新（名字 / 头像 / 粉丝数）同样报，BN 存进本来就按订阅 `id` 存的运行时表。

8. **持久状态那格这次不开**（修订 ADR-0012 决策 14 的时间表）。B 站自己就没存游标 —— 动态游标只在内存、开机设成「现在」、停机期间的不补推。抖音照做：开机第一轮只记基线不推，之后出现新 id 才推。行为与 B 站对齐，主人不会碰到「B 站不补、抖音补」的不对称。真要「停机期间也补推」时再开。

### 订阅的身份与存储

9. 🔴 **分两支，B 站那支一个字不动。**
   - 拓展订阅是新的一支 `{ kind: "extension", extensionId, 外部 id }`，**不带 `uid`** —— 编译器会把约 200 处 `sub.uid` 全列出来逐个分流，「遍历所有订阅去 B 站拉资料」这类循环不会拿抖音的 id 去问 B 站。
   - 运行期键用订阅自己的 uuid：与纯数字的 uid 永不相撞、当文件名安全。外部 id BN 不解读，原样交给拓展。
   - **另存一个文件。** 旧载荷读不到它，照常开机；再升回来抖音订阅都在。
   - `extensionId` **由 BN 填**（请求来自哪个拓展的解析门），不由拓展报 —— 同 ADR-0012 决策 28：归属是宿主的判断。一个拓展就是一个平台；哪天一个包要出两个平台，再加一格子键。
   - 推送历史每行加一格可选的平台字段，没有就是 B 站；订阅删了也看得出是哪个平台的。
   - 字段名避开裸词 `source`（拓展市场占了）。

10. **平台选择只在至少一个订阅源拓展在跑时出现**，否则新建订阅与今天一模一样。拓展停用 / 卸载后，它名下的订阅**保留**：置灰、写明「××拓展没开」（没装时拿不到名字就写拓展 id）、不轮询不推送，开回来自动恢复；只有主人手删才删。卸载确认框写明「有 N 条订阅会保留（暂停）」。理由同 ADR-0012 决策 21：认不出就静默丢，主人配好的东西会一声不吭地没了。

11. **新建订阅**：选了平台，输入框里的字原样交给那个拓展的解析门（`GET /api/ext/:id/lookup?q=`，走面板鉴权），拓展返回候选 `{ id, 名字, 头像, 粉丝 }`，之后是同一个配置弹层。**拓展读自己名下的订阅**走现读快照 + 变更通知（同 ADR-0012 决策 30），全部给、带 `enabled`，停用的由它自己跳过。

12. **第一版管到哪**：推送整条链 + 订阅列表那一行（头像 / 名字 / 粉丝）+ 首页的在播状态。**不含**统计页 / 粉丝曲线 / 锐评、AI 工具查订阅、卡片页预览、B 站专属过滤（屏蔽转发 / 专栏 / 图文 / 视频）、特别关注。

### 卡片

13. **拓展自带一套卡片皮肤**（纯数据，不是代码）：包里一个 `card-skin/` 目录，装包时过皮肤那道清洗；在皮肤库里是只读的内置皮肤、标着「来自 ××」，随拓展升级更新，卸载即消失（主人复制出去的副本留着）。它是这个平台的默认皮肤。

14. **卡片设置多一格「平台 → 皮肤」**（键：`bilibili` / 拓展 id）。选择链：**单 UP > 平台 > 默认**；任何平台都能切回通用默认皮（现在 B 站那套）。拓展的皮肤用的就是现有的皮肤字段表 —— 那本来就是只增不删的公开契约；B 站独有的字段对别的平台是空的，碰到的块由 `showIf` 藏掉。

### 清单 v2

15. **只有一个文件 `extension.json`，不另开 schema 文件。** 表单声明与清单在**同一时刻**读（import 之前）、带**同一份签名**、过**同一道校验**、出错同一个口径；拆开的话白名单 / 摘要 / 装包闸 / 装载器都要多认一个文件，还多出「清单好的、表单文件坏了」这种半个拓展的状态（ADR-0012 决策 41 说过它最难查）。一个口的声明（外观 / 能力 / 皮肤 / 配置项）集中在一段。

16. **按层分段，静态声明全住清单，代码只剩行为与 zod 校验。**
    ```jsonc
    {
      "$schema": "…",                    // 可选:编辑器补全,由 zod 生成,不是手写的第三份
      "id": "douyin", "name": "抖音订阅", "description": "…", "version": "0.1.0", "icon": "<svg…>",
      "apiVersion": 2,
      "settings": { "fields": [ { "key": "cookie", "type": "string", "label": "Cookie", "required": true, "secret": true, "multiline": true } ] },
      "actions": { "login.start": { "label": "扫码登录" } },
      "contributes": {
        "subscription": {
          "display": { "label": "抖音", "shortLabel": "抖", "color": "#…", "postNoun": "作品" },
          "events": ["post", "liveStart", "liveEnd"],
          "cardSkin": "card-skin"
        }
      }
    }
    ```
    推送源那段是 `"push": { "display": {…}, "connection": { "fields": [] } }`。
    - **`provides` 去掉**，由 `contributes` 的键推出来；BN 核对「注册了的口 ⊆ `contributes`」，补上今天「声明订阅却去注册推送」没人拦的缝。以后开新口 = `contributes` 多一个键。
    - 同一种东西只有一个形状：表单永远是 `{ fields: [...] }`，一个口在界面上的样子永远叫 `display`。
    - 包内路径一律相对拓展根、不带 `./`、不许 `..`，指到的东西必须在拆包白名单里（`card-skin/` 因此进白名单）。

17. **表单项按数据类型分，不按控件分**：`key / type / label / description / required / default`，`type` 为 `string`（`placeholder` `secret` `multiline` `monospace` `generate`）、`number`（`min` `max` `step` `unit`）、`boolean`、`enum`（`options`，选项可带图标）、`list`（对象数组，见决策 21）。与 zod 一一对应，所以**加载时对表不只对键，连类型与默认值一起对**，两份声明漂不开。
    - 改名：`code→key`、`kind→type`（`text→string`、`toggle→boolean`、`select→enum`）、`hint→description`、`suffix→unit`、`mono→monospace`、`tint→color`；类型 `ExtensionConfigField→ExtensionField`、`ExtensionDescriptor→ExtensionDisplay`。桥是唯一现存用户，一起改。
    - 叫法：`settings.fields` 是「**设置项**」，`push.connection.fields` 是「**连接配置项**」，中间那张表是「**订阅事件**」；「字段表」只留给皮肤字段表。
    - 修订 ADR-0012 决策 19 / 33：表单那份从代码搬进清单，zod 仍在代码。清单文件头「不放要跑一下才知道的东西」那句的归类也跟着改 —— 表单声明是静态数据，从来不属于那一类。
    - **白捡的三样**：没在跑的拓展也读得到密钥声明，备份能精确脱敏（今天是整份抹）；装好还没启用就能填设置（「装好 → 填 cookie → 启用」这个顺序才走得通）；BN 写设置前照声明先校验（今天宿主那格是 `z.unknown()`，写坏了桥读到的是空名单、所有 token 当场失效）。

18. **apiVersion 改成「契约档位」，宿主认一个区间 `[最低, 当前]`**（修订「只比主版本、严格相等」）。这次升到 2，同时认 1（老格式，声明写在代码里 —— 退路）和 2（本份清单）。已发出的 BN 只认 1，看到 2 就拒装、市场标「不兼容」—— 用的是它们本来就会查的那一格。不兼容的改动 = 抬「最低」并删掉对应的退路。宿主**先单读 `apiVersion`，再按那一档的格式校验其余**，以后清单格式再变，旧宿主说的是「版本不合」而不是「清单读不了」。

### 拓展的界面

19. 🔴 **全部由主程序照声明来画**，仍是 ADR-0012 的「数据描述 + 主程序渲染」。简单拓展只交设置项；复杂的用下面三件套拼。**桥也照这套迁过去**，手写的那一页退役，长相保持今天这样。

20. **状态区改成「视图」**：`publishStatus` 不再交任意 JSON，交一组**封闭的积木** —— 状态徽标、键值、表格（列：文本 / 等宽 / 图标 / 三态）、提示条（提示 / 警告 / 错误）、可复制的值（BN 替它算的值，比如对外地址）、二维码、按钮、`qrLogin`。积木能挂在整页，也能挂在列表的某一项上（桥「一个接入一张卡、卡里带状态与 bot」就这么拼）。**派生逻辑由拓展算好交来**（桥的四态、「对不上」），BN 不发明表达式语言。

21. **设置项扩档**：`list`（对象数组：每项一张卡、新建弹窗、删除确认）；`string` 可 `generate`（面板生成、新建时明文显示一次、之后遮住 / 可复制 / 可重新生成）；`enum` 选项可带图标（桥那两个 logo 从 web 搬回拓展）。

22. **按钮两种**：调拓展的（清单 `actions` 声明、代码 `ctx.onAction` 注册、`POST /api/ext/:id/actions/:name`）与让 BN 改一格设置的（桥的「改成 ×」）。设置的写路径仍只有 BN 一条。

23. **扫码登录 = `qrLogin` 积木 + 动作。** 六态（空闲 / 出码 / 等待确认 / 完成 / 过期 / 出错），BN 用画自己 B 站登录的**同一张二维码卡**来画，所以任何拓展的扫码都与 BN 自己的长一样。推送式：拓展在服务端轮询平台、每次变化 `statusChanged()`，浏览器不轮询（B 站那条就是这么做的）。
    - 🔴 **动作只走 `/api/…`，吃面板会话鉴权；绝不走 `/ext/<id>`**（ADR-0012 决策 36 / 38 刻意放在鉴权外）—— 否则任何够得着 BN 的人都能发起登录、用自己的手机扫，BN 就替对方存下了账号；二维码也只经有鉴权的 status 口送到面板。
    - 失败的真实原因照实写进消息。
    - **凭据要一格 `ctx.secrets`**（master key 加密、备份脱敏、卸载清掉）：设置只有面板能写，cookie 会轮换要拓展自己回写，设置又是明文。**这里只定形状，等第一个真要扫码的源再开**；抖音第一版粘 cookie。

### 界面的细节（09-22 照设计稿补定）

拷问时只定了积木的名目。动工前把桥页逐块盘了一遍（约 1172 行），画成设计稿、再逐项拍板 —— 下面这些都是看着稿子定的。

24. **迁完的样子 = 版式、交互、状态都照今天，文案允许变。** 每一块归到三处之一：**清单**声明的、**视图**交来的、**BN** 自己画的。桥专属的整段话要么由视图原样交来，要么由列表在清单里声明的几句提供；只有桥才用的花活换成通用积木。真会变的只有五处：重新生成的确认改成通用说法；没跑起来时卡上写「状态未知」（面板不再替拓展猜）；删除拓展的确认去掉只写给桥的那句括号；头卡和别的拓展一样显示版本号；**停用的接入不再挂「没连上」那段排错说明**（那段写的是 401，而停用的 token 握手收到的是 503、桥会退避重连 —— 今天就是错的，迁移时改对）。**不走「一字不差」**：照着一个例子把每句话都开成槽位，等于给以后所有拓展背上桥的形状，而契约的宽度收不回来。

25. **放在哪。** 页级积木挂在**头卡正文**（桥的「BN 地址」行、抖音的键值与提示都在这儿）；「配置」页签给**任何**有设置项或有视图的拓展（今天只认 `id === "bridge"`）；拓展列表页那一行由视图的 `summary` 交（今天那句「N 个 bot 在线」是面板里专为桥写的）。

26. **视图的形状**：`{ summary?, page?: 积木[], items?: { <列表设置项的 key>: { <项 id>: { status?, pill?, subtitle?, buttons?, lead?, blocks? } } } }`。卡里的积木分两段：`lead` 画在 BN 画的字段行（token 行这种）上面，`blocks` 画在下面 —— 桥今天就是「对不上」的提示在 token 行上、bot 表在下。`status` 是 `{ tone: ok | warn | error | off, text }`，`tone` 同时决定卡角那团颜色；**停用的项由 BN 盖成「已停用」**，拓展报什么都不算。

27. **积木**：`keyValue`；`table`（列四种：icon、text（可两行、可定宽）、mono、tristate）；`notice`（info / warn / error，可带一颗按钮）；`copy`；`qr`；按钮两种 —— `action`（调拓展，决策 22）与 `set`（让 BN 改**这一项**的一格设置，**只挂在列表项上**）。页上一出现三态格，BN 就在列表头挂一次图例（它不是装饰：三个记号里两个是空心圈，不说明就只能猜）。`qrLogin` 在词表里**占位不实现**，与 `ctx.secrets` 同一刻开（决策 23）。

28. **富文本只有五种片段**：字符串、`{ b }`、`{ mono }`、`{ time, suffix }`（浏览器按相对时间画 —— 服务端算好的「12 分钟前」发到面板就冻住了）、`{ host: "extensionUrl" }`（浏览器现算 `ws(s)://<地址栏的 host>/ext/<id>` —— 服务端不知道外面经哪个地址访问它，而那正是桥那台机器要填的）。没有表达式、没有 HTML。

29. **列表设置项自己声明**：`title`（哪一格当卡片标题）、`mark`（哪个枚举的选中项图标当方块）、`toggle`（哪一格布尔画成「停用 / 启用」）、`itemLabel`（「接入」）、`description`（空态与新建弹窗里那句）、`newItemCopy`（新建弹窗底部要成对复制的几样：host 值与本项的某一格 —— ADR-0009 决策 21「token 与地址成对交出去」）、`removeWarning`（删除确认里「删了会怎样」那句 —— 删一条接入会让借来的 bot 建的连接一起发不出去，这是安全提示，通用说法说不出来）。**项的 `id` 由 BN 生成（UUID）、藏起来、不许改**；项里的字段不许叫 `id`；拓展那份 zod 要带它，对表时这一格免声明。桥今天存的形状本来就是这样。

30. **设置项怎么画**：
    - `string`：输入框；`multiline` 换多行；`monospace` 用等宽字。`secret` 只露头尾各四位（八位及以下整段打点），按「换一份」才重填。`generate` 只读、带「重新生成」，格式由 BN 定为 32 位小写十六进制；新建时明文显示一次，之后只露头尾；有值时重新生成要确认，空值（脱敏备份恢复回来就是这样）直接生成并给一句红字提示。
    - `number`：输入框 + `unit`；`boolean`：开关。
    - `enum`：选项带图标 → 选项卡片（桥的「哪一种桥」）；不带 → 分段按钮。

31. **平台图标由拓展交，BN 不替它查。** `table` 的 icon 格只有两级：拓展给的图 → 两个字母；BN 不再拿自己的平台表去补（那张表只收 BN 直连的平台，桥借来的 telegram、discord 今天就因此只剩两个字母）。桥自己带一张常见平台的小表，插件报了图标用插件的，没报用这张表。推送目标页上借来的 bot 长什么样，同一条原则，不在这次迁移里。

    **图标一律是图片 data URL**（`png` / `jpeg` / `webp` / `svg+xml`，大小封顶，与桥协议 §5.2 的 bot 图标同一条），枚举选项与 `table` 的 icon 格都用 `<img>` 画，**不过 SVG 白名单** —— `<img>` 里的 SVG 不跑脚本、拉不进外部资源，而白名单每宽一格都是把外来标记塞进页面。修订施工 ① 里「选项图标过清单图标那道门」。只有拓展自己那枚图标仍是内联 SVG（要吃 `currentColor` 在渐变方块上变白）。

32. **拓展关着时，设置照样能改**（决策 17「装好 → 填 → 启用」落到界面上）：卡照常画、照常增删改，没有状态、统一写「拓展关着」，顶上一条提示。设置只是存着的数据，关着时改了什么都不会发生，打开时拓展才读。今天桥「关着就压暗成一行一条、不给按钮」随之退役。**没跑起来**时同样照常能改，状态写「状态未知」。

33. **截图比对的口径**：拿迁移前后的桥页逐块比，差别只许是决策 24 列出的那五处，外加决策 31 带来的 bot 图标变化；多出任何一处，要么补回去，要么回来问。

    比对（09-22）多出的一类回来问过，**定为照留**：拓展交不出视图（关着 / 没跑起来）时，**视图交来的块一律不画** —— 头卡的「BN 地址」行，卡上的药丸、副标题与排错提示都在此列。这些话归拓展说，拓展不在场时 BN 替它编就是越界，决策 24「面板不再替拓展猜」的同一条。新建接入真要用的地址不受影响：它在清单的 `newItemCopy` 里，配对框不靠视图。「没跑起来」那句提示随之挪到「配置」页签顶上，和「拓展关着」那条同一处。

### 施工顺序

每一步都能保持绿：① 清单 v2 + apiVersion 区间（桥此时仍是老格式，走退路；09-22 完成）→ ② 先拍桥页迁移前的截图 → 设置项表单与写入校验 → 视图积木 + 动作 → 桥迁过去 → 截图比对（09-22 完成）→ ③ 订阅身份分支 + 另存文件 + 订阅源注册表 + 解析门 + 平台选择 → ④ 订阅事件 → 抽出装配 → 「给 node 就出卡」入口 → 接进推送链 → ⑤ 自带皮肤 + 「平台 → 皮肤」→ ⑥ 假源 + e2e → ⑦ 文档。

## 明确不做

- **运行时把拓展的前端组件加载进面板**（共享宿主的 React 与 `packages/ui` 单例）。宿主的每个导出都成了拓展的 ABI，而拓展与本体**分开发版**（拓展化的出发点）、本体又会**应用内自主升级** —— 版本一错开，拓展页面就可能静默白屏。**永远不走。**
- **沙箱 iframe 页面**（拓展自带打包好的静态页，嵌进不带 `allow-same-origin` 的 iframe，请求经 postMessage 由面板代发、路径钉死在它自己的前缀下）：**这次不建，留作后路** —— 真遇到决策 19–23 表达不了的，下一步是它。代价是风格要拓展自己维护、面板要做 token 签发 / 资源改写 / 代理那一整套。
- **拓展直接交 `DynamicNode`**（和推送一致）：得先把它改成纯数据（正文分段、图廊成列表、附加内容成 B 站那几种附加卡的数据联合），改完它就成了契约，B 站侧每次调整都要拓展跟着发版。
- **拓展伪造一份 B 站 API 的原始 JSON** 去喂现有引擎：等于把 B 站的接口形状当成我们的契约；链接、按 `mid` 认订阅、取图白名单这些特例照样要改。
- **拓展自带卡片模版代码**：卡片会落在皮肤系统之外，编辑器、女仆做皮肤、单 UP 选皮肤全管不到；渲染器内部（Vue / UnoCSS / 截图管线）会成为能开出的最宽的一口。
- **另定一张新的皮肤字段表、旧名当隐藏别名**，以及**字段分通用层 / 平台层**：拷问中途定过，随决策 3 撤回。
- **内部特性键换中立名、旧名留别名**：它不是主人手写的东西，是 BN 自己落盘的标识（订阅路由、全局开关、历史三处）；换名只换来三处永远要维护的双向翻译。中立名只在契约层（决策 4）。
- **把所有订阅统一成 `(来源, 来源 id)`**（ADR-0012 原计划）：B 站的粉丝 / 统计文件要改名、约 80 个文件的键全换，且旧载荷回退照样会砖。
- **推送侧另加一张中间表**：会复制出一份一模一样的类型再加一层翻译，正是 ADR-0012 决策 31 否掉的东西。
- **表单声明单开一个文件**：见决策 15。
- **`minHostVersion`（BN 版本号）**：已发出的 BN 不认识这一格、静默忽略，照装不误然后炸在 activate；它还把拓展绑到 BN 的发版号上（预发布号算不算都要判）。
- **拓展声明自己的平台字段**、**源专属特性**：第一版不开，见决策 4 / 5。
- **按来源放宽取图白名单**、**ctx 给一个「帮我取图」的钩子**：前者逼 BN 去学每个平台的门道（哪天要 cookie 才取得到就得再加格），后者多一次来回，且出卡那一刻拓展可能已被停用。
- **在声明式界面里做表达式语言**：派生的东西由拓展算好交来。

## 后果

- **认下的活**：从动态引擎里抽出装配段、写一个订阅事件 → 内部形状的映射、桥那一页（约 1172 行）改成声明式、apiVersion 1 那条退路要一直带到最低档抬上去。
- **已发出的 BN 手动上传一个 v2 包**会说「清单读不了」而不是「版本不合」（它们还不会先单读 `apiVersion`）；走市场那条路按 `apiVersion` 标不兼容，不受影响。
- **另存文件的代价**：退回旧载荷时看不见拓展订阅，旧载荷做的备份也不含它们。
- **积木只随 BN 发版增长**：缺一种积木就得等 BN 加。
- **顺手补上的三个洞**：`provides` 没人核对、设置写入不校验（`z.unknown()`）、纯订阅源拓展声明不了密钥。
- 🔴 **第三方拓展的处境**（ADR-0013 让主人能自己加第三方源，BN 不审核、只弹两道风险提示）：
  - **同进程、没有沙箱。** 只从 `@bilibili-notify/extension` 进、副作用经 ctx 这些规矩只在本仓有守卫；第三方的包伸手就能读 `<dataDir>/secrets/`（B 站登录态、master key）。**ADR-0012 决策 1「代码是我们自己的，这颗雷才不存在」的前提，对第三方源不成立** —— 今天只靠那两道提示兜着。这件事与本次开口无关，今天就存在。
  - **开发者的局限**：拿不到 SDK（`@bilibili-notify/extension` 是 private、没发 npm，也没有作者指南）；界面只能用 BN 的积木；数据只有统一表里那些；包只能是一个自包含的 `index.mjs`（带不了 wasm、原生模块、多个 JS 文件）；没有自己的存储；devtools 那套开发工具只在本仓的开发版里；契约档位跟着 BN 发版走。

## 仍未决

- **给第三方补三样**（已定做，先当 TODO）：`@bilibili-notify/extension` 发 npm（只含类型与零依赖的 wire，契约档位就是它的主版本）、一份拓展作者指南、一个「从本地目录装、改完自动重载」的开发入口。都是往上加的，不改契约。
- **`ctx.secrets` 什么时候开**：等第一个真要扫码的源。
- **进程隔离**：第三方生态真起来之前不做（每一格 ctx 都要跨进程）。
