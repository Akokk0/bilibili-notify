# ADR-0047 抖音首版接入订阅、群聊作品解析和系统扫码登录

- **状态**　2026-11-12 主人选定「常用操作和扫码登录都对齐」。这是首版范围决定，接口实现与真实账号验收在后续切片。
- **影响面**　订阅源拓展 SDK、宿主群聊链接解析、系统账号页、抖音拓展。修订 [ADR-0019](0019-subscription-source-opening.md) 首版粘贴 Cookie 的安排，落实 [ADR-0021](0021-neutral-core.md) 留给第二个来源的链接解析与账号接入决定。

## 背景

B 站用户可以在系统账号页扫码、在订阅页按主页或昵称加人、接收作品和三种直播通知，也可以在开了解析的群里贴视频链接。宿主已有群聊解析器和账号页，已发布的拓展 SDK 尚未向作者开放这两个入口。抖音是两者的首个拓展使用者。[调研与对照](../1.0/douyin-source-research.md)

## 决策

1. 抖音首版支持通过作者主页、主页分享短链、精确抖音号和昵称候选添加订阅。视频、图文以及开播／直播／下播走宿主已有的卡片、目标、历史和统计。抖音按可确认的上游状态上报，轮询受阻时保留已有资料与直播状态。
2. 给拓展开放群聊作品链接解析。宿主依据清单中的网址范围分派单条链接，负责逐群开关、回复形式、额度、冷却与停用时撤销。抖音负责解析视频、图文及分享短链；未订阅作者也能出卡。
3. 抖音首版从「系统 → 账号」扫码登录，与 B 站共用账号列表和扫码界面。会话和凭据按来源隔离。扫码后被要求二次验证时引导账号持有人完成，只有取得有效登录凭据才显示已登录。账号切换、退出、重启恢复和凭据失效沿宿主账号语义处理。

## 明确不做

手工提取 Cookie 不作为登录前提。群聊解析沿用已有消息入口；拓展专属私聊指令和 AI 工具继续等具体使用者。礼物、粉丝团等直播互动与真实素材编辑器预览留在原范围之外。

## 后果

6-07 落实链接解析，6-07a 单独接通拓展登录、抖音扫码和二次验证，6-08／6-09 接资料、作品与直播。系统页只在原账号行及扫码流程中补必要交互。公开 SDK 的兼容声明、旧宿主识别及作者文档随实现一起验收，已发布的包仍以其实际能力为准。[第六期计划](../1.0/phase-6-plan.md)
