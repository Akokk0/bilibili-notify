# ADR-0044：由BN管理拓展源码开发

- **状态**：2026-11-11主人要求采用宿主驱动的源码开发流程，生产才打包。
- **影响面**：源码开发版装载、创建器、作者指引。
- **修订**：[ADR-0012](0012-extensions.md)决策35对开发源码入口的限制。

## 决策

1. 开发者只启动BN。在拓展页指定源码工程并启用，由BN读取`src/index.ts`、监听实际依赖并局部重载；拓展不启动独立进程，也不启动或发现宿主。
2. create-bn-ext生成独立工程，去掉拓展自己的dev/start命令。build、ZIP与Actions发行只在生产打包时使用。BN的dev:apps也不再启动拓展打包监听。
3. 开发加载由devtools中的Vite+模块加载器承担：运行时转换源码、维护依赖图和重载，不写dist、不读取工程的打包配置、不另开HTTP服务。先核对清单身份与兼容性，读取模块定义和schema；仅启用后调用activate，模块顶层仍禁止副作用。
4. 装载器继续只扫描数据根`extensions/<id>`。显式挂载把源码工程链接到该根，宿主内部注入受管理的源码入口解析；不增加自动扫描根、装载优先级、清单entry字段或SDK能力。生产没有源码解析器，仍只加载固定index.mjs。
5. 多工程各自监听。源码或子依赖加载、schema与清单校验通过后，再沿原装载队列收掉旧实例并启用新版；校验失败保留正在运行的旧实例。停用项不自动启用，解除和退出关闭监听、模块加载器及运行上下文。
6. 开发场景与拓展页共用同一源码挂载服务。普通构建继续剔除整个devtools与源码加载依赖；生产装包、签名、兼容性和缓存语义保持。
7. 拓展页挂载弹窗提供宿主目录选择：从BN工作区起步，可进入子目录、返回上级及回工作区；选择仅回填路径，原挂载动作仍单独确认。目录浏览接口沿`/api/dev`鉴权与源码开发门，只列目录和清单存在提示，不读取文件内容、不执行源码或改变挂载。取消保留路径与监听草稿。

## 验证

沿主人已批准的拓展页、挂载HTTP与真实装载器、实际npm创建器入口先红后绿，覆盖无dist直接加载、子依赖变化、多拓展、失败保留、开关与收尾。内置浏览器确认只启动BN即可联调，生产bundle确认没有源码开发能力。

参考：[Koishi启动与热替换](https://koishi.chat/en-US/guide/develop/script)、[Vite模块加载API](https://vite.dev/guide/api-javascript.html)。实现以本仓已安装的Vite+版本为准。
