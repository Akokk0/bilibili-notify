# ADR-0042：拓展脚手架自带vp工程基建与Actions

- **状态**：2026-11-10主人要求创建器将工程基建配齐；实现随第6期6-04/6-05。
- **影响面**：创建器生成的新工程、本地检查与Git hooks、GitHub Actions模板。
- **延伸**：[SDK与创建器的npm分发](0040-extension-sdk-npm.md)、[固定Release索引](0041-extension-repository-source.md)。

## 背景

原始Issue #56和第6期计划已要求创建器带上发布用的GitHub Actions，但只写“可构建、可打包”不足以交付完整工程。作者还需要自己补检查脚本、提交钩子和CI，生成后也无法验证发布链路是否就绪。

## 决策

1. 创建器默认生成完整工程基建，安装依赖后即可检查、测试、构建和打包。Node、包管理器与工具版本、锁文件及所需配置一并准备。
2. 新工程统一经vp管理命令，lint/format采用vp原生能力；提供格式修复、只检查格式、lint、类型检查、测试、构建和拓展打包的明确入口。BN主仓继续沿其现有工具规范。
3. 本地Git hooks默认配好：pre-commit经vp检查暂存文件的lint/format，commit-msg经vp执行commitlint，采用Conventional Commits。hook配置作用于生成工程自己的Git仓库。
4. GitHub Actions默认包含PR/分支检查与版本tag发布流程。CI复验检查、类型、测试和构建；提交信息检查也有CI覆盖。本地hooks与CI使用同一组工具配置，检查失败时发布停止。
5. 版本tag通过门禁及清单版本核对后，自动构建自包含拓展、打ZIP、计算sha256和大小、创建对应GitHub Release并上传附件，再更新固定Release上的完整市场索引。包先上传，索引随后更新；提供只构建/校验的dry-run入口。
6. 生成工程携带配置和所需脚本，或使用已分发的开发工具，能够在独立第三方仓库运行。README说明首次安装、本地开发、检查、版本/tag、dry-run和GitHub发布权限配置。发布作业按需声明仓库写权限，普通检查保持读取权限。

2026-11-11主人补充要求提供agent指引和skill：SDK随包提供契约指引与开发skill；创建器生成AGENTS.md和CLAUDE.md，并为Codex/Claude提供各自的发现入口。skill正文从SDK同一来源分发，不另外复制维护契约；开发资料可在仓外读取。

## 明确不做

- 不只生成一份示例源码，再要求作者手工补齐检查、hooks与Actions。
- 不依赖第三方仓库中不存在的BN主仓脚本、私有包或机器路径。
- 不把拓展的GitHub Release自动发布混同于SDK/创建器自身的npm发行；后者沿ADR-0040另行安排。
- 不将本地模板验证当作真实GitHub发布已经验收。

## 后果

创建器和发布模板需要以“生成后的独立工程”验收，覆盖检查失败、提交钩子拒绝、版本不匹配和dry-run等实际行为。版本固定与模板升级增加维护工作，但作者获得的是可以持续开发与发布的工程。
