# ADR-0028：中段模块 —— 作品文字的拼法、出图字节门、模板变量、醒目留言与会员卡

- **状态**：2026-09-28 `/grill-me` 拍板（一次一题）。**未施工**。
- **记录方式**：拷问当场落的定案。类型与模板变量表的正本在 [docs/1.0/](../1.0/) 的 data-model；本份只写定了什么、为什么、否了什么。
- **影响面**：`posts/` 的文字组合、过滤、AI 点评的输入；`packages/image` 的五种卡与像素门；模板引擎与皮肤字段；`bilibili/` 的作品映射与直播互动。
- **依赖**：[ADR-0021](0021-neutral-core.md)（中立 `Post` 与会员体系）、[ADR-0014](0014-card-skin.md)（卡片皮肤）。

## 背景

核心模块的审计查出：过滤、AI、出图各自拼作品的文字，口径不一；出卡的字节门要求逐字节一致，而中立化必然改掉一些字节；模板变量 `{guard}`、`{mdn}` 是 B 站的概念；醒目留言的档位与会员卡的文字写死在 B 站的形状里。

## 决策

1. **作品的文字只有一种拼法**：`text` 只放正文，标题、视频标题、转发的原作品各有位置。核心 `posts/` 里唯一一个取段函数给所有来源用：过滤时无前缀换行拼接，AI 用「标题：」「视频标题：」「（转发自 X：…）」。屏蔽图集与视频只看最外层，转发归「屏蔽转发」管。B 站：UP 自己的视频进 `post.video`，番剧、合集、课程进附件的视频卡。
    - 理由：同一条作品，过滤看到的、AI 看到的、卡上画的是同一份字；这个函数进守卫 4 的点名表，对拍逐字比。
2. **出图字节门的裁决**：中立的形状优先。
    - 能用通用手段表达的照样逐字节一致（比如把链接图标的颜色烤进图库里的图）。
    - 需要通用能力的就加通用能力（比如卡片行 `{ text, icon?: ImageRef }`），不许加 B 站专属的枚举。
    - B 站纯装饰去掉。
    - 剩下的差异进「批准的像素差清单」，预批三类：平台叫法中立化、内联 SVG 换成图库图的残差、B 站纯装饰去掉；每条写样例、变化、类别与依据。清单外的差异由守卫 10 判红，更新快照必须同时补清单。
    - 守卫 10 扩到五种卡（直播、醒目留言、会员、词云、榜单）。
3. **模板变量**：`{guard}` → `{tier}`（会员事件的档名）；`{mdn}` → `{fanclub}`，资料加中立的可选字段 `fanClubName?`；两者进模板变量可满足性守卫。弹幕总结的其余缩写不动。迁移改写主人的文案，出来的字不变。
    - 理由：粉丝牌是 B 站的概念，别的平台叫粉丝团或者没有。
    - 作品叫法的变量叫 `{postNoun}`（原定 `{noun}`），与提示词变量同名（ADR-0030 决策 3）。默认文案「{name}发布了一条{postNoun}」保留「一条」：只订 B 站的主人收到的推送一字不差，「条」配作品类的名词（动态、作品、视频、笔记）都通顺。
4. **醒目留言与会员卡**：`SuperchatEvent` 加可选 `tier { rank, durationSec? }`，由来源按平台规矩算，卡按档取色（默认配色照今天六档，皮肤可按档换色），有留言时长就显示；金额按币种用 `Intl.NumberFormat`（人民币整数仍写「¥30」）；`MembershipTier` 加可选 `announcement`（宣告语，可用 `{viewer}`、`{name}`、`{tier}`），皮肤字段 `membership.text` 改名 `membership.announcement`，面板上叫「宣告语」。
   🔗 **2026-10-05**（㉓ 开片，主人拍板）：
   - 上面那个皮肤字段的原名写错了，代码里是 `guard.text`。醒目留言卡与会员卡两组字段随 ㉓ 一起改到最终名字（对照表在 construction-plan「㉓ 开片」）。
   - 「皮肤可按档换色」分两半：出图器按档取色、皮肤读得到档色变量，这一半随 ㉓；皮肤自己定每一档的色要给皮肤契约加挂点，归 ㉔。
   - 金额固定中文环境、关掉千分位（「¥2000」不写成「¥2,000」），本意是老用户看到的字不变。
   - 留言时长走 `formatDuration`，写「1分」「30分」，不为醒目留言卡另写一种排版。
   - 上舰文案的占位符（`{viewer}` / `{name}` / `{tier}`）与 `-key` 改写随 ㉓ 先做，其余直播文案仍等 3b。

## 明确不做

- **各模块自己拼作品的文字**：原因见决策 1。
- **为保字节一致给中立形状加 B 站专属枚举**：那等于把 B 站的形状请回核心。
- **字节门一刀切放宽**：只批准清单里的差异，清单外的照样判红。
- **默认文案改成「发布了新{postNoun}」**：换哪个来源都通顺，但只订 B 站的主人收到的推送会变。
- **推送文案与提示词各用一个变量名**：同一个概念两个名字。

## 后果

- 卡片快照会有一批批准过的像素差，每条都记在清单里。
- 主人自己写的文案里 `{guard}`、`{mdn}` 由迁移改写。
