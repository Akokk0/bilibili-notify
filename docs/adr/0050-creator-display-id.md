# ADR-0050 创作者展示账号与来源身份分开

- **状态**：2026-11-14 主人同意开始 SDK 改进，先落实展示账号与兼容诊断。
- **影响面**：来源 SDK、资料缓存、来源描述符、搜人候选及订阅界面。
- **依赖**：[ADR-0027](0027-monitoring-stats-and-descriptor-driven-panel.md) 的来源叫法与 [ADR-0047](0047-douyin-source-parity.md) 的第二来源接入。

## 背景

来源的稳定身份可能是很长的内部标识，不适合作为用户辨认账号的首选；公开账号又可能改变。抖音目前将公开账号拼进简介，搜索与订阅资料不能一致呈现，也不能随资料刷新独立更新。

## 决策

1. 来源资料增加可选 `displayId`，只用于展示。省略沿用旧资料，空串清除；非空值保留原文，最多256字。搜索候选、新建资料种子、刷新和资料上报走同一字段，持久化在既有资料缓存。
2. 来源描述符增加可选叫法 `displayIdNoun`，随来源译文切换。公共展示函数优先显示可读账号及其叫法；未提供时沿既有身份标签回落。搜索提示同样优先取展示账号叫法。原始身份标签、复制、订阅关联、去重和路由仍使用 `externalId`。
3. 新字段要求拓展契约 API 1、修订号2；原修订号0/1的拓展继续可用。使用新描述符字段的清单必须声明修订号2，宿主按既有版本闸拒绝不兼容拓展。SDK的实际公开版本另按发行流程确定。
4. 开发挂载复用正式安装与发现的兼容说明，区分清单格式错误与契约不支持，保留字段诊断；不把所有失败归为清单无效。

## 明确不做

不以展示账号替换身份，不迁移订阅ID、不重建订阅，不从简介猜账号。没有展示账号的来源无需补字段。此次不引入通用登录状态机、平台签名或统一风控策略，不执行npm发布。

## 后果

资料缓存向后兼容增加可选字段，无需改写旧记录；下一次真实资料刷新后已有订阅可以得到展示账号。新增SDK字段、清单校验、四语叫法与仓外消费需一起验收。
