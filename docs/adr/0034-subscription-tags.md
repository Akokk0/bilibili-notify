# ADR-0034：订阅标签 —— 一份登记表，订阅只记 id

- **状态**：2026-10-02 `/grill-me` 拍板（一次一题，起因是 issue #53「订阅 UP 主的分组能变成标签」）。**未施工**：随 1.0 一起做，0.12.x 不做（主人一度想放进 0.12.1，听完「0.x 改数据格式」的代价后撤了）。
- **记录方式**：拷问当场落的定案。登记表放在哪个文件、读写口与面板长什么样，施工时定；本份只写定了什么、为什么、否了什么。
- **影响面**：订阅 schema、`config/` 下的订阅存储、0.x 迁移、备份、面板的订阅页（筛选、卡片角标、「编辑分组」弹框、订阅详情的「分组」一栏）。
- **依赖**：[ADR-0022](0022-data-generations-and-migration.md)（数据代与 0.x 迁移）、[ADR-0023](0023-neutral-naming.md) 决策 15（命名规矩，词表加了一行）。

## 背景

今天每条订阅自己带一个 `groups: string[]`，没有单独的登记表：面板上的分组列表是从所有订阅里现凑出来的。于是改名要逐条订阅改，没人用的分组自己消失、不能先建好，打错一个字就多出一个分组。编辑入口有两个：卡片菜单里的「编辑分组」弹框是勾选已有的 + 新建，不会打错；订阅详情「基础 → 分组」是自由文本框、按英文逗号拆，错字都从这里来，输中文逗号「A，B」会整串变成一个分组。分组今天只用在订阅页的筛选和卡片角上的那一枚（只显示第一个、空的写「默认」），不参与推送与路由。

## 决策

1. **标签是一份单独的登记表，订阅只记 id**：每个标签有 id 和名字，顺序就是登记表里的顺序；订阅上存 `tagIds: string[]`。改名只改登记表那一处；没有订阅挂着的标签照样留着；删一个标签，所有订阅上的这个 id 一起去掉。名字去掉首尾空白后不许为空、不许重名。面板上凡是给订阅挑标签的地方都是同一个勾选组件（勾已有的 + 就地新建），不再有自由文本框。
   被否的备选：仍存字符串、只把订阅详情的文本框换成勾选组件（不用迁移，但改名要逐条改、空分组留不住的老问题都还在）；在 0.12.1 就做（0.x 没有数据代，降回 0.12.0 不管是自愈回退还是手动降，旧代码读新格式：订阅 schema 剥掉不认识的键、下次保存就丢，沿用 `groups` 存 id 的话旧版会把 uuid 当分组名显示；1.0 的迁移也得同时认两种 0.x 格式）。
2. **叫「标签」，代码里是 `SubscriptionTag`**（订阅上那一格是 `tagIds`），词表加一行。一条订阅能挂好几个，这是标签的语义，不是分组；代码里的 `group` 已经指群（目标的 `scope: "group"`、`InboundGroupMessage`）、图集（`image-group`、`PushImageGroup`）和设置分组（`ConfigGroup`、`FeatureGroup`），再加一层就是一词四义；「分组」又是 B 站关注分组的叫法（接口里叫 `tagid`，`packages/api` 留着两个没人调用的口），哪天要同步关注分组就分不清。光叫 `Tag` 不行：小写的 `tag` 已经是 HTML 标签、日志 tag、加密的 `authTag`。
   被否的备选：沿用「分组」/ `Group`。
3. **迁移把 0.x 的字符串换成标签**：每个去掉首尾空白后非空、互不相同的字符串成一个标签，订阅上的字符串换成对应的 id；顺序照今天订阅页筛选胶囊的排法（按 `zh-Hans-CN` 排序），主人升上来看到的顺序不变。带中文逗号的那种拆不拆、登记表放在哪个文件，施工时定。

## 后果

- 第 2 期多两件：订阅数据模型加 `tagIds` 与标签登记表、0.x 迁移多一条。改了形状以后面板必须同期跟上（筛选、角标按登记表读名字，订阅详情的文本框换成勾选组件），标签的管理界面（改名、删除、排序）随第 4 期。
- 面板文案跟着改：「编辑分组」→「编辑标签」、「未分组」→「无标签」之类，卡片角上的那一枚不再写「默认」。
- 备份带上登记表；恢复时标签按 id 并、撞名的怎么并，施工时定。
