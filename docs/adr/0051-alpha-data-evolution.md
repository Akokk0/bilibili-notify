# ADR-0051：alpha 期间保留数据并按格式迁移

- **状态**：2026-11-15 主人确认，作为第 6 期 6-11 的数据演进规则。
- **依赖**：[ADR-0022](0022-data-generations-and-migration.md) 的数据代、复制迁移、失败恢复及回退隔离。
- **补定**：ADR-0022 的 alpha 之间如何演进数据格式这一未决项；数据代布局和启动器不变。

## 背景

开发期通过迁移修订号重开数据代，只能从 0.x 重新迁入或开空代，alpha 期间新增的订阅、登录、历史和设置因此不会自动保留。公开 alpha 不能继续以这种方式演进数据。

## 决策

1. 首次 alpha 采用当前数据格式 1，冻结 0.x → 格式 1 的迁移基线 53。后续不靠增加这个修订号触发自动重迁。
2. 盘上格式不兼容时增加格式版本，并随实际变化提供上一格式到新格式的迁移。复制到新的 `.partial` 代，完整转换后才原子启用，旧代原样保留。当前没有格式 2，不预造转换器或空登记表。
3. 兼容性以旧版能否完整、安全地读取和继续写入为准。改字段名、含义、目录布局，以及会被旧版严格 schema 拒收的新增字段，都按不兼容处理；可选字段不自动视为兼容。
4. 有本格式的完整数据代时，使用其中序号最大的代，不能被回退期间产生的较高序号旧格式代取代。盘上只有较旧格式代而没有本格式时，必须有真实迁移路径才能升级，不静默从 0.x 重迁或开空代。全新安装仍可开空代。
5. 回退仍使用旧版自己的数据代，再升级读回新版自己的代，两边新增数据不自动合并。半成品不参与选代，失败自愈、手动全新开始、从 0.x 重迁和旧代清理沿既有机制。
6. 备份版本独立判断备份信封兼容性，仍只恢复同版，不与程序版本、数据格式版本或 SDK 契约号绑定。

## 明确不做

- 不以“alpha 可破坏”为由自动丢掉 alpha 期间新增数据。
- 不原地改写旧代，不合并回退前后两代的数据。
- 不为没有真实格式差异的版本造空迁移器。

## 后果

后续每次不兼容的格式变化都必须交付真实转换与失败、回退验收；旧代占用的磁盘由既有手动清理规则管理。0.x 迁移的冻结摘要继续约束格式 1，不再按开发期方式更新修订号和摘要来绕过。

## 仍未决

无。下一次实际格式变化的字段和转换实现随该变更设计。
