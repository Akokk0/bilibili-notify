# ADR-0035：推送目标标出所在连接，下拉统一换成自己的组件

- **状态**：2026-10-02 `/grill-me` 拍板（一次一题，起因是 issue #55「单独选择推送目标的设置增加来源标识」）。**未施工**：随 1.0 第 4 期（面板）做，0.12.x 不做。
- **记录方式**：拷问当场落的定案。组件与函数叫什么、长什么样，施工时定；本份只写定了什么、为什么、否了什么。
- **影响面**：`packages/ui` 的 `TSelect` 与清单、面板里所有列出推送目标的地方、所有下拉框及驱动它们的测试。
- **依赖**：[ADR-0024](0024-push-platform-adapter.md)（1.0 的目标不再带 `platform`，平台经连接查）、[ADR-0023](0023-neutral-naming.md) 决策 15（命名规矩）。

## 背景

面板上用 HTML 画的目标列表（目标页、订阅详情的目标表与加目标按钮、链接预览的逐群表、周报「发送到」的胶囊）都是平台图标 + 目标名；五处原生下拉（系统→主人账号、卡片页预览目标、AI 测试面板、锐评推送、devtools）只有目标名。哪儿都没有连接名，而同一个平台可以有两条连接（两个 QQ 机器人），各自底下都可能有一个叫「家人群」的目标 —— 平台图标一样，分不出来。

## 决策

1. **目标一律标出平台图标 + 所在连接的名字**：目标名后面跟一行小一号、浅色的连接名（「家人群 · NapCat 主号」）。凡是列出目标给人挑或给人看的地方都标，由一个函数从目标与连接表算出来，各处都调它 —— 1.0 的目标没有 `platform` 这一格，平台本来就要经连接查。代码里别叫 Source：词表里核心的 `Source` 只指订阅来源。
   被否的备选：只补平台（下拉里加平台名、胶囊不动）—— 同平台两条连接下的同名目标照样分不清。
2. **面板与 `packages/ui` 里的下拉全部换成自己的组件，不再有原生 `<select>`**（主人定）：`TSelect` 改用 `PopoverShell`（`role="listbox"`）+ `MenuItem` 拼，选项能带图标和一行小字，目标下拉就是它的一个用法，不另做一件。原生的那几样要自己补齐并由测试钉住：上下键与 Home / End 移动、回车或空格选中、Esc 关、打字跳到对应选项、关掉后焦点回到触发器、读屏器能念出展开状态与当前选项；触发器照旧挂 `data-bn="input"`、走 `bg-bn-field` 底，浮层按 `--z-bn-*` 分层表叠。加一条守卫扫面板与 `packages/ui`，见到裸 `<select>` 就红，换完以后不会再长回来。
   被否的备选：原生 `<select>` 按连接用 `optgroup` 分组（组名写平台 + 连接名，键盘、读屏器、手机的系统选择器都是原生的，但下拉里没有图标，跟胶囊和列表长得不一样）；只换目标那五处、别的照旧原生（同一个面板两种下拉）。

## 后果

- 换的面：`TSelect` 本体、免扰时段的整点下拉 `HourSelect`，以及 `Logs`、`SkinEditor`、`RoastPushBox` 三处手写的原生 `<select>`；`TSelect` 的 14 个调用点（9 个文件）接口不变就不用动。9 个测试文件里约 26 处按原生 select 驱动的（10-02 粗数）要改成点开再选。
- 手机上不再弹系统的选择器；键盘与读屏器的行为从此归我们自己维护，坏了没有浏览器兜底，所以要有测试钉住。
- 选项很多时要不要带搜索框、目标下拉按连接分组还是平铺，施工时定。
