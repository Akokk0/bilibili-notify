# ADR-0018：画布画的格子，DOM 里得真有那个盒子

- **状态**：2026-09-20 `/grill-me` 三轮拍板，**未开工**
- **影响面**：`packages/image` 的皮肤渲染器（每块多一层「格子层」）、`apps/web` 的网格画布与预览栏、出厂默认皮肤的字节基准（要重打，像素应当零差）
- **依赖**：ADR-0014 决策 6（12 列网格）、决策 20（画布能拖）、决策 22（预览走 HTML）
- **取代**：ADR-0014 决策 6 里「画布是示意图」的**一半** —— 行列关系仍是画布的语言，但它画的那个矩形从此**恒等于 DOM 里一个真元素**。「叠在真卡上编辑」那条否决仍然成立（见「明确不做」）。

## 背景

主人指着编辑器截图报「画布不能准确反映实际渲染」。查下来：画布与出图**都没算错**，行列坐标两边一字不差。差的是几何，三处：

1. **网格宽度**：画布拿清单里的卡宽当网格宽，而网格实际落在玻璃层上，宽度是外框的内容宽 —— 那圈内边距写在**皮肤 CSS** 里，清单里没有这个字段。
2. **容器被皮肤捏小**：`justify-self` / `align-self` 让容器收到内容尺寸，wrapper 上的 `margin` 让它内缩，而画布按「占满格子」画。出厂皮肤 36 个块里 13 个如此。
3. **行高**：画布行等高，真卡行按内容撑（决策 6 的 🔗 已处理过一半：标了 `heightFromRows` 的块跨行就是真高度）。

根因一句话：**画布照清单算几何，真卡的几何由皮肤 CSS 决定，中间没有任何东西保证两者相等。**

## 决策

### 目标

1. **收成一句能验的话**：画布画的每个矩形，DOM 里必须真有一个元素与它同宽同高。**内容在这个盒子里溢不溢出，是皮肤 CSS 的自由，画布不管。** 这是主人定的口径 —— 保障我们自己的默认皮肤真实反映，同时保住皮肤的自由度。

### 做法

2. **渲染器给每块加一层「格子层」。** 外层由渲染器注网格坐标，皮肤够不着；内层就是今天那个 `[data-bn="self"]`，皮肤照旧随便捏。外层 `display:grid`，所以内层仍是 grid item，皮肤写的 `justify-self` / `align-self` 参照系一样大、行为不变。
   - **恒等靠结构，不靠自觉**：清洗器强制每条块 CSS 以 `[data-bn="self"]` 打头，渲染器把它翻成 `.bn-blk-<id>`。class 挂**内层**，于是块 CSS 结构上选不中外层。
   - `data-block` **一个字不动**留在内层，外层挂新的 `data-cell`。既有的验收门、挂点契约、`selfLabelled` 那个特例零改动；画布按 `data-cell` 找格子。被否：外层挂 `data-block`（`guard.badge` 自带一个，会重新引出「一块两个 `data-block`」那个老问题）。
   - **`grid.z` 搬到外层**：内层的 `z-index` 只在外层那一格里排序，压不过隔壁块。
   - **`heightFromRows` 的高度留在内层**：它是**块**声明自己多高，格子的高度归行轨道；而且搬上去的话内层会 `stretch`，把自己的外边距从高度里扣掉，外观当场变。
   - 外层还要显式 `place-self:stretch` 与 `place-items:inherit`：前者挡住外框的 `align-items` 把格子捏小（那就不是格子了），后者把外框的默认对齐透给内层，让没写 `align-self` 的块表现与从前一致。**这三条的实测数字写在代码注释里，不在这儿抄第二份。**

3. **画布的列线改读真值**：从预览 iframe 读一次玻璃层的实际宽度与 `grid-template-columns`。这个值只在改列定义 / 卡宽时变，不像块的 rect 那样每拖一下就抖 —— 所以读它不拖累拖拽的即时性，画布其余部分仍是纯本地算。

4. **加两道门，不是一道。** 今天**没有任何测试**钉这件事，这正是错位一直活到主人自己发现的原因。一道盖不住，因为门禁里的测试跑 jsdom，而 **jsdom 没有布局引擎**（`getBoundingClientRect()` 一律回 0 —— 决策 20 当初把几何算法拆成纯函数正是为此），CI 的干净安装也没有 Chrome。
   - **常驻门（进 `vp test`）钉结构**：外层在不在、`data-cell` 与网格坐标在不在、`grid.z` 有没有被注回内层。恒等一旦对上，真正会漂的就是结构 —— 有人顺手把 `data-cell` 挪了、把 z 写回内层，这道门当场红。
   - **本机门（住像素门旁边，不入库）钉几何**：拿出厂皮肤那 23 份产物，在真 Chrome 里逐块比「画布算出来的格子」与 `data-cell` 那个元素的 rect，不等就红。跑一次，结论写进代码注释。

### 调试开关

5. **真卡上看得见格子。** 面板给一个开关，往预览 iframe 的 srcdoc 追一段 `<style>`：`[data-cell]` 描一条轮廓，悬停那一格上半透明底 —— 浏览器开发者工具查元素那个样子。**这个开关只有格子层存在才做得出来**：今天那层 wrapper 会被皮肤捏形状，描出来的框不是格子。
   - **注在 web 侧**，出图那条路一个字节都不动：调试样式绝无可能漏进推送的卡，出图基准也不被它污染。被否：渲染器加 `debugCells` 选项。
   - `outline` 与 `background` 都不占布局，所以开着调试看到的仍是那张真卡。
   - `:hover` 由浏览器自己做，不需要脚本 —— 决策 22 那条「同源与脚本永远不许同时给」照旧。
   - **悬停高亮为主，另给一档「全部常显」**：常显会把卡看花，查某一块时用的是悬停。
   - **尺寸牌不做**：框里没有脚本，牌子只能用 CSS `content` 拼一串渲染时算好的死字符串，还会被卡片内容盖住、裁掉。要数字就在画布那侧的检查器里报 —— 那个数就是本决策保证过的同一个数。

### 边界

6. **外框 CSS 那条口子不堵。** `sanitizeCardFrameCss` 是 free 模式，皮肤写 `[data-bn="glass"] > *` 仍摸得到格子层，恒等会破。不堵：本决策承诺的就是「出厂皮肤恒等 + 皮肤自由」，决策 4 那道门也只钉出厂皮肤那 23 份。free 模式是决策 13 有意留的口子，别在这儿顺手收窄它。

## 明确不做（拷问中被否决的）

- **画布叠在真卡上编辑。** 决策 6 的 🔗 否过一次，这轮**以新理由再否**：真容器 68×30 摆在 112.5×50 的格子里，这个盒子在「12 列 × N 行」的图上根本画不出来 —— 要么按真像素画（那画布就不再是网格），要么四舍五入回格子（那是更难查的撒谎）。**所以「画布读每块的真 rect」单独不成立**，它必须连着「画布整个变成真卡上的叠层」一起做；而后者的代价一条都没变：预览是 server 异步出的、拖拽中间那段没有真值、被盖住的块点不中、`showIf` 收起的块在真卡里没有盒子、真卡还被缩放。
- **强制内容不许溢出容器。** 主人否掉的第一版：那是皮肤 CSS 的自由，画布不该替它做主。（顺带记一个实测结论，免得下次重算：出厂 23 份产物今天**零溢出**、块 CSS 里**零阴影**，所以「加一道裁」本来是零像素改动 —— 但它解决的不是本决策要解决的问题。）
- **让内容填满容器**（拖窄就真变小）。要它就得改掉出厂皮肤 13 处写死尺寸、四张卡的列定义全部重排，12 等分列基本退场。这是另一个决定，值得单独一轮，别混进「保真」这件事。
- **把出厂皮肤那 13 处收缩下放到块根**（只改皮肤、不动渲染器）。便宜，但只保障我们自己这一份 —— 别人写一句 `justify-self:start` 画布又开始撒谎。恒等要靠结构。

## 后果

- 每块多一个 div：23 份字节基准全红，**像素应当零差**（外层默认 stretch，内层行为与今天相同）—— 落地时逐片过像素门验，不许先 `-u` 再看。
- **存量皮肤一行都不用改**：挂点与 class 都留在内层。
- 画布从此**纯本地算**格子（列线那一次 iframe 读除外），拖拽的即时性保住。
- 认下的代价两条：外框 CSS 仍能破坏恒等（决策 6）；皮肤把容器缩小时画布看不出来 —— **不描内层淡框**，那会在示意图上再加一层要解释的东西，而真预览就在旁边。

## 仍未决

- 「让内容填满容器」那一轮什么时候开。
- 尺寸牌到底要不要。主人坚持的话就用 `content` 拼，并在界面上说清它拼的是渲染时算好的值、不是浏览器量的。
