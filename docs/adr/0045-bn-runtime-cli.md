# ADR-0045：通过BN启动器运行宿主成品

- **状态**：2026-11-11主人指定npm启动器为`@bilibili-notify/bn`。
- **影响面**：宿主启动器、开发宿主产物、拓展作者指引与分发。
- **修订**：[ADR-0040](0040-extension-sdk-npm.md)补充公开启动工具；延伸[ADR-0044](0044-extension-source-development.md)的源码开发流程。拓展源码加载、手动挂载、多工程独立重载与正式产物隔离继续成立。

## 背景

拓展作者需要运行一台BN宿主，修改的对象是自己的拓展。运行成品不需要准备主仓依赖和构建SDK。运行成品与开发本体应各有明确入口。

## 决策

1. npm启动器使用`@bilibili-notify/bn`，可执行名为`bn`；普通用户通过`npx @bilibili-notify/bn web`运行正式宿主。启动器只依赖Node及其公开npm依赖，不要求全局vp或本地Git检出。
2. `bn dev`显式运行打包好的开发宿主，保留拓展源码挂载、加载与热重载。`create-bn-ext`继续生成独立拓展；拓展不启动或发现宿主。开发BN本体仍直接克隆主仓，按仓库既有vp命令运行。
3. 正式和开发宿主分别构建，启动器严格选择对应产物。正式产物继续从构建中剔除开发能力；运行环境变量不能把正式产物变成开发宿主。
4. 启动器取得官方构建产物，核对固定版本、用途、大小和摘要后缓存；下载或解包失败不替换完整缓存，离线运行只使用已校验缓存。npm不逐包公开业务核心，也不退回克隆源码或在用户机器构建主仓。

   🔗 **2026-11-11改为随包提供宿主**：首次下载改为npm包自带两种宿主，随主程序tag发行，见[ADR-0046](0046-bundled-npm-distribution.md)。
5. 持久数据与可删除的运行时缓存分开，正式和开发默认数据分开，支持显式指定数据目录。沿既有迁移、备份和拓展生命周期，不自动搬动已有工作区的数据。
6. 启动器提供web/dev两个运行入口，不另提供宿主工作区初始化器。将来出现明确的项目化配置需求时，再考虑`bn init`。现有用户工作区和示例由用户管理，启动器不自动改动。
7. 外部拓展开发沿SDK与公开宿主能力，主仓开发与拓展工程继续用vp。此决定不改变MIT许可，也不引入多包管理器兼容层或改变仓库PR政策。
8. 本次只定实现与包名。实际发行版本、宿主产物、npm组织权限和发布动作在发行时确认；本地npm归档与协议夹具不代表已经发布。

## 明确不做

- 不在隐藏目录中检出BN主仓，或由拓展工程管理另一台BN进程。
- 不把正式包的开发能力改成一个运行期环境变量开关。
- 不用临时npm缓存保存唯一一份用户数据，不覆盖用户自行指定的目录或已有源码修改。
- 不通过打包声称能够禁止修改本地副本，不顺带改变软件许可。

## 后果

拓展作者通过成品运行宿主；启动器需要承担成品获取、校验、缓存及进程收尾。开发宿主新增一份明确用途的构建产物，正式发行的隔离与既有自包含布局仍需独立验证。
