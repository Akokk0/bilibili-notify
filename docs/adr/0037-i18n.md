# ADR-0037：多语言 —— 整台一种语言，口吻是叠在平实版上的一层

- **状态**：2026-10-12 拷问定案（一次一题，十七题；其中两条在收尾复核时当场改定）。**未施工**。
- **记录方式**：拷问当场落的定案。拍板前做了一次全仓只读勘察（对人说的话散在哪、多少处是拼出来的、哪些整句落了盘、拓展契约里有哪些给人看的字段），选型前把三种做法各做了一个用完就扔的小样。
- **影响面**：`apps/web`、`packages/ui`、`apps/server`、`packages/internal`、`packages/image`、`packages/ai`、`packages/extension`（契约第 3 版）、仓里的拓展、桌面壳的托盘菜单；主人的设置文件要迁移一次（文字模板与内置人格的存法）。
- **依赖**：[ADR-0026](0026-failure-results.md)（失败的形状）、[ADR-0025](0025-integrations.md)（问题表、集成上下文）、[ADR-0021](0021-neutral-core.md)（来源的描述符、文案模板）、[ADR-0030](0030-ai-follows-sources.md)（提示词变量）。
- **不影响**：日志、开发版专属的调试面板、主人自己写的文案与提示词。

## 背景

主人 10-11 定了要做多语言，核心与面板都做，并要求在 3b 的拓展契约定稿之前把几件大事定下来。勘察时的现状：

- 对人说的话全部写死在代码里：面板约 3100 行带中文、服务端约 2400 行、核心包合计约 700 行（数的是带中文的行，已粗剔注释与日志）。没有任何按键取文案的机制，没有装过多语言的包，没有语言设置项。
- 句子大量是拼出来的：面板里模板字符串带变量的约 280 行、三元挑词约 160 行、「数字 + 量词」约 50 行。
- 服务端回给面板的失败是写好的整句（约 450 处），面板基本原样显示；问题文案、私聊、指令回复同样由服务端出。
- 整句会落盘：推送历史的成品文字与失败原因、主人改过的文字模板、锐评草稿、重推原件。问题表只在内存里。
- 设置文件里存的是完整的一份文字模板与内置人格：没改过的存的就是默认文案的原样，分不出「没改过」与「改了又等于默认」。
- 测试里断言中文原文的约 5100 行，面板测试按中文文字找元素。
- 拓展契约里没有任何语言相关的字段。

同期另有一件已定的事：第 4 期要做「口吻」开关（女仆 / 平实两套，用户自选）。两件事都要「同一句话有几个版本」，所以一起定。

## 决策

### 范围

1. **语言整台一种，放 store，出字的那一刻读。** 面板、私聊、指令回复、推到群里的文字与卡片、数字与时间的写法都用这一种；不按推送目标分，也不为它给出字的函数加语言参数。面板与服务端各有一个 store。
    - 两条要守的：出字的那一刻才读，不在文件加载时读（写成常量表的名字，如卡种名、平台名、字段名字典，不能在加载时把字取好）；`packages/internal` 里前后端共用、被守卫钉着不许有值的 import 的那几个文件不能自己去拿 store，「当前语言」由面板与服务端各自在启动时交给它。
    - 留的缝：以后真要按目标分，服务端让「当前语言」跟着一次推送的执行过程走（运行时自带的异步上下文），出字的代码不用改。这条没有做过小样。
    - 理由：BN 是一个人部署、推给自己那几个群的工具，同一台同时服务两种语言的群是少数；按目标分会让出卡与 AI 点评的成本按语言数翻倍。
2. **第一版四种语言：简体中文、繁体中文、英文、日文。** 机制按「可以再加一种」做，不写死成四种。
    - 🔗 2026-10-16（3b-10，主人定）：**繁体中文进第一版**，语言码 `zh-TW`，选择器上显示「繁體中文」；原文「三种语言、繁体中文不在第一版」改掉。繁体的译文与女仆层都第 5 期做，在那之前没翻的句子由简体中文打底。
3. **口吻是单独的一个设置项，不是语言列表里的一项；女仆版是叠在平实版上的一层。**
    - 每种语言一份完整的平实版是底：标题、导航、栏目名、数据名只在这里。女仆版只写与底不同的句子（交互与提示：说明句、按钮、状态行、报错、私聊）。
    - 切换语言或口吻的那一刻把两份合成一份放进 store，之后按键读；不在每次取字时回落。
    - 某种语言没有女仆层时，口吻那一项在这种语言下不出现。
    - 理由：并进语言列表的话，标题与数据名要写两遍或一样要做回落；语言是「看不看得懂」，口吻是「喜不喜欢」，放在一个选择里切语言会顺带把口吻切掉。
    - 🔗 2026-10-14（3b-10，主会话照规矩定）：**口吻那一项设置的默认值，第 4 期定默认之前取女仆**（今天写死的话全是女仆口吻，行为不变）；默认值只写在规则里、不落盘，第 4 期改默认时没动过的人自动跟上。
    - 🔗 2026-10-15（3b-09，主人定）：这一项在代码与设置里叫 **`voice`**，取值 `maid` / `plain`。`tone` 已指状态的轻重、`persona` 已指 AI 人格、`Style` 已指卡片样式，都不用；词表见命名规范。
    - 🔗 2026-10-16（3b-10，主人定；放哪与怎么补是主会话照规矩定）：语言那一格在设置里叫 **`locale`**（BCP 47 写法，词表同上，不用 `language` / `lang`）。`locale` 与 `voice` 都放核心设置顶层、**可选、不带默认值**：缺的按核心里一条规则函数补（语言简中、口吻女仆），默认不落盘；「改回跟默认走」是把这一格删掉。
4. **女仆层：中文（简体、繁体）与日文有，英文第一版只出平实版。** 之后给英文补，只是多放一个译文文件。
    - 🔗 2026-10-16（3b-10，主人定）：繁体的女仆层第 5 期做，从简体女仆层转写、再按台湾用词调；怎么转写、谁把关第 5 期再定。

### 机制

5. **译文放 JSON 文件，构建时打进包。** 每种语言一个平实版的文件，女仆层另一个文件。**不在运行时去磁盘读**：服务端是自包含的打包产物，运行时读自己包里的文件会在运行期出错而构建全绿。代码里取字是「键 + 参数」。
    - 理由：日文的译文要请写代码以外的人来看、来改，数据文件让不写代码的人也能提修改。以后要换成写在代码里，用的地方不用动，JSON 转成代码是全自动的；反方向要守规矩才转得动，所以从 JSON 起步两头都不亏。
6. **自己写一层薄的，不装多语言的包。**
    - 形状：一个函数把平实版与女仆层合成一份；取字函数按键取、填 `{名字}` 形式的占位符，带数量的句子在译文里拆成带类别后缀的几条、按当前语言的单复数规则挑（规则用运行时自带的，不自己写）；一个带订阅的 store，面板订阅它、切语言后已经画出来的组件自己变。
    - 键的集合由类型从简体中文那份译文里取：键写错在编译时报。
    - 一条检查钉着：各语言的键齐不齐、同一句的占位符一不一样、带数量的句子各类别齐不齐、女仆层的键是不是都在底里。
    - 🔗 2026-10-15（3b-09，主人定）：**对外公开的三样格式**（经 `ctx.i18n` 交给拓展，定了就改不动）：带数量的句子写成 `键#类别`（类别名直接用 `Intl.PluralRules` 给的 `zero` / `one` / `two` / `few` / `many` / `other`），取字时传 `count`；语言码用 BCP 47 写法 `zh-CN` / `en` / `ja`，一个文件就叫 `<语言码>.json`；放译文的目录叫 `locales/`（BN 自己与拓展同名，见决策 14 下的 🔗）。女仆层的文件名只有 BN 自己用（口吻不交给拓展，决策 15），3b-09 照规矩定。
    - 另加一条检查补短板：调用处传的参数名与那句译文的占位符对一遍。这条没有做过小样，是按仓里已有的读源码语法树的守卫推的。
    - 理由见「明确不做」里两个现成的包各自的情况。
    - 🔗 2026-10-13（3b-09，主人定）：**公开接口落定**。核心：`mergeDict` / `translate` / `createI18n`，住 `packages/internal` 新开的零依赖子路径（「仍未决」里「核心的那一层放哪个包」的结论）；服务端：`i18n` 与 `t`；面板：`i18n` 与 `useT()`。译文 JSON 住服务端与面板各自那边。
7. **语言是服务端的一项全局设置；服务端出的话由服务端翻。** 回给面板的失败、问题文案、私聊、指令回复、推送，都在出字时用当前语言取好；面板原样显示，面板自己的界面文字也跟这一项走。失败的形状不变，仍是 `code` 加写好的 `message`。
    - 面板连不上服务端、还没登录时：浏览器里记住上一次的语言，头一回打开按浏览器语言猜。
    - 🔗 2026-10-16（3b-10，主人认可）：没登录时浏览器**语言与口吻都记**（键 `bn.locale` / `bn.voice`），超出上一条的字面（只记语言）；口吻登录前没有别的出处，不记的话选了平实的人每次先看到女仆口吻。登录后以服务端设置为准，并把它记回浏览器。
8. **存下来的整句不跟着语言变；只有问题表在换语言时重报。**
    - 推送历史的成品文字与失败原因、锐评草稿、重推原件：存的是当时的原话，历史行的形状不改。
    - 问题表：换语言的那一刻让各处把开着的问题重新报一遍（同一条再报只换文案，是问题表已有的规矩），问题表与私聊马上是新语言。
    - 理由：历史是记录，成品文字本该是当时推出去的原样；失败原因里常带着平台返回的原话，拆成「哪一句 + 参数」也翻不了那一段；换语言是很少发生的动作。
    - 🔗 2026-10-20（主人定 R1 乙）：换语言时问题表重报另开一片 3b-61，不在 3b-51 做；3b-51 只保证私聊的引子在出字那一刻按当前语言与口吻取，表里开着的句子要等 3b-61 重报才换。
    - 🔗 2026-10-20（3b-61 落成）：宿主的句子交取字函数（`message` / `recoveryMessage` 收 `string | (() => string)`），表在语言**或**口吻变了时重跑，字变了发 `updated` 并带 `reworded`；B 站与 QQ 官方机器人自己记着、换语言时重报；拓展自己在 `ctx.i18n.onChange` 里重报；通知器把「只换了说法」当同一件事 —— 记成「不再说」的不重发，「已恢复」用新说法。已知缺口：语言换过之后，同一条的第一次再报一律算「换说法」。
9. **主人敲进来的字一律从宽。** 三种语言的内置指令别名、三种语言的时长单位，不管当前是哪种语言都认；帮助里只列当前语言的那几个。
    - 理由：别名与单位是输入，不是 BN 说的话；切了语言，手上的习惯不会马上跟着换。

### 各块怎么跟

10. **推送的文字模板改存法：没改过的不存，跟随当前语言的默认。** 「设置文件里没有」就是跟随默认；只有主人改过的才存。换语言、以后默认文案更新，没改过的自动跟上；主人改过的是主人写的字，不动。
    - 这是一件单独的重构：迁移主人现有的设置文件（等于默认的那几条拿掉）、所有读模板的地方改成「没有就取默认」、「默认文案有更新」那套提示的含义重定（只对主人改过的那几条还有意义）。
    - 理由：「跟随默认」与「主人改过」从此分得清。
11. **AI：提示词保持中文，加一句指定输出语言；内置人格出三种语言，并跟着当前语言走。**
    - 给模型的提示词（点评、总结、锐评、做皮肤、技能）不翻，只加一句「用当前语言回答」。要求模型按固定键名输出的那种结构是程序在读的格式，不动。
    - 内置人格：设置里只记「留着哪几份内置的」与主人自己建的；内置那几份的内容每次按当前语言取。内置的在面板上本来就锁死（能删、能另存副本、不能就地改），所以跟着走不会盖掉任何东西。主人自己建的、从内置另存的副本不动。设置文件的这次迁移并进第 10 条那件重构。
    - 工具回给模型的话同提示词，不翻。
    - 按中文标点整理模型输出的几处，要跟着认英文与日文的写法。
    - 理由：提示词是程序与模型之间的约定，不是给人看的；按语言各写一份，每次改要改三处、测三遍，效果也难保一样。
12. **面板的使用指引要翻，开头一句可以带女仆口吻。** 每种语言一篇平实的正文；开头的那一句引子不写在文章里，放进字典当一个键，平实版里是普通的开场，女仆层里盖成女仆的那一句。
    - 理由：指引是最适合出女仆口吻的地方，但要非常克制，只有开头一句；正文不按口吻写两份，免得两份各改各的。
13. **不翻的**：日志；开发版专属的调试面板。

### 拓展

14. **拓展参与多语言。**
    - 清单：给人看的字段保持单个字符串，当默认的字；拓展包里每种语言一个译文文件，按字段在清单里的位置对应。宿主读清单后再读当前语言的那个文件，对得上的盖上去，没有就用清单里原来的字。
    - 运行时：把「当前语言」交给拓展，换语言时通知它；说哪种话由拓展自己定，宿主不拦。
    - 两样都可选：不带译文文件的拓展、不理会当前语言的拓展照常能用。
    - 理由：与宿主自己的译文放法统一，清单看着不乱；旧的宿主不认识多出来的文件，照常用清单里的字。
    - 🔗 2026-10-14（3b-43，主人定；键与错误处理、白名单主会话照规矩定）：**拓展的译文与 `ctx.i18n`**。译文放包里的**单独目录**（目录名与 BN 自己放译文的目录同名，3b-09 定），一种语言一个 `<语言码>.json`，`extension.json` 只有一份；宿主读包里的译文，给上下文一个 `ctx.i18n`：按当前语言合好、`t(键, 参数)` 取字（占位符与单复数同 BN 一套规则）、语言变了自己换并另给 `onChange`；清单字段的译文住同一份文件的一个保留段。它顶替上面「当前语言 + 变了的通知」原排的两格。键按字段在清单里的路径，一条一条的（设置项、选项）按它们自己的 `key` 而不是序号（上面「按位置」与「仍未决」里「按 `key`」不矛盾，后者是对列表的细化）。写坏的文件或对不上的键只丢那一份 / 那几条、记 warn、拓展页注一句，不拒整个拓展。装包白名单放行「那个目录下的 `<语言码>.json`、能按 JSON 解析、单份限大小」，解压总量上限与打包脚本同改（ADR-0012 决策 8 下的 🔗）。**与本条理由的出入**：「旧的宿主不认识多出来的文件，照常用清单里的字」对今天的装包器不成立（白名单外的文件会整包拒），但装得了第 3 版的宿主都认译文，不受影响。
    - 🔗 2026-10-17（3b-43，主人定）：**译文的文件、键与回落链落定**。译文目录 `locales/`、一种语言一个 `<语言码>.json`（BCP 47），`extension.json` 只有一份；普通键与 BN 同段形 `[A-Za-z0-9_-]+`（点分；带数量的句子用 `#类别` 后缀，类别名照 `Intl.PluralRules`）；清单字段的译文住顶层保留键 `$manifest`，值照清单的形状嵌套，列表按 `key` / `value` / `host` 展开成子对象。回落链固定为「本语言 → 简中 → 英文 → 清单原字」，不按语言分；清单原字只对清单字段有意义，运行时走到链尾仍没有就回键本身。宿主先按这条链为每种语言合成平实版再交给 `createI18n`，不给 `fallback`、不改核心。**「原字排最末」与上面「没有就用清单里原来的字」字面上有出入，主人知情同意。** `ctx.i18n` 的形状定为 `ExtensionI18n { locale(): string; t(key, values?): string; onChange(fn): Disposable }`，只挂拓展上下文；语言真变时换字并叫一次 `onChange`，口吻不交给拓展。装包时认长得像 BCP 47 的文件名，只有 `LOCALES` 里的语言写进盘，落盘文件名取自常量、不取自 zip（见 ADR-0012 决策 41 ② 下的 🔗）；不在表里的（含大小写写错的）跳过并在装包结果里告知，读目录时也只读表里的。上限：单份 256 KB、`locales/` 合计 2 MB，整包 10 MB 照旧。坏了照下面这条规矩：装包时不是 JSON 或超单份上限，整包拒并点名那一份；读目录时（手放、开发版软链、对不上的键）只丢那份 / 那几条、记 warn、拓展页注一句，不拒整个拓展。照规矩定（可否决）：语言变了宿主替每个在跑的拓展喊一次「面板数据变了」；读目录的问题 warn 只记一次；只换了译文、跑着的那份标 `staged`；面板那一句标题经 `useT()` 进面板字典；本片只让假源带 `locales/`，桥这一片不动，桥的清单与视图文字何时收另行写进 construction-plan。
    - 🔗 2026-10-19（3b-43 落地）：宿主在 `extensions/locales.ts` 的 `runtimeDictOf` 里按同一条链为每种语言合好平实版，直接交给核心的 `translate` 取字，没有另建 `createI18n`（拓展用不上订阅与口吻层）。「不给 `fallback`、不改核心」照旧成立，行为与 10-17 那条一致。
15. **口吻不交给拓展。** 拓展的话一律平实。

    - 🔗 2026-10-20（3b-51 R2 乙，主人定）：集成没给恢复句时，通用的那句带名字与**集成的原句**（不带引子，只一层）：「主人，好消息，<名字>之前报告的「<原句>」已经恢复啦。」。理由：同一个拓展私聊过两种问题时，只带名字分不清恢复的是哪一件；只接原句、不接整句，所以不会套两层引子。上面 10-14 那条的「一句带名字的通用说法」按这条为准。
    - 🔗 2026-10-20（3b-51 落成）：**写者名与引子**。问题表的上报入参与 `ProblemChange` 多一格 `writtenBy?: string`，意思是「这句话是哪个集成写的」，值是给人看的名字；它不上 `Problem`、不进 `GET /api/problems`、不进 `apps/contract`。写者名盖在三个上下文入口（集成、来源、适配器），逐格抄，第三方塞不进来：集成上下文与适配器上下文的选项 `label: () => string` 在报问题那一刻取；拓展取当前语言的清单名、走与拓展列表同一条回落链；B 站取来源描述符的 `label`；内置适配器暂用适配器键（`qq-official` 等），第 4 期适配器自带描述后换。宿主直写问题表的那几条（连接探测、拓展设置、核心设置、登录）不盖，就是宿主写的整句。引子只在通知器把话交给发送口的那一刻按当前语言与口吻加，账上存的是集成交上来的原句，「不再说」的比较不受影响。字典键 `problem.relay.reported` / `problem.relay.recovered` / `problem.relay.recoveredGeneric` / `problem.recoveredGeneric`，女仆层 `zh-CN.maid.json` 第一次有了这四条。登录问题归宿主：`subscriptions/login-problems.ts` 的 `watchLoginProblems` 按来源键报与清 `auth_lost`（`expired` 私聊、`logged-out` 只进表、`logged-in` 清），句子是宿主写的整句（字典 `problem.login.*`）。

## 明确不做

- **按推送目标分语言**：同一条作品要按语言各出一份文字、各渲染一张卡、各生成一次点评，模板设置也要按语言各存一份。
- **语言当参数从上往下传**：约六千行出字的代码每个函数多一个参数，改的签名比文案还多；面板换语言要靠订阅重画，参数做不到。
- **口吻并进语言列表**、**女仆口吻只留在中文里而不做成可选项**。
- **译文写在代码里**：编译时能拦住所有对不上的地方，但不写代码的人改不了。
- **译文放 YAML**：面板没有解析它的依赖，JSON 两边今天都能直接引。
- **现成的、运行时查字典的包**（小样用的是 i18next 配 react-i18next）：服务端产物大约 79 KB、面板大约 52 KB；新加的包默认不会被打进服务端的自包含产物，构建全绿、运行时才报找不到包，要在打包配置里登记；「只换口吻不换语言」时面板不会重画，要借包的内部事件；自己要写的胶水反而更多。
- **现成的、编译期把译文生成成代码的包**（小样用的是 Paraglide JS）：每次编译要从公共的文件分发站下载一个插件（不是装进来的包、不在锁文件里），生成的代码不进版本库、测试与类型检查之前要先生成；带进 27 个构建期的包；参数能在编译时查，但漏翻一句会静默显示底稿、女仆层多写了键拦不住；英文单复数要写一段带专门语法的结构。
- **语言跟浏览器走、服务端只给「哪一句 + 参数」由面板翻**：约 450 处失败的形状全要改，面板要再有一份字典，混着第三方原话的句子难拆；私聊与推送无论如何都得服务端翻。
- **把存下来的整句改成存「哪一句 + 参数」**（只改推送失败原因，或全部都改）。
- **换语言时逐条比对、把等于旧默认的模板换成新默认而存法不变**；**都不自动换、全部亮提示让主人逐条点**。
- **提示词也按语言各写一份**；**第一版 AI 只说中文**。
- **换语言后主人正在用的内置人格不变、要自己去换**：理由原是「自动替换会盖掉主人改过的内容」，核对后对内置的不成立（内置的改不了）。
- **使用指引第一版不翻**（照样显示中文，或在英文与日文下把入口藏起来）；**使用指引只出平实版**。
- **拓展清单的字段直接写成按语言分的一组**（`"label": { "zh-CN": …, "en": … }`）：一个文件、列表型的字段不会错位，但清单会变胖，与宿主自己的译文放法也不一样。
- **拓展不参与多语言**、**只接运行时那一类**。
- **把口吻也交给拓展。**
- **只认当前语言的指令别名。**
- **第一版只做简体中文与英文**；~~**简体中文、繁体中文与英文**~~ —— 2026-10-16 推翻：繁体进了第一版，与日文并存（四种），见决策 2 下的 🔗。
- **三种语言都有女仆层**；**只有中文有**。
- **多语言单开一期排在第 4 期之后**；**3b 开工前先把收字全做完**。
- **新装一律默认简体中文**；**新装时先出一步选语言**。

## 后果

- 主人的设置文件要迁移一次（文字模板与内置人格里等于默认的内容拿掉），要占一个迁移修订号。
- 行为变化：今天默认文案更新是亮提示等主人点头，改完后没改过的直接跟着变。
- 换语言后翻推送历史，旧行的失败原因是旧语言，一页里会混着两种语言。
- 换语言时重报问题管不到拓展报的那些：拓展说哪种话自己定，要等它自己重报才变。
- 中文提示词配英文或日文输出，模型可能跑回中文；测试里验不了（测试不调真实的模型），只能真机看。退路：哪一份跑偏得厉害，单独把那一份按语言各写。查过的三个做多语言的同类项目里，两个是提示词一份加一句指定输出语言、一个是提示词按语言各写，但前两个的底稿是英文，这里是中文。
- 从 3b 到第 4 期结束，代码里一半走字典、一半写死；第 4 期本来就重，加上收字会更重。
- 译文里参数对不对从「编译时就报」退到「靠检查报」。
- 拓展包多出译文文件：安装、市场的签名、备份都要带上它们；译文文件里的位置对不上清单是一种新的出错方式。
- 桥接拓展自己的清单与视图文字也要出三种语言。
- 约 5100 行断言中文原文的测试：简体中文那份译文与今天的原文一致时不受影响，文案在第 4 期逐句改写时要跟着改。
