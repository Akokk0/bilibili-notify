# ADR-0014:卡片皮肤 —— 皮肤包是网格里的块,不是一门模版语言

- **状态**:2026-09-13 `/grill-me` 两轮 20 条拍板,同日开工第一步;当日晚间开工后改正两处(决策 5 的验收门口径、决策 24 的发版节奏,见各自条目的 🔗)。
- **记录方式**:拷问原文当日整理,非追认。
- **影响面**:`packages/image`(模板拆块、皮肤渲染器、清洗器)、`packages/internal/src/schema`(数据契约、挂点表、变量表、皮肤包 schema;`cardLayout` / `cardStyle` 迁移)、`apps/server`(`<dataDir>/card-skins/`、上传 / 导出、预览 HTML 路由)、`apps/web` 卡片页与新编辑器
- **依赖**:ADR-0002(CSS 清洗方言与挂点哲学整套借用)
- **取代**:ADR-0002 头部那句「不影响卡片渲染图(后者有模版编辑器的地盘)」—— 那块地盘现在归这份
- **不影响**:发送侧的消息版式(`messageLayout`:卡 / 文字 / 链接的先后)、dashboard 皮肤本身

## 背景

dashboard 有皮肤包,AI 女仆能造皮肤包;推送出去的卡片图却只有一套写死在 Vue JSX 里的外观(`packages/image/src/templates/`,九个模板 1621 行),用户能动的只有渐变色 / 字体 / 玻璃 / 背景图,以及一个**一维竖栈**的版式编辑器(`cardLayout` v7:块的顺序、显隐、上边距)。主人要的是:卡片也有皮肤包,且皮肤包能改**布局**;布局编辑器从「只能上下」进到「自由排版」。

主人的原提案:皮肤包 = 一份自定义模版,BN 提供数据并负责渲染;编辑器以「块」(一个 div)为最小单位自由排版,每块可单独编辑含自定义 CSS,块里写什么由用户决定;为此定一门模版语法,编辑器带解析器。

拷问下来改了三处提案的形状(决策 1、3、8),其余照主人的方向细化。

## 决策

### 形态(皮肤包是什么)

1. **正本是 JSON,没有单独的模版语法。** 皮肤包 = `card-skin.json` + `assets/`,编辑器直接读写它;「语法」只剩块内容里的 `{a.b.c}` 占位符。
   - 被否:先定一门文本模版语法、编辑器解析后可视化编辑再存回文本。理由:GUI 与手写文本要**双向往返**,任何 GUI 不认识的写法都会把往返弄断;而且解析器只能住渲染那头(`packages/image`),编辑器再带一个必然漂移。
   - 被否:JSON 正本 + 单向导出成文本。没人真需要。
2. **zip 分发,跟 dashboard 皮肤同规**:面板上传 / 导出 / 复制一份 / 删除,存 `<dataDir>/card-skins/`,zip-bomb 闸与资产上限沿用 `skins/package.ts` 的思路。**不进拓展市场** —— 皮肤是数据不是代码,签名索引与宿主 ctx 是给要跑代码的东西准备的;将来要「皮肤市场」单开索引。
3. **一包覆盖全部七种卡**(live / dynamic / sc / guard / 锐评榜单 / 单人锐评 / 词云),缺的卡种回落默认皮肤。用户换皮肤的心智是「换一套风格」,不是逐张卡换。**锐评榜单、单人锐评、词云三种各自整张是一个固定内置块**,皮肤只管它们外面的卡片外框(词云是页面里跑画布脚本画的,块模型进不去)。
4. 皮肤包记 `schemaVersion` 和它写时依据的**数据契约版本**(决策 12)。对外叫「卡片皮肤」,代码里叫 `card-skin`。
5. **默认皮肤内置只读**,要改先「复制一份」。当前外观必须能用这套格式重写出来 —— 这是格式够不够用的验收门,口径见决策 24。

### 布局(自由到哪一步)

6. **12 列网格 + 可调卡宽。** 每种卡一份网格,每块占「第几行、从第几列起、跨几列」,行高随内容自撑;卡宽是皮肤包字段(现在 `renderCard` 就吃 `htmlWidth`,只是没暴露),有上下限。根块是卡片外框(内边距 / 背景 / 圆角),有自己的挂点与 CSS。
   - 被否:**绝对坐标**(x / y / w / h 自由拖)。卡片内容高度不定 —— 一条动态可能一行字也可能二十行加九图,绝对坐标下内容一变块就互相压住。
   - 被否:一维竖栈 + 块内左右分栏。「自由」只剩一层,主人正是嫌它只能上下。
   - 附带:上舰卡现在特判的「徽章靠左 / 靠右」(`GuardLayout.badgeSide`)在网格下就是普通的一行两列,`GuardLayout` 这一支退役。
7. **块分内置与自定义。** 内置块渲染逻辑不动、用户只能排版 / 显隐 / 挂 CSS;自定义块用户自己写内容。理由:动态卡正文 567 行逻辑覆盖 14 种动态类型,用户用占位符拼不出来。
8. **内置块复合与原子并存。** 现有 14 个复合块照旧(默认皮肤用它们,升级零跳变);另加原子块:头像、名字、时间(三种卡的「头部」都是这三件套)、徽章、分割线。皮肤要么用复合块,要么用原子块自己拼,都合法。
   - 被否:维持现有粒度。「头像单独放左栏、名字放右上」做不到,自由排版在头部这块名不副实。
   - 被否:全部拆到原子。正文与数据行没法原子化,拆了也没人分开摆。
9. **内置块带内部挂点契约表**(「作者行.头像」「统计行.图标」……),可分别挂 CSS,跟 dashboard 的 `SKIN_CSS_HOOK_MAP` 同哲学:hook 名是公开 API 只增不改,真实 class 是实现细节。不然「换个头像圆角」都得整块重写成自定义块,内置块形同虚设。
10. **块级条件显示 `showIf: "<字段路径>"`**,真值一档,没有表达式语言。覆盖「下播才显粉丝变化」「有封面才显封面」。三个显隐开关(`showPopularity` / `showArea` / `showFans`)退役成它。
    - 被否:不区分场面。自定义块会在不该出现的场面留一行空壳。
    - 被否:场面级多份版式(开播 / 下播各一份)。编辑器多一层「当前编辑哪个场面」、默认皮肤要写多份,成本翻倍;将来真要也是在 `showIf` 上加。

### 自定义块的内容与 CSS

11. **自定义块内容是受限 HTML 子集**:标签白名单(`div span p b i strong em img br` 一类)+ 属性白名单,`img` 只准指向包内资产或契约里标为图片类型的字段。清洗按白名单**重建节点树**,不在名单里的标签与属性整段丢弃,不用正则过滤。这是 Q4 那条路的主要代价(现在只有清 CSS 的清洗器)。
    - 被否:结构化 item 列表(文本 / 字段 / 图片 / 图标)。表达力只有一行内的排布,配不上「自定义」。
    - 被否:Markdown 子集。标题 / 列表 / 引用在卡片上没用武之地。
12. **占位符 `{a.b.c}`**,复用 `packages/internal/src/util/interpolate.ts`(已挡 `__proto__` 那族):
    - 数据契约直接提供已格式化的 `*Text` 字段(「1.2 万」「3 小时前」),**不带过滤器语法** —— 过滤器是一门新语言的起点,契约多几个字段便宜得多,且格式化口径由我们统一、皮肤之间才一致。
    - 缺字段:出图给空串,编辑器报警。原样保留 `{xxx}` 会把写错的皮肤推到群里。
    - 转义:文本位置一律 HTML 转义;属性位置只准整个值是一个占位符、且该字段在契约里是图片 URL 类型,其他属性不认占位符。
13. **每块的 `css` 是 dashboard 方言按块作用域收窄**:一段小样式表,用 css-tree 解析成 AST 逐条过滤,选择器只准指向 `[data-bn="self"]`(块自己)与该块类型的内部挂点,外加伪元素;属性走 ADR-0002 的白名单;清洗器复用 `apps/server/src/skins/css-sanitizer.ts`,只换 hook 集合。
    - 与 dashboard 两处刻意不同:`@keyframes` 不放行(截图是静态的,动画只拖慢渲染);块背景图走结构化字段指向包内资产,`url()` 照旧拒收。
    - 🔴 硬底线:`<script>` / 事件属性 / `@import` / 外部 URL 任何情况下不放行 —— puppeteer 是 `--no-sandbox` 跑在 server 旁边的,皮肤包又是要分享的。
    - 被否:只写声明列表、选择器全由我们生成。比方言少的只有伪元素与内部挂点的分别定制,而那正是「换个头像圆角」要用的。
    - 被否:整段样式表选择器随便写。`:has()` / `@container` / 属性选择器都能越过块边界摸到别处,放行就得永远追着 CSS 新特性补洞。
    - 主人的话:「先做出来看看能自定义到什么程度,够不够,不够再改」。

### 数据契约

14. **对外、带版本、每种卡一份的数据模型**,字段名稳定、有中文说明、**只增不删不改名**,老皮肤永远能画;含场面布尔字段(`live.isEnded`、`dynamic.hasCover` 等)供 `showIf`。字段表当契约常量住 `packages/internal/src/schema/card-skin.ts`(拷问时说的是 `apps/contract`,开工时按依赖方向改正:`apps/contract` 依赖 `packages/internal`,反过来不行,而 `packages/image` 也要读这份表),编辑器的「插入字段」下拉与渲染器的占位符解析都从它读;内部 props → 契约的映射层住 `packages/image`。
    - 被否:直接暴露 `LiveCardProps` / `DynamicNode` 等内部形状。皮肤包能分享就一定会被第三方写,内部一重构所有第三方皮肤一起断;`LiveCardProps.data` 还是 B 站原始 `any`。

### 与现有配置的关系

15. **皮肤包吞掉 `cardLayout`,`cardStyle` 留作变量。** 旧版式编辑器退役;渐变色 / 字体 / 玻璃 / 背景图轮换 / 封面轮换作为「皮肤变量」注入(`var(--card-color-start)` 一类)。当前默认外观重写成默认皮肤,存量 `cardLayout` v7 迁进它。
    - 被否:三套并存(皮肤只管 CSS)。会出现「皮肤想要左右分栏、`cardLayout` 是竖栈」互相打架。
16. **变量集是固定契约**,皮肤包可带默认值、可按卡种给不同默认;用户面板里改的覆盖皮肤默认;`cardStyleByKind` 保留,语义变成「这个卡种的变量覆盖」。
    🔗 **2026-09-13 开工后复核**:三个显隐开关(人气 / 分区 / 粉丝)画在「直播数据」**一个复合块里面**,块级的 `showIf` 管不到块内一行。我提议把开关留作变量,主人否掉:「不需要三个开关留在 cardStyle 当变量,我们可以直接编辑块内容」—— 所以数据块**再拆三个原子块**(`popularity` / `area` / `fans`),复合块恒画全部三项;关过开关的存量用户迁移成用原子块拼的派生皮肤(决策 17 的同一条迁移)。
    - 被否:皮肤自定义旋钮(声明 → 面板生成控件)。dashboard 皮肤也没做;将来要也是在固定表上加一段 `custom`。
17. **per-UP = 选皮肤 + 变量覆盖。** 想给某个 UP 单独改排版就把皮肤「复制一份」再改。迁移:存量 per-UP `cardLayout` 若与全局不同,升级时自动生成「<UP 名> 专用」派生皮肤挂给它,出图不变、来历可见。
    - 被否:per-UP 再叠一层版式补丁。是现在「整份覆盖」的翻版,且皮肤更新后补丁会指向不存在的块。

### 运行时

18. **解析与渲染都在 `packages/image`**(皮肤 JSON + 契约数据 → Vue JSX 树 → 现有 SSR / UnoCSS / 截图管线不变)。
19. **装包严拒**(schema 不对、块类型不认识、CSS 清洗后为空、资产超限 → 拒装并报原因);**出图失败回落默认皮肤**,推送照发,面板亮告警「皮肤 XX 渲染失败已回落,原因……」。卡片有最大高度,超了算失败。回落必须可见,不然用户以为皮肤没生效。
    - 被否:照推错图或不推。推送不能因为换皮肤而丢。

### 编辑器

20. **卡片页重组三段**:皮肤库(同 dashboard 皮肤库款式)/ 变量面板(现有控件原地保留,语义变「覆盖当前皮肤默认」)/ 「编辑这套皮肤」进全屏编辑器(独立路由)。per-UP 那侧改成「选皮肤 + 变量」。
    - 被否:另开「卡片皮肤」页。皮肤库与变量面板是同一件事的两层,分页要来回跳。
21. **块样式 = 常用旋钮 + 高级 CSS 文本框,两者同写一段 CSS**:旋钮(内边距 / 背景 / 圆角 / 边框 / 对齐 / 字号字色)的实现就是「解析这块 CSS 里 self 规则的那几条声明、回显、改了写回」,前端复用 css-tree。不要「旋钮值」和「CSS 文本」两份状态互相盖。
    - 被否:只给文本框(普通用户对着空框不会下手,dashboard 皮肤就是因此做了全字段表单);全 GUI(做不完,也不比旋钮多多少表达力)。
22. **预览走 HTML 不走截图**:server 返回 `renderCard()` 产出的 HTML(图片字体已内联成 data URL),编辑器塞进 `sandbox` iframe(不给 `allow-scripts`)实时显示;「最终效果」按钮才截图。附带:没装 Chrome 也能编皮肤。已知差异:iframe 字体是浏览器渲染、截图是 server 上的 Chrome,像素级会有细微不同,所以那颗按钮得留着。
23. **AI 女仆造卡片皮肤下一轮另开 grill。** 这轮只为它预留:字段表与挂点表都是带中文说明的契约常量,提示词将来直接从常量拼。

### 节奏

24. **三步,提交分开、发版合并**:
    1. **地基**:数据契约、皮肤包格式、HTML 与 CSS 清洗器、皮肤渲染器、九个模板拆成内置块、默认皮肤、`cardLayout` v7 与显隐开关的迁移、皮肤库上传 / 导出。
    2. **编辑器**:网格画布、块面板、旋钮 + CSS、HTML 实时预览、派生皮肤可编辑。
    3. **AI 女仆**:另开一轮。
    - **验收门(2026-09-13 开工后改正口径)**:拷问时定的是「默认皮肤画出的 HTML 与现状逐字节一致」,开工发现它与决策 9(内置块加 `data-bn` 挂点)、决策 6(网格容器是新标记)打架 —— 字节只是「升级后卡片不能变样」的代理。改成两层:**自动门**是每个内置块的内层 HTML 剥掉 `data-bn` 属性后与基准逐字节一致(基准 = 开工前打的 23 份快照,`packages/image/src/__tests__/card-baseline.test.ts`);**一次性本机门**是 23 份基准重构前后各出一遍 PNG 做像素比对。上舰卡预期有偏差(等分 12 列做不出 175px 定宽的徽章列),主人看图定要不要加定宽列。
    - 🔗 **2026-09-13 改:不单独发第一步。** 拷问时选的是「每步可发」,理由是把「升级后卡片变样」和「编辑器难用」两种反馈分开;但决策 20 删掉旧编辑器,第一步单独发出去用户就没有版式编辑器可用,要保它可发就得让 v7 版式模型多活一段、迁移做两遍。主人拍板:整个功能做完才发版,第一步的风险靠像素门 + 真机试推单独验,不靠发出去收反馈。
    - 被否:地基 + 编辑器合成一步做。提交仍按步分,第一步门禁绿是第二步的前提。

## 明确不做(拷问中被否决的)

- 文本模版语言 + 编辑器解析器(决策 1)
- 绝对坐标排版(决策 6)
- 场面级多份版式(决策 10)
- 占位符过滤器 / 表达式语言(决策 10、12)
- 整段自由选择器的 CSS、`@keyframes`、`url()`(决策 13)
- 暴露内部 props 当数据契约(决策 14)
- 皮肤自定义旋钮(决策 16)
- per-UP 版式补丁(决策 17)
- 皮肤走拓展市场(决策 2)
- AI 女仆这轮接(决策 23)

## 后果

- `packages/image` 的九个模板从「一种卡一个函数」变成「内置块组件库 + 一个按皮肤 JSON 装配的渲染器」;`block-layout.tsx` 的 `renderBlocks()` 与 `card-layout.ts` 的 v7 模型退役,只留迁移。
- 多出两个清洗器(HTML 子集重建、按块收窄的 CSS)和一份数据契约映射层,都要有「把实现改坏能红」的守卫(参照 `docs/adr/0002` 之后皮肤 CSS 清洗器的教训)。
- 用户可见的变化在第一步为零,第二步才出现新编辑器。
- 认下的代价:每种卡多一层「内部 props → 契约」映射;卡片子系统(约 8200 行)大部分要动。

## 仍未决

- 各项上限的具体数字(每块 CSS 字节、自定义 HTML 字节、块数、卡宽范围、卡片最大高度、资产数量)—— 落地第一步时定,写进契约常量。
- 数据契约每种卡到底暴露哪些字段 —— 从现有模板真用到的字段起,落地时逐张卡列。
- 「最终效果」截图与 iframe 预览的观感差异有多大 —— 真机看过再说。
- 决策 13 的 CSS 口子够不够 —— 主人明说「先做出来看看,不够再改」。
