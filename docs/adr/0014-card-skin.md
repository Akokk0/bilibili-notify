## 背景

dashboard 有皮肤包,AI 女仆能造皮肤包;推送出去的卡片图却只有一套写死在 Vue JSX 里的外观(`packages/image/src/templates/`,九个模板 1621 行),用户能动的只有渐变色 / 字体 / 玻璃 / 背景图,以及一个**一维竖栈**的版式编辑器(`cardLayout` v7:块的顺序、显隐、上边距)。主人要的是:卡片也有皮肤包,且皮肤包能改**布局**;布局编辑器从「只能上下」进到「自由排版」。

主人的原提案:皮肤包 = 一份自定义模版,BN 提供数据并负责渲染;编辑器以「块」(一个 div)为最小单位自由排版,每块可单独编辑含自定义 CSS,块里写什么由用户决定;为此定一门模版语法,编辑器带解析器。

拷问下来改了三处提案的形状(决策 1、3、8),其余照主人的方向细化。

## 决策

### 形态(皮肤包是什么)

1. **正本是 JSON,没有单独的模版语法。** 皮肤包 = `card-skin.json` + `assets/`,编辑器直接读写它;「语法」只剩块内容里的 `{a.b.c}` 占位符。
   - 被否:先定一门文本模版语法、编辑器解析后可视化编辑再存回文本。理由:GUI 与手写文本要**双向往返**,任何 GUI 不认识的写法都会把往返弄断;而且解析器只能住渲染那头(`packages/image`),编辑器再带一个必然漂移。
   - 被否:JSON 正本 + 单向导出成文本。没人真需要。
2. **zip 分发,跟 dashboard 皮肤同规**:面板上传 / 导出 / 复制一份 / 删除,存 `<dataDir>/card-skins/`,zip-bomb 闸与资产上限沿用 `skins/package.ts` 的思路。**不进拓展市场** —— 皮肤是数据不是代码,签名索引与宿主 ctx 是给要跑代码的东西准备的;将来要「皮肤市场」单开索引。
3. **一包覆盖全部七种卡**(live / dynamic / sc / guard / 锐评榜单 / 单人锐评 / 词云),缺的卡种回落默认皮肤。用户换皮肤的心智是「换一套风格」,不是逐张卡换。**锐评榜单、单人锐评、词云三种各自整张是一个固定内置块**,皮肤只管它们外面的卡片外框(词云是页面里跑画布脚本画的,块模型进不去)。
4. 皮肤包记 `schemaVersion` 和它写时依据的**数据契约版本**(决策 12)。对外叫「卡片皮肤」,代码里叫 `card-skin`。
5. **默认皮肤内置只读**,要改先「复制一份」。当前外观必须能用这套格式重写出来 —— 这是格式够不够用的验收门,口径见决策 24。

### 布局(自由到哪一步)

6. **12 列网格 + 可调卡宽。** 每种卡一份网格,每块占「第几行、从第几列起、跨几列」,行高随内容自撑;卡宽是皮肤包字段(现在 `renderCard` 就吃 `htmlWidth`,只是没暴露),有上下限。根块是卡片外框(内边距 / 背景 / 圆角),有自己的挂点与 CSS。
   - 被否:**绝对坐标**(x / y / w / h 自由拖)。卡片内容高度不定 —— 一条动态可能一行字也可能二十行加九图,绝对坐标下内容一变块就互相压住。
   - 被否:一维竖栈 + 块内左右分栏。「自由」只剩一层,主人正是嫌它只能上下。
   - 附带:上舰卡现在特判的「徽章靠左 / 靠右」(`GuardLayout.badgeSide`)在网格下就是普通的一行两列,`GuardLayout` 这一支退役。
    - 🔗 **2026-09-15 重叠成了特性,配套 `grid.z` 层次。** 块的列区间相交是合法的(角标压封面)。事实勘误:这不是「以前控不了」—— 块 CSS 里写 `[data-bn="self"]{z-index:5}` 一直放行;缺的是**不会写 CSS 的人够不着**,而且**画布不解析块 CSS**,留在 CSS 里的话编辑器看到的叠放顺序和出图对不上。所以做成结构化字段,不是第八枚旋钮。**不写就一个字节不注**(0 = 没声明 = 交还给 CSS 与数组先后)。面板与画布都说一句「你俩占着同一片格子」——**是旁注不是警告**:靠 `showIf` 互斥地占同一格是正当用法。
    - 🔗 **画布上的「叠」用深浅说,不写计数**(2026-09-15 主人指着截图说「太粗糙」)。计数说得出「几个」,说不出「谁在上」——而最该被标出来的恰恰是被盖住的那块,它的字正是看不见的那样东西。现在:压着别人的浮起来、底换成不透明的,被压住的往左上错开一条露边。**那几个数与横竖为什么不一样,整段写在 `SkinCanvas.tsx` 顶部**,不在这儿抄第二份。叠放方向由 `stackingOf` 算,**排序规矩与渲染器同一条** —— 两边对不上的话画布画出来的深浅会与出图正好相反,那比不画还坏。被否的两种表达:「选中时成对亮一圈」(最优雅,但静态看不见)、「挪成一枚中性 chip」(改动最小,但说的还是「有」不是「谁」)。
    - 🔗 **同一片格子最多叠三层,只拦拖拽**(2026-09-16 主人:「三重都还好,四重就乱掉了」)。事实勘误:乱的**不是数据,是画布的画法** —— 横向错位封两档,第四层起两条露边重合;出图那头四重一点问题都没有。所以这个数就是**画布画得清的层数**。三条都是主人拍的板:**只拦画布拖拽**(检查器的数字框是精确编辑、皮肤包 schema 放行 —— 手写的四重装得进来,画布上挤但出图没事);**写了 `showIf` 的一个都不数**(否则「四种形态各摆一个块」这条自己写过的正当技巧就被堵死;⚠️ 留了个洞:四个块写**同一个** `showIf` 仍会同时出现四层,编辑器判不出来);**错位不动**(被否:封顶提到三档 24px —— 只是把墙推后一格、五重照样乱,而 24px 开始像「它在哪」的谎话)。拦法是**块停在最后一个合法落点**,与「顶到边就停住」同一条形状;**预览与松手各拦一次**,只拦预览的话甩一下的动量投射会把它送过第四层。相交判据与 `overlappingBlocks` **共用一份**(`gridsOverlap`)—— 两处各写一份的话,拦住的和画出来的会是两回事。
    - 🔗 **2026-09-18 高块用 `rowSpan` 声明自己占几行,画布只画 JSON。** 主人指着截图说「封面差不多占了整体内容的 2/3,画布上却只反映出一行,而头像这么小却反映了两行」。事实:列那一维一直是真的(按真实列宽折算),**只有行在说谎** —— 画布行恒等高,而封面在 JSON 里只占一行。头像占两行不是它大,是它的 `rowSpan: 2` 真写在数据里,名字压底、时间贴顶并排在它右边。**定案:封面、图廊这类高块也照头像的样子写 `rowSpan`**(按画布一行 56px 折算,600 宽的封面 5 行、九图图廊 7 行),后面的块行号顺延;AI 提示词加一句「高块按块高 ÷ 56 写跨行数」。画布一行代码不用改 —— 跨行块它本来就画得出;检查器、画布、JSON 三处说的是同一个数。**出图不受影响**:被跨的那几行空着、高度为 0,像素门 18/18 一致;行距不为 0 的皮肤,跨行块会把中间那几段行距吃进自己身上,是已知行为。**这与 react-grid-layout / Grafana 的模型同形**(块声明 `h`),区别只在我们的行由内容撑、跨行数是近似 —— 声明得不准,画布就退回等高,不会更差。
    - 🔗 同日**走了一段弯路再撤回**,记下免得重走:先做成「画布从预览量块高、行高按真实比例连续拉伸」,主人看图指出**同一行里叠着的矮块被 `stretch` 撑成大框**(主播名与封面同在 r1,30px 的名字拉成 300px 的空框、把封面整个挡住);改成「格子恒高、高块多占格」之后画布上多出一个 JSON 里不存在的「格」,行号列只有一个 r1、看不出封面顶了五行,主人要「像头像一样跨行」。两版都要画布跟预览耦合(切场景重排、旧框迟到回调、换卡种先退回等高),数据驱动之后这些全没了。七个提交存在本机备份分支里,没进主线。
    - 🔗 同日主人问过「一行能不能切成几份」,拷问后拍板不加:子行在 CSS 里没有原语,翻译出来就是「N 行 + `rowSpan: N`」,加了做不了任何新事;且 `split` 挂在行上,同一行三种切法写不出来,比现在更弱。**「叠在真卡上编辑」也否了**:`showIf` 收起的块在真卡里没有盒子、空格高 0 接不住落点、真卡还被缩放。
    - ⚠️ 已知局限:被完全盖住的块在画布上**点不中**(那条露边点得到,但不算治好);**没有反向的「置底」**——要把 A 压到 B 下面,得去抬 B 的层次。
7. **块分内置与自定义。** 内置块渲染逻辑不动、用户只能排版 / 显隐 / 挂 CSS;自定义块用户自己写内容。理由:动态卡正文 567 行逻辑覆盖 14 种动态类型,用户用占位符拼不出来。
8. **内置块复合与原子并存。** 现有 14 个复合块照旧(默认皮肤用它们,升级零跳变);另加原子块:头像、名字、时间(三种卡的「头部」都是这三件套)、徽章、分割线。皮肤要么用复合块,要么用原子块自己拼,都合法。
   - 被否:维持现有粒度。「头像单独放左栏、名字放右上」做不到,自由排版在头部这块名不副实。
   - 被否:全部拆到原子。正文与数据行没法原子化,拆了也没人分开摆。
   - 🔗 **2026-09-18 主人拍板:默认皮肤改用原子块拼,再补一批原子块。** 起因是主人看编辑器:「默认皮肤的布局沿用的是之前的竖排,应该拆分得更细,用户才有更多自由调整的空间」—— 用户多是从默认皮肤复制一份再改,默认皮肤里只有复合块,能挪的就只有整行。事实勘误:上面「正文与数据行没法原子化」只对了一半 —— 直播数据区早在决策 16 的 🔗 里拆成了三件;动态正文里话题 / 转发框本来就是分开的数据,文字与视频卡 / 图廊是构建时才拼进同一个 `body`,给呈现态加两个字段(文字、媒体)就分得开,`body` 与复合块 `content` 原样保留。**新补的原子块**:动态卡的话题、正文文字、视频卡或图廊、转发框、转发 / 评论 / 点赞三个数;醒目留言卡的金额、时长胶囊、「SC to」那一行;上舰卡的用户名胶囊、主播胶囊。**复合块照旧留在目录里**,派生皮肤照用。**外观允许小幅变化**(主人选的,被否的是「必须逐像素一致」):不为复刻每个像素去写难懂的 CSS,升级后默认卡片可以有几个像素的出入,换来默认皮肤好读好改。连带一处:「旧默认版式折出来 = 默认皮肤」那条铁律不再成立,所以把拆之前那份复合块版的默认皮肤**原样冻成「旧默认」**,迁移折派生皮肤时拿它当底子、像素验收门与块内层字节门也改认它 —— 改过版式的存量用户,派生皮肤照旧与原来的卡一模一样;没改过的留在默认皮肤上,跟着新版式走。**落地结果**(同日本机出图,新旧默认对着示例数据比):直播卡三个场面与醒目留言卡**逐像素一致**;动态卡四个场面只有转发 / 评论 / 点赞那一行左右挪了几个像素;上舰卡两颗胶囊往右下挪了约 10px。做法上两处要说明:直播卡与动态卡两侧各加一列定宽(左边那列就是头像列,名字才落回原位;右边补一列同宽保持对称),头部三件的 wrapper 做成 flex(行内元素单独放进块容器会被行盒撑高)。
   - 🔗 **2026-09-18 主人拍板:复合块整个退役,目录里只留原子块与天生不可拆的块。** 起因是主人看编辑器截图:「我觉得应该把内置块去掉,只留下原子块」「封面图应该拆成封面原子 + 右上角直播状态标签覆盖」「视频卡 / 图廊首先它不够原子,这完全是个内置块了,有封面、右下角时间标签、标题、简介、播放量信息;其次它也没有分场景,视频就是视频,图廊就是图廊,我们都分了不同场景,这里却合并了」。**这条推翻本决策正文的「14 个复合块照旧」,也推翻上面被否的那条「正文与数据行没法原子化」** —— 拆到今天,真正拆不动的只剩四种。查下来目录里的块分四类,处置各不同:
     - **A 只是漏标**:直播标题、简介、上舰的文字信息、醒目留言的留言 —— 本来就是一个容器包一段文字,补上原子标记即可,渲染零改动。
     - **B 该拆**:直播卡封面 = 图 + 绝对定位的状态角标 → 拆成**封面**与**直播状态**两块;动态卡的「视频卡 / 图廊」→ 视频那半拆成**视频封面 / 视频时长 / 视频标题 / 视频简介 / 播放·弹幕数**五块,**图廊独立成一块**。两者靠 `showIf` 互斥占同一片行(判据用契约里已有的 `dynamic.hasVideo` / `dynamic.hasPics`)—— 预览场景早已分开,块也跟着分开。
     - **C 天生一块**:转发框(里面是整张内层卡)、图廊(图的张数是动态的)、附加内容(预约 / 商品 / 通用 / 关联视频四种形态结构各异、字段不在契约里)、三种不可编辑卡的整卡块。这几个保持非原子 —— 主人拍板「这种不好拆的还是留做内置块」。
     - **D 删掉**:八个复合块(直播的主播信息 / 直播数据、动态的头部信息 / 动态正文 / 互动数、醒目留言的金额 / 发送者、上舰的姓名)从目录与渲染器一起删。
   - 🔗 **覆盖层与容器一律用网格 + CSS 表达,不引入「隐形底板块」。** 角标(直播状态、视频时长)与被覆盖的块**占同一片格子**、`z` 更高,靠 `align-self` / `justify-self` / `margin` 定位;视频卡那圈灰底圆角容器由标题 / 简介 / 播放数三块**各自带一段灰底**、首尾块分担上下圆角拼出来 —— 做成空的底板块的话,画布上会多出一个看不懂的隐形块。收起简介时,标题到播放数之间仍是 10px,与今天无简介时一致。出图**允许小幅变化**(沿用同一口径):DOM 从嵌套容器变成网格兄弟,边距与圆角靠 CSS 复刻,几个像素的出入不倒回重做。
   - ⚠️ **三处删了不报错、只在真机露馅的**(动手前查实,守卫要先立):① 锐评榜单 / 单人锐评 / 词云三张卡的皮肤定义**只存在于旧默认皮肤里**,出厂默认靠展开它继承 —— 旧默认一删这三张卡静默消失,而四种可编辑卡的门一条都不会红;② 旧模板按**字符串**去块表里取渲染器,删掉一个复合块没有任何类型错误,只会运行时少画一块;③ 上舰卡的三个原子块靠旧版式的「徽章靠哪边」决定对齐,**皮肤路径也走这里**,不是旧模板残留 —— 退役旧版式时这处要改成由块自己的列号决定。
9. **内置块带内部挂点契约表**(「作者行.头像」「统计行.图标」……),可分别挂 CSS,跟 dashboard 的 `SKIN_CSS_HOOK_MAP` 同哲学:hook 名是公开 API 只增不改,真实 class 是实现细节。不然「换个头像圆角」都得整块重写成自定义块,内置块形同虚设。
