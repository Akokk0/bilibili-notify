# ADR-0015:AI 做皮肤 —— 编辑器写一段,工坊做整套

- **状态**:2026-09-16 经 `/grill-me` 七轮 28 格拍板。**第一片(dashboard 清场)2026-09-17 已落地**;第二片(编辑器那口)同日开工,第三片未动。三片按序做:dashboard 清场 → 编辑器那口 → 工坊那口,**三步全写完再一起发**。
- **记录方式**:当日拷问整理,**非追认** —— 决策与理由都出自拷问现场。
- **影响面**:`apps/web/src/pages/cards/SkinInspector.tsx`(那枚禁用的钮)、`apps/server/src/card-skins/`(新增 AI 那一层)、`apps/web/src/components/ai-chat/`(工坊多一档选择器)、`apps/server/src/routes/ai.ts`(工具与 systemPrompt 的互斥三元要拆开才容得下第二支写工具)、`apps/web/src/pages/skins/SkinSection.tsx`、`SkinEditor.tsx` 与已删的 `apps/web/src/services/skin-pack.ts`(决策 27 的清场)
- **依赖**:ADR-0014(卡片皮肤的格式、编辑器与清洗器)、ADR-0002(dashboard 皮肤的 CSS 方言)
- **取代**:ADR-0014 决策 23「AI 女仆造卡片皮肤下一轮另开 grill」—— 下一轮就是这一份
- **形态**:这是一份**主题 ADR**(见 `README.md` 的「一份 ADR 该多大」)。两口 AI 咬得很紧 —— 共用提示词的拼法、共用清洗器那道门、共用「皮肤只在 BN 里做」这条口径,拆开就读不懂。配套那两条硬规矩照样管着:**这个主题做完之后的新决策另开号**、**销账即删**。

## 背景

ADR-0014 决策 23 把「AI 造卡片皮肤」整个推给下一轮,第二步只在每个 CSS 文本框旁边**摆了一枚禁用的钮**(`title` 写着「下一轮才接上」)。主人当时的原话是「大部分用户可能都不会写 CSS,让用户能直接请 AI 帮忙」。

dashboard 皮肤那边已经有三条 AI 路可以借:编辑抽屉里的**一键改写**(`POST /api/skins/:id/ai-edit`)、侧栏的**皮肤工坊**多轮聊天(`create_skin` —— 全仓唯一一把会写盘的 AI 工具)、以及**复制提示词粘给外部 AI** 再把 JSON 粘回来。这一轮要定的是:卡片皮肤借哪几条、怎么借,以及第三条还该不该存在。

## 决策

### 分工与口径

1. **两口,各管各的。** 编辑器那枚钮**只写它自己那个框**的 CSS(块 CSS 一枚、外框 CSS 一枚);**整套皮肤归 AI Chat 的皮肤工坊**,它既能从零新建、也能加工已有的。理由是按钮的位置本身就在说话 —— 一个坐在「块 CSS」框旁边的钮,按下去却重写了整套皮肤,没人预期得到。
2. **皮肤只在 BN 自己的 AI 里做。** 两种皮肤都**不留**「复制提示词粘给外部 AI」那条路:卡片皮肤不新开,dashboard 那条现有的也收掉(决策 25)。

### 编辑器那口(第二片)

3. **作用面 = 那一个框。** 不碰块的增删、位置、`showIf`,也不碰别的块。「不会写 CSS」这条理由虽然同样适用于排版,但**扩到结构就必须回答「怎么局部改而不整份重吐」**,那是 dashboard 至今没解决的问题(见决策 12 的理由),不值得压在这一片上。
4. **按了才弹**一个小浮层(输入框 + 送出),不做常驻 textarea。检查器只有 380 宽,里面已经排着挂点清单、七枚旋钮、这枚钮、CSS 框、字节计数器;而这功能不是每次编辑都用。
5. **给 AI 的上下文**:整张卡的**结构轮廓**(每块一行)+ **外框 CSS** + 这个块的**挂点表** + **已声明的旋钮**(只读)。**不给别的块的 CSS 正文** —— 外框定了字体与底色、直接影响这块怎么写,结构轮廓很便宜,而隔壁块写了什么圆角对「写这一块」没有用,纯占 token。
6. **旋钮只读不写**:AI 可以在 CSS 里引用已声明的 `var(--bn-knob-<key>, …)`,但**不能声明新的**(决策 15)。皮肤作者既然开了「主色」那枚钮,就是要这套皮肤的主色统一走它;AI 写死一个值等于在他的设计上开个洞。而「引用已有的」和「发明新的」是两回事,前者零风险。
7. **流式写进框里**,右边预览跟着变 —— 那正是这一口的卖点,也正好躲开 dashboard 那条一键改写的坑(它把 `onProgress` 丢了,几分钟界面静止、还不能取消)。**不给「改前/改后」对照**:对不会写 CSS 的人,diff 是看不懂的东西。
    - 🔗 **2026-09-17 开工前拍板两条**(主人):
        - **逐条规则流进框,不逐字**。预览是「停手 400ms 才把整份草稿送去重渲染」,逐字流的话计时器一直被重置,停顿时送去的又常是半条规则,预览区只会闪警告;逐条追加时,框里每一刻都是完整的 CSS。
        - **能取消,并真断上游**。弹层里一颗「停」,点了就停下、还原成动手前的原文,服务端同时断开到模型的请求 —— 不然白烧的是用户自己的 key。为此 `generateRaw` 要多两个口:正文分片转出、外部取消信号(原来只报字数,也收不了信号)。
    - **框里最后留的是 AI 的原文**(去掉代码围栏),不是清洗后的版本:清洗器会把它重新序列化成一行,人没法读。削掉了什么,照旧由预览与保存时的 warnings 报(决策 26)。
8. **一颗一次性的「还原」**,只记住 AI 动手前那段原文。这是硬要求不是锦上添花 —— **编辑器没有撤销栈**,不给还原的话,用户手写的那段会被当场覆盖且找不回来。
9. **失败**:产出过不了清洗器就带着错误列表**自动重试一次**,二败报错(照 dashboard 的 `runSkinAiRound` 那条纪律)。
    - 卡片 CSS 的清洗器**只在解析不了、或超出字节上限时整份拒收**,其余违规都是逐条削掉并记进 warnings。所以触发重试的只有前一种,后一种走决策 26。
10. **没配模型时按钮在按之前就禁用**,`title` 说清去哪配。让人填完需求、等一圈、再被 503 拒绝,是最气人的那一种。
    - 🔗 **2026-09-17 判据定为「当前模型实例的 key 与地址都填了」**(主人拍板):与 dashboard 的「让女仆改」、以及服务端建 AI 实例时用的是同一条;「智能女仆」总开关不管这颗钮(那是聊天的闸)。
    - **默认皮肤里这颗钮也禁用**,提示先复制一份。默认皮肤的草稿改得动但存不了,「复制一份」复制的又是出厂那份而不是草稿,让 AI 在上面写等于白烧 key。

### 工坊那口(第三片)

11. **不加第三档独立入口,加一个选择器。** 侧栏那颗「新建皮肤工坊」文案不变,进去之后在**空态**摆一条 `TabBar` 选「dashboard 皮肤 / 推送卡片」—— 形态照日常聊天里那条**人格选择器**(同样只在空态摆、同样开口即锁)。⚠️ 被否:给 `AiChatMode` 加第三档 `"card-skin"` 并在侧栏加第三颗按钮 —— 用户按下「新建皮肤工坊」时还没想好做哪种,先让他选比先让他认两颗按钮省事。
12. **开口即锁**(面孔锁定,与人格同规);**历史会话缺这一格就当 dashboard 皮肤**,沿用现成的「按工具痕迹反推」。
13. **写工具四把,切在「卡」和「块」两级**:`write_card(kind, {width, columns, css, blocks})` 整张卡一次写完 · `set_block(kind, id, {grid?, css?, html?, showIf?})` 改一个块 · `remove_block(kind, id)` · `set_skin_meta({name, author, description})`。一个字段一把工具会碎到十几把、模型选错的面很大;一把大工具又退回整份重写。
14. **读工具三把,与写对称**:`list_skins()` 给库存清单 · `read_card(id, kind)` 给**这张卡的摘要**(每块一行:id、类型、行列跨度、有没有 `showIf`、CSS 多少字节)加外框 CSS · `read_block(id, kind, blockId)` 才给那一块的正文。摘要与正文**必须分两把** —— 合成一把的话,每读一张卡就把所有块的 HTML 全拖进上下文。
15. **`list_skins` 是工具,不是开局塞进 system 的清单**(主人拍板)。理由:用户进工坊**不一定是要改,可能是要新建** —— 开局就塞清单,对新建这个主场景是纯浪费。
16. **新建也走工具,粒度「一张卡一次」。** 一次吐七张卡的 JSON 就是整份重写的老路;一张卡一次,每次几个块,模型写得准,中间还能报进度。没提到的卡种不写,自然回落默认皮肤(ADR-0014 决策 3)。
17. **资产与旋钮声明这轮不给 AI。** 资产要用户在聊天里贴图才有(是另一条链);旋钮声明会让 AI 同时想「这套长什么样」和「留哪几个钮给人拧」,分心。两者都能下一轮单独加,不挡这一轮。
18. **改已有皮肤 = 先复制一份再改,原件一个字节不动**;同一轮对话里后续都改这份新的,不会每说一句堆一套。这跟 ADR-0014 决策 5(「默认皮肤内置只读,要改先复制一份」)是同一个心智,用户本来就熟这个动作。**必须有这条** —— 卡片皮肤库既没有版本也没有撤销,「改到一半发现还不如原来」在 dashboard 那边不存在(它的工坊只新建),在这儿是真风险。
19. **有视觉能力就把出的图喂回给模型自查,但只说不动手。** 仓里已有现成判据(主模型 `supportsVision`,或单配一个视觉副模型),看得见就给、看不见就跳过,**绝不因此报错**。⚠️ 被否:让它看完自己接着改 —— 自动循环烧的是用户自己的 key、他还看不见它在折腾什么;而且「它觉得不好、用户觉得挺好」是常事,用户回一句「那你改」成本极低。
20. **给人看走 HTML 不走截图**:那份卡片是完整独立的 HTML(图与字体都内联成 data URL),塞进 sandbox iframe 就能看 —— 与 ADR-0014 决策 22 同一条路,不需要 Chrome。
21. **直接落盘,但 `activate` 不给 AI。** 一套皮肤要反复调,卡在「确认」上会让多轮对话每轮都顿一下;但**换上**是会立刻改变真实推送出图的动作 —— dashboard 换肤只是面板变样,卡片皮肤换错了是发到群里的图变样。这两件事的代价不对等。
22. **换上那一下给人做**:聊天里工具结果下面一颗「换上这套」,点了才换。路收在原地,而「点」这个动作仍然是人做的,决策 21 的理由一个字没松。
23. **一轮最多碰 2 套皮肤,套内的工具调用不限次。** 工具是逐块的,「做一套」可能就是七次 `write_card` 加若干次 `set_block`,按调用次数封顶会卡死正常用法。真要兜底跑飞,靠现成的总工具轮数那道闸。

### 两口共同

24. **不带人格。** 这是工具口不是对话口:用户按下去要的是一段能用的 CSS,人格既占提示词又让模型分心,而产出要被清洗器判、语气帮不上忙。与 dashboard 工坊的 `persona: false` 同规。
25. **规则从契约常量拼进提示词,不手抄。** ADR-0014 决策 23 预留的东西已经备齐:`CARD_SKIN_BUILTIN_BLOCKS`(每块带中文 label 与挂点)、`CARD_SKIN_FIELDS`、`CARD_SKIN_FRAME_HOOKS`、`CARD_SKIN_LIMITS`,加上 CSS 属性白名单与 HTML 标签白名单。手抄的下场是契约一改提示词就悄悄漂。
    - ⚠️ **2026-09-17 改正**:上面「CSS 属性白名单」那半句写错了。卡片皮肤的 CSS 在 ADR-0014 的一步半就从属性白名单改成了**黑名单**,那两个白名单常量此后一直没人读(已删)。拼进提示词的应是清洗器**真在执行**的规矩:执行面黑名单、值里禁用的写法(`url(` 一族)、`position` 的取值、挂点表、字节上限,**从清洗器自己的常量导出**,不另抄一份。HTML 标签白名单只有工坊那口用得到。
26. **清洗器削掉了什么照说**,走现成的 `warnings` 管子 —— **AI 写的和人写的走同一条门**,不给它开后门。规则进提示词是为了少撞墙,不是替代那道门。

### dashboard 清场(第一片)

27. **删掉 `SkinGuideModal` 与 `buildSkinPrompt`**(复制提示词 → 粘给外部 AI → 粘回 JSON → 前端组包)。**「上传皮肤包」那条独立的路不动** —— 别人做好的 zip 照旧传得进来,皮肤分享不受影响。副标题里「或让任意 AI 帮你做一套」要跟着改,CHANGELOG 记 `Removed`。
    - 除了口径统一,还有一条硬理由:`buildSkinPrompt` 是**第三份**从契约常量拼的提示词,而它**没有任何真机用户盯着** —— 契约一改它就悄悄漂,漂了也没人报。
    - 认下的代价:**没配模型的用户从此做不了 dashboard 皮肤**(只剩内置四套与别人分享的 zip)。门槛抬了,这是换口径统一付的价。
    - **「制作皮肤」那颗钮整颗删掉**,副标题改成指路侧栏的「新建皮肤工坊」(2026-09-17 主人拍板)。⚠️ 我提的「改成一点就进一场新工坊的按钮」没被采纳 —— 工坊的入口仍然只有侧栏那一颗。
    - **挂点清单挪进编辑器**:它原来**只写在被复制出去的提示词里**,删掉之后界面上一个挂点名都看不到,而「自定义 CSS」那一折还写着「挂点见制作引导」。现在那一折就地列出全部挂点,名字取契约的挂点表、悬停给契约里那句说明(2026-09-17 主人拍板)。

### 节奏与验收

28. **顺序:dashboard 清场 → 编辑器那口 → 工坊那口。** 先做编辑器那口是因为它小、能独立验收,而且**先把「规格表从契约常量拼进提示词」这套地基验一遍** —— 那是两口共用的东西,编辑器只用到 CSS 那一小半,错了好查。工坊那口要动模式枚举、还要先拆开「工具与 systemPrompt 的互斥三元」,摊子大得多。
29. **验收门两条,都是真机** —— AI 这种东西单元测试只钉得住「管道通不通」,钉不住「它写出来的能不能用」:
    - 编辑器那口:拿一个**空**的块 CSS 框,说一句「毛玻璃、圆角大一点」,产出要**过得了清洗器**且右边预览真的变了;
    - 工坊那口:**从零做一整套**卡片皮肤(不是改),七种卡各出一张图。与 ADR-0014 一步半那条验收门同一个形状。
30. **三步全写完再一起发**(主人拍板)。⚠️ 我提过反对并被否:ADR-0014 决策 24 那句「发版合并」的原始理由只管第一步(第一步单独发出去用户没有版式编辑器可用),而第二步发出去是完整可用的;主人听完仍要全部写完再发,照办。

## 明确不做(拷问中被否决的)

- **外部 AI 粘贴那条路** —— 两种皮肤都不留(决策 2、27)。卡片皮肤那边本来可以只给编辑器那口留(要的就是一段 CSS,粘贴可行),但第三步已经两个产品面,再加一条路会拖慢;没配模型的人,引导他配一次(终身受用)比教他来回粘贴更直接。⚠️ 真有人反馈随时能捡回来,提示词那半本来就是共用的。
- **AI 声明新旋钮**(决策 6、17)。
- **AI 传资产**(决策 17)。
- **AI 自己 `activate` 一套皮肤**(决策 21)。
- **AI 看完自己出的图接着自己改**(决策 19)。
- **编辑器那口做整套皮肤**,或扩到块结构(决策 1、3)。
- **给 `AiChatMode` 加第三档 + 侧栏加第三颗按钮**(决策 11,改用空态选择器)。
- **皮肤页放一颗直达工坊的按钮**(决策 27,只在副标题里指路)。
- **整份重写**(决策 13,改用工具逐块)。dashboard 的 ai-edit 至今是整份重写,靠提示词里一句「没被要求改的字段一律原样保留」;卡片皮肤含每块的 HTML,整份重吐等于「改个圆角把所有块的 HTML 全重写一遍」,等得久、被清洗器拒收的面也更大。

## 后果

- AI Chat 那一侧要动结构:`ChatFace` 多一格、空态多一个选择器,而**「工具与 systemPrompt 的互斥三元」目前只容得下一支写工具**,得先拆开。
- `apps/server/src/card-skins/` 多出 AI 这一层(提示词拼装、工具定义、产出校验),但**清洗那道门是现成的** —— `sanitizeScopedCss` 两套皮肤早已共用,`sanitizeCardBlockHtml` 也在。
- dashboard 那边少一个弹窗、少一份提示词;皮肤分享不受影响。
- 皮肤库会因「改 = 复制一份」(决策 18)堆出几套 —— 跟用户手动复制一份是一样的,删得掉。
- 没有视觉模型的用户,工坊里 AI 自查那一档不存在(决策 19),功能其余部分照常。

## 仍未决

- **资产与旋钮声明**这轮不给 AI(决策 17),等真有人要再开:资产要用户在聊天里贴图、是另一条链,旋钮声明要先想清楚「谁来决定哪些该开成钮」。
