# ADR-0052:累计视频播放量按需采集并与粉丝曲线共用图表

- **状态**:2026-11-16 主人拷问定案。
- **影响面**:来源读数、统计设置与时序、统计页创作者图表。
- **依赖**:ADR-0021 的来源中立接口、ADR-0027 的统计总开关。

## 背景

Issue #59 希望查看播放量走势。当前资料刷新不含创作者累计视频播放量，已确认的 B 站接口需要额外请求及登录态；逐条拉取作品既增加请求，也不能可靠地代替创作者累计值。

## 决策

1. 指标为创作者全部视频的累计播放量，包含旧视频继续获得的播放。首版由 B 站实现中立来源读数能力；未实现的来源显示暂不支持，不提供开启入口。
2. 在现有创作者粉丝总量图上增加 Picker，切换粉丝总量与播放总量；时间范围沿用近 7、30、90 日，粒度沿用小时与日。
3. 播放量统计出厂关闭。关闭时图表中央说明采集需要额外请求，并提供范围选择及开关：仅当前创作者，或全部支持的创作者。
4. 全部表示全局默认，今后新增且支持此能力的创作者也继承；单个创作者可以覆盖该默认。统计总开关与订阅停用仍优先阻止采集。
5. 开启时立即采一次，此后每小时一次。关闭停止后续采集，保留历史；重新开启后续记，不补采关闭期间的历史。
6. 使用独立采样时序，不重复上报作品或进入推送判新。小时、日桶取最后一次有效采样；缺测保留空值，图表桥接缺口仅作估算展示。
7. 未登录、风控、超时及缺少有效累计值时回报失败，不将缺失值写成零。宿主负责串行、超时、取消与采集生命周期。

## 明确不做

- 不默认增加所有订阅的接口请求。
- 不逐条请求视频、不汇总近期视频冒充累计播放量。
- 不提供半小时粒度，也不恢复不存在的历史采样。
- 不在核心或面板按平台名分支，不假定所有来源都有此指标。

## 后果

用户开启后会增加按创作者计的请求与少量时序存储。曲线从开启后才有真实记录；上游登录或风控会留下缺口。此时序与粉丝时序一样，不属于 `PostEntry` / `LiveSessionEntry` 附加字段的“不多发请求”约束，既有附加字段规则保持原义。
