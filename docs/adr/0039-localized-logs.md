# ADR-0039：日志纳入多语言

- **状态**：2026-11-07主人要求纳入第5期，并随日志输出整理实施。
- **影响面**：主程序、内置集成、工作区业务包及随仓拓展编写的运行日志。
- **修订**：ADR-0037决策13中「日志不翻」；开发版专属调试面板仍按原定范围。

## 背景

原多语言范围排除了日志。主人希望日志也能使用当前语言，同时整理输出中不明确、重复及不规范的表达。现有日志器已有等级过滤、模块名、参数保留与统一脱敏，不需要另建出口。

## 决策

1. 日志中由BN编写的人类可读说明纳入译文，写出这一条时取当前语言。启动早期尚未读取语言设置时使用现有简中回落；切语言只影响新日志，盘上/内存中的历史整句保持原样。
2. 日志采用平实的诊断措辞。集成只拿到语言、不拿口吻，继续经`ctx.i18n`与`ctx.logger`；核心和宿主沿各自既有取字及日志入口接线，不将第三方拓展译文纳入核心字典。
3. 错误码、事件标识、模块名、字段路径、ID与原始上游诊断属于诊断数据，保持原值；用户自填名字、消息内容不翻译。对外协议字段、close code与供协议诊断的固定close reason不随显示语言改变。
4. 本轮整理先解决同一状态在多层重复记录、说明不清、日志正文混入数据及只剩`String(error)`丢失错误上下文的问题。日志等级、保留期、脱敏与入口过滤继续沿用既有规则；任何等级调整按具体场景核对，不批量升降级。

## 明确不做

不翻历史归档，不猜测翻译第三方错误或插件上报内容，不新建日志出口，不改协议或持久日志形状，不以这轮译文整理修改运行状态或重试策略。

## 后果

运行期切语言后归档可能混有不同语言，按原始写入时间保留。需要按模块核对调用、错误上下文与译文，不能对日志参数整体忽略后宣称完成。日志片级进度写在第5期计划。
