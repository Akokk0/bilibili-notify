# ADR-0008:通用 devtools —— 造状态与造事件

- **状态**:**已实现并 push**(2026-09-06 经 `/grill-me` 15 问拍板、同日八片全部落地 19 个 commit;09-07 `/code-review` 26 条全部处置完,随 v0.10.1 发出)
- **记录方式**:⚠️ **事后追认** —— 据定案记录与已落地的实现整理,非当时原文。
- **影响面**:`apps/server/src/devtools/`、`apps/web/src/devtools/`、`apps/contract/src/devtools.ts`、`packages/ui` 的 `DockPill` / `DockPanel`;另有五个包各多开一个公开口
- **怎么用**:`docs/agents/devtools.md`

## 背景

BN 的大半功能要**等真事发生**才能验:开播、下播、上舰、有人贴链接、更新有新版、登录掉了。开发时要造出这些状态,靠的是手动改配置 + 等 + 运气。

主人先要了个只管更新的 devtools,看完说 UI 不满意、要「完善的、不只针对更新」的 —— **拍板从头来,一行旧代码不复用**。

## 决策

### 门

1. 🔴 **门 = 载荷版本号是开发版**(`isDevBuild`),**alpha 也不给**;前端半边看 `import.meta.env.DEV`。
2. 🔴 **不用环境变量。** 环境变量能在生产镜像里被设上 —— 上一版 `BN_DEVTOOLS=1` 那套主人踩过,而且提示还误报。
3. 🔴 **审查后又加了一道**:`0.0.0-dev` 是仓库常驻值、版本号读不出来的兜底也是 `"dev"`,**凡是没走发版流程的构建都自认开发版**;而 `test-image.yml` 构建前不同步版本却**公开推 `:test`** —— 那个镜像一直带着能删历史、停引擎、退进程的 `/api/dev`。于是再加一道**构建产物身上不可能成立的门**:`import.meta.url` 以 `.ts` 收尾。
   ⚠️ **同一个 `isDevBuild`,更新服务那边敞开是安全侧(开发版不查更新),这里敞开是危险侧。别再把这两处判据合并。**
4. 🔴 **最终形态:构建产物里结构性地没有 devtools**(主人 09-07 拍板「devtools 不能打进正式版,只能是开发版源码运行」)。`vite.config.ts` 的 stub 插件在两种构建里把指进 `src/devtools/` 的 import 换成恒回 null 的 stub;构建后再 `grep` 一遍自检(**插件拆掉真会红,验过**)。运行期那两道门保留为源码运行时的兜底。

### 形态

5. **两层都要**:造状态(只换面板看的那份)+ 造事件(整条链路真跑)。
6. **副作用默认真发 + 可截流。** 截流期间历史照记 `delivered` **不打标**(不为调试改 history schema),面板截流列表当对照 + 一个「清掉截流期间历史行」的按钮。
7. **入口 = 底边 dock**(主人主动指定的形态,推翻了我先前的抽屉方案):左下角玻璃药丸 + 底边升起的整宽面板。**UI 要好看、走组件库、贴整体风格。**
8. **注册表中央化,声明类型住 `apps/contract`,分两半合一份**:服务端经 `/api/dev` 列举 / 执行,前端半边同形状在浏览器跑,面板合并两张表。**参数 schema 驱动**,面板照 `params` 画控件、**不必认识每个场景**。

### 注入高度

9. 🔴 **在既有边界上套装饰器,引擎一行不动**:直播塞帧包 `connectLiveRoom`、动态并进传给引擎的 `api`、入站直接调 `handleMessage`、推送出口包 `PlatformAdapter.send`、总线事件**直接 `bus.emit`**。
10. ⚠️ 最后那条是**发射不是转发** —— 没有碰 MessageBus 那条「绝不写 bus 与别的事件通道之间的转发器」的铁律。
11. **时间只做「现在就跑」+ 单点覆盖**(免扰「当作现在是 xx:xx」、计时器提前到期);**假时钟不碰**,留独立议题。

## 明确不做(拷问中被否决的)

- **用环境变量当门**:见决策 2。
- **复用旧的那五个提交**:主人拍板从头来,旧代码留在本地分支。
- **假时钟**:见决策 11。
- **建 bot 向导 / 清理类场景 / WS 重连与皮肤浮条**:定案时就砍了,后期按需加。
- **为调试改 history schema**:见决策 6 —— 截流用对照列表而不是给历史行打标。

## 后果

- 🔴 **假状态只由 devtools 收摊,真动作(check / download / rollback)只转发不清、且响应也回装饰后的状态。** 因为面板每次打开都会自动 check,顶掉的话刷新一下注入就没了,「打开面板弹有新版卡」永远测不到。
- **devtools 的查询要 `refetchIntervalInBackground: true`** —— react-query 的 `refetchInterval` 窗口失焦就停,而人盯着终端时面板正在后台。
- **新场景要先问「它的消费点是查询还是时机」**:靠「作废所有查询」看不到的那种(只在某个时机才出手的),得单独登记补做。主人首报的「注入 available 却不弹更新卡」就是这个。
- **五个包各多开了一个公开口**:`observeLiveConnections` / `quietHoursNow` / `repushNow` / `healthCheckNow` / `detectNow`。发版 CHANGELOG 不必写 devtools(dev-only),但要提就提这几处。
- **`/code-review` 撞额度时按区域切 finder**,别让每个 agent 读全量 diff。
- 🔴 **守卫写完必须把实现改坏跑一次** —— 隔离守卫那次就只钉了形状(只钉 `from`,副作用 import 与裸动态 import 都漏)。
