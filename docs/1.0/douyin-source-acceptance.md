# 抖音订阅源验收（2026-11-13）

[首版范围](../adr/0047-douyin-source-parity.md) · [第六期片表](phase-6-plan.md)

先用公开的 `create-bn-ext@0.1.0-alpha.3` 创建独立工程（`akokko.douyin`），从来源公开入口验证，再移到 [extensions/douyin](../../extensions/douyin)（官方 ID 为 `douyin`）。两者使用同一个宿主契约，身份与凭据按 ID 隔离。官方版按普通拓展安装，不内置于 BN 核心。尚未上架市场。

| 操作 | 已验证 | 尚未验证 |
| --- | --- | --- |
| 系统 → 账号 | 真实抖音返回可扫码的二维码，未扫描时正确过期。持有人扫码后，轮询收到安全拒绝码 2156，手机 App 未显示安全消息。已补齐首个二维码前的首页会话初始化、响应令牌续传，并移除要求查看 App 消息的提示。模拟平台验证扫码确认、二次验证、输错重试、恢复、退出、过期及来源间的凭据隔离；内置浏览器验过账号页。 | 2156 的具体触发原因和修复后的真实扫码仍待确认，尚未完成真实登录及带凭据的恢复。若平台要求短信或网页验证，由持有人在本机完成。 |
| 查找与订阅 | 用固定响应验证作者主页、分享短链、抖音号及昵称候选。真实匿名搜索触发平台验证，面板报告暂不可用，不显示为空结果。 | 登录后的真实昵称候选、作者资料和作品列表。 |
| 作品和群聊 | 固定响应验证视频、图文、翻页、置顶、去重、重启基线和群里解析未订阅作者的作品；旧账号的迟到响应不能触发推送。匿名解析[人民日报的一条公开视频](https://www.douyin.com/video/7627083063436053769)时，详情接口实际返回 HTTP 403，拓展报告签名被拒（`douyin.signature`）。 | 带凭据的真实作品内容、图片与分享短链。 |
| 直播 | 固定响应验证首次观测、开播、直播、下播、重复观测及暂时失联。宿主沿用同一场次链路。 | 真实账号下可以核实的在播、下播变化。 |
| 宿主端到端 | 实际安装官方格式 ZIP；外部平台响应与推送接收端用本机夹具。验证登录、资料、卡片内容、四条送达历史，以及两条作品和一场直播的统计。 | 未向真实 IM 群发送验收消息。 |
| 官网浏览器先行验证 | 独立 Chrome 临时上下文扫码及官网账号确认成功；Cookie 只在内存交给现有拓展后，HTTP 账号校验成功，昵称搜索仍遇验证。第二轮在官网页面仅传搜索业务参数，返回 10 条用户结果且无正文验证指令；保留旧签名／环境参数的对照请求失败。会话已关闭，凭据未落盘。 | 这是本机有界面的独立原型。尚未实现宿主正式浏览器契约、来源候选转换及后续取数，也未验证无头模式、重启恢复或远程人工验证；不能视作系统账号页和订阅源已经可用。 |

按主人要求回到 HTTP 路线后，先修正昵称搜索的签名策略，再补登录前的首页 nonce 协商。签名回归的合成向量由冻结官网脚本产生，运行拓展时不执行网页脚本。匿名实测两次首页均为 200，第二次 1,079,725 字节，随后请求已带服务端访客标识；取码及一次待扫轮询均为 200、错误码 0、状态 `new`。首页专用响应上限调整为 4 MB，其他登录接口仍为 1 MB。55 项拓展测试及 2 项宿主端到端通过。这些结果尚未证明本轮真人扫码能通过，也未证明普通数据请求的首次会话初始化、真实昵称搜索、作品和直播可用。

本轮宿主与拓展需要 API 1 / revision 1。已发布的 SDK `0.1.0-alpha.0` 与创建器 `0.1.0-alpha.3` 不包含全部新契约；仓外工程通过随工程固定的本地预览包构建，官方版直接使用 workspace 依赖。未发布 SDK、创建器或主程序新版本。

复验：仓外使用 `vp install --frozen-lockfile` 和 `vp run verify`。主仓从 `extensions/douyin/src/__tests__/*.test.ts` 运行来源测试，从 `apps/server/src/__tests__/douyin-source-e2e.test.ts` 运行安装至推送的回归。真机登录只在本机系统账号页操作，不保存二维码、验证码或凭据作为交付证据。
