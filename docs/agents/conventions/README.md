# 仓库规范

**对全仓长期生效的规矩。** 写代码、审代码之前先对一遍。这里是索引，每条规矩的正文在同目录下各一篇。都是活规范，可以直接改，但加条、改条要主人拍板；每条的来龙去脉在它「出处」指的 ADR。

- **核心**指一等的中立核心：`packages/`、服务端里 `bilibili/` 与 `platforms/` 以外的部分、`apps/contract`、面板。**集成**指 `bilibili/`、每个拓展、每个内置平台适配器（[ADR-0025](../../adr/0025-integrations.md) 决策 1）。
- 守卫编号指 [docs/1.0/architecture.md](../../1.0/architecture.md)「守卫」那张表。大多数随 1.0 施工分期才开，哪期开、哪期清零见 [construction-plan.md](../../1.0/construction-plan.md)「中立性守卫的归期」；没开之前靠审查把关。

## 索引

| # | 规范 | 管什么 |
| --- | --- | --- |
| 1 | [命名](naming.md) | 一个概念只用一个词：类型名的后缀表、词表，外部接口回应的起名；我们写的代码都管，第三方的管不到 |
| 2 | [失败规矩](failure-results.md) | 结果一律用 `ok()` / `fail()` 造，失败是 `{ ok: false, code, message }`，`code` 只取标准码表；错误体只多 `issues`；抛错只留给 bug |
| 3 | [中立性](neutrality.md) | 核心里不出现「B 站」这个概念：不按平台分叉，身份只有 `{ sourceKey, externalId }`，B 站只经登记表进核心，只有 `TargetDispatcher` 能发送 |
| 4 | [叫法](nouns.md) | 创作者、作品、会员、ID 怎么叫：一个来源用它的叫法，混着用中性词，由 contract 里一个函数给；句子绕开量词；描述符不装句子 |
| 5 | [集成副作用只经 ctx](integration-side-effects.md) | 集成不读写文件、不裸开定时器与端点；状态、凭据、请求、图、日志、收尾都经 ctx |
| 6 | [设置校验](settings-validation.md) | 保存时校验；读取时坏一条只隔离那一条；只有信封或连接外壳坏了才挡开机 |
| 7 | [统计收集](stats-collection.md) | 只收来源交到手的现成字段：不多发请求、不存图、不收观众个人数据，字段全部可选 |
| 8 | [没有实现者的接口不造](interfaces-need-implementers.md) | 一个实现者都没有、也没有预知使用者的接口与登记表先不造，写清什么时候再看；使用者有名有期且形状已定的可以提前造 |

## 加一条规范

先问主人。定了就在本目录新开一篇，在上表加一行。每篇的骨架照第 2–8 篇：开头一段说管什么、指向 ADR，然后是「规矩」「边界与例外」「怎么钉住」「出处」四节（`naming.md` 是一张表，格式另算）。
