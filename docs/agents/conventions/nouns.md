# 叫法

**这条管界面、文案、提示词里怎么称呼「创作者」「作品」「会员」「ID」这些东西。** 一个来源叫「UP 主」，另一个可能叫「博主」，核心不许替它们选。这是活规范，可以直接改，但加条、改条要主人拍板；为什么这样定见 [ADR-0027](../../adr/0027-monitoring-stats-and-descriptor-driven-panel.md) 决策 6。核心、集成的含义见 [README.md](README.md)；不出现平台词这一半见 [neutrality.md](neutrality.md)。

## 规矩

**1. 只涉及一个来源的地方，用它自己的叫法。** 叫法来自来源描述符：`creatorNoun`（B 站「UP主」）、`postNoun`、`externalIdNoun`（B 站「UID」）。

**2. 混着多个来源的地方，用中性词。** 「创作者」「作品」「会员」「ID」。描述符没声明就落到这几个词。

**3. 只装了 B 站时，混着的地方也用 B 站的叫法。** 只订 B 站的主人看到的字一个不变。

**4. 挑叫法只由 contract 里的一个函数做。** 面板、服务端（提示词变量、模板、CSV 列名）都调它，不各自判断「是不是 B 站」。没声明叫法时落的中性词由调用方递进去：给人看的（推送正文、面板）从各自的字典取，随界面语言变；给模型的（提示词）随提示词写死中文、不翻（ADR-0037 决策 11），只在 `packages/ai` 的 `PROMPT_NEUTRAL_NOUNS` 定义一次。（主人 2026-10-23 定）

```ts
// 错：面板自己判断
const noun = isBili ? "UP主" : "创作者";
// 对：挑法交给 contract，中性词按给谁看递进去
const noun = sourceNounsOf(sources, neutral).creatorNoun;
```

**5. 自己拼的句子绕开量词。** 写「新{postNoun}」「{n} 位{creatorNoun}」（「位」对人通用），不写「一条{postNoun}」。量词跟名词走，「条」配不上每个来源的叫法。不给描述符加量词字段。

**6. 描述符只装叫法、能力清单与会员档位，不装界面句子。** 想要句子，由核心按已有字段拼。`featureHints` 是描述符里唯一允许写自由文字的一格。

**7. 搜人输入框的提示句由叫法函数拼。** 来源只声明 `searchAccepts?: ("id" | "link" | "name")[]`，收哪几种输入；不声明就是「搜索{creatorNoun}」。

```ts
// 错：来源自己写句子（searchPlaceholder 已删）
descriptor: { searchPlaceholder: "输入 UID、主页链接或名字" }
// 对：只声明收什么，B 站三种都收，拼成「UID、主页链接或名字」
descriptor: { searchAccepts: ["id", "link", "name"], externalIdNoun: "UID" }
```

**8. 外部 id 的标签也由一个函数生成。** 写「{externalIdNoun} {externalId}」；没声明就写「{label} · {externalId}」。「复制 UID」随之是「复制 {externalIdNoun}」或「复制 ID」。统计 CSV 的 ID 列名同样走叫法函数（只装 B 站叫「UID」，混着叫「ID」）。

**9. 提示词跟着来源叫。** 内置人格、卡片工坊、锐评、内置技能与工具说明里，用 `{creatorNoun}`、`{postNoun}`、`{sources}` 变量，调用时由核心按这次涉及的订阅填。风格性的写法（「B 站弹幕解说员」「B 站梗」）改成中性。

**10. 来源没装时兜底。** 拓展卸载后遗留的订阅：平台名显示来源键，叫法用中性词，不露特性开关，卡上标「来源没装」。

## 边界与例外

- **主人可改的文案模板不受第 5 条限制。** 默认文案「{name}发布了一条{postNoun}」保留「一条」：只订 B 站的主人收到的推送一字不差，「条」配作品类的名词（动态、作品、视频、笔记）都通顺。模板里作品叫法的变量就叫 `{postNoun}`，与提示词变量同名，不再有第二个名字。
- **主人自己写的提示词、文案不改写。** 里面若写着「UP 主」，不会被自动改成变量。内置预设改版时照旧亮「默认文案有更新」。
- 「投稿」「动态」在面板与 CSV 里保留（ADR-0021 决策 50），不受第 2 条影响。
- `bilibili/` 与迁移模块里可以出现 B 站词；中文叫法棘轮的白名单就是它们。
- 只涉及一个来源的地方，包括 `bilibili/` 自己产出的文案（如问题表里 B 站给的文案），本来就该用它的叫法。
- 平台名本身（徽章、平台列）取描述符的 `label`，不写死「B 站」。

## 怎么钉住

- **中文叫法棘轮**（第 4 期开，第 5 期末清零）：范围核心与面板的字符串字面量，不扫注释。词：`UP ?主`、`B ?站`、`哔哩`、`舰长`、`提督`、`总督`、`大航海`、`上舰`、`粉丝牌`、`专栏`、`房管`、`UID`、`动态`；白名单 `bilibili/`、迁移模块、ADR-0021 决策 50 的「投稿」「动态」。开张时连 `locales/*.json` 一起扫：字搬进字典以后，源码扫描看不见它们。
- **守卫 4（名字唯一的家）**：叫法函数进点名表，家以外出现同名定义就红。
- **模板变量可满足性**（3b）：每个模板变量映射到中立字段，表外判红；`{tier}`、`{fanclub}` 进表。
- 中立性的其余扫描见 [neutrality.md](neutrality.md)；期次以 [construction-plan.md](../../1.0/construction-plan.md)「中立性守卫的归期」为准。

以下靠审查把关，逐条看：
- 新句子里有没有量词（「一条」「一位」「个」）直接接在叫法变量前。
- 描述符里是不是新加了句子或量词字段；要加界面句子，是不是改成了核心按字段拼。
- 面板与服务端有没有各自写了一份叫法的判断。
- 内置提示词里有没有新写死的平台叫法。
