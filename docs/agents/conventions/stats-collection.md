# 统计收集

**统计只收来源已经交到手的现成字段。** 这条管统计仓里每一行多收什么、不许收什么。这是活规范，可以直接改，但加条、改条要主人拍板。为什么这样定见 [ADR-0027](../../adr/0027-monitoring-stats-and-descriptor-driven-panel.md) 决策 4。

## 规矩

1. **不为统计多发请求。** 字段只取上报或响应里已经有的；要多问一次接口才能拿到的，不收。
2. **每条几百字节以内。** 估算 50 条订阅一年约 20MB，多收一个字段前先算它会不会破这个量级。
3. **不存图片字节。** 要图的话存 `ImageRef` 之类的引用，不把字节塞进统计行。
4. **不收观众个人数据，只收汇总。** 收弹幕条数与发弹幕人数，不收弹幕原文、观众名单、观众昵称。检测时点的互动数也不收。
5. **字段全部可选。** 来源给不出就空着，不为了填满而编默认值，也不因为缺字段拒收整条。

   - 对：`danmakuCount?: number`，来源没给就不写。
   - 错：来源没给就写 `0`；或者标成必填，让拓展少报一格就被拒收。

现在多收的字段（ADR-0027 决策 4；分期见决策 12：拓展作品的与 B 站作品的都已在收，场次的随 3b）：

| 行 | 多收什么 |
| --- | --- |
| 作品行 `PostEntry` | 链接 `url`、标题 `title`（截 100 字）、摘要 `summary`（与 AI 同一种拼法，截 200 字）、话题 `topic`、视频时长 `videoDurationSec`。链接取信封上的 `url`，其余从 `Post` 取，都经 `stats/post-entry-extras.ts` 那一个函数 |
| 场次行 `LiveSessionEntry` | 标题、分区、弹幕条数与发弹幕人数、醒目留言条数与按币种的总额、按档的新增会员数；累计观看本来就有（`peakTotalViewers`） |

想加新字段，先按上面五条对一遍；对不上就先问主人，别默认加。

## 边界与例外

- **「记不记」不归这条管。** 开了开关才监听、才记，「在记」按特性分，这些是 ADR-0027 决策 1、2 定的，与本条互不相干。
- **推送历史、粉丝时序不在这条里。** 这条讲的是 `PostEntry` 与 `LiveSessionEntry` 多收的字段。
- **摘要取段用唯一的取段函数**（ADR-0028 决策 1），不为统计另拼一份作品文字。
- **汇总不等于放宽。** 「发弹幕人数」是汇总，「谁发的弹幕」不是。

## 怎么钉住

靠审查。没有守卫，字段名与形状施工时才定。审查逐条看：

1. 新字段的值是不是来源上报时已经带着的，有没有新增一次请求。
2. 单条会不会超过几百字节（摘要有没有截到 200 字）。
3. 有没有字节、`data:` URL 之类的东西进了统计行。
4. 有没有观众个人数据：原文、名单、昵称、用户 id。
5. 新字段是不是可选，读的地方缺了字段会不会崩。
